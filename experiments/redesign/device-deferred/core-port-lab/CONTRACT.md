# RD-P05 laboratory bridge v0 — provisional, synthetic effects only

This is an isolated replaceable adapter contract, not product M03 wire/schema, authority or real persistence. Both clients invoke the same Rust backend and the unchanged RD-P01/RD-P02 crates. Separate seeded processes prove deterministic equivalence, not cross-device sync. No new installation/licence/account/device/model permission.

## Single wire source and transport

Rust core owns the definitive serde request/reply definitions; this document fixes the minimal shape for client work. Any necessary delta is agreed with B and recorded here before clients consume it. UTF-8 NDJSON frames <=32768 bytes, one reply per request, lab protocol 0; strict unknown fields/enums/version/type/range rejection. Counters travel as canonical decimal strings, never JSON floating numbers. Read stdout incrementally/bounded; EOF/invalid response is transport unavailable, never business success. request_id correlates transport, not business identity. Node/JVM launch only the fixed trusted lab executable/seed, no arbitrary shell/path capability exposed to renderer.

Request fields: protocol=0, request_id:string, op:hello|snapshot|preview|commit|lookup|reconnect, domain:{store,scope,stream}, display_epoch:string. preview/commit/lookup additionally use object_id:string, intent:string, expected_revision:decimal-string, raw_utf16:array<u16>; commit/lookup carry plan_id:string. reconnect additionally carries new_display_epoch:string. Irrelevant optional fields must not silently grant authority. A receipt is never caller-insertable. Backend is initialized once from fixtures/seed.json; request cannot reseed or reset the ledger.

Every identity label (request_id, object_id, intent, plan_id, domain components, display_epoch, new_display_epoch) is nonempty and at most 128 UTF-8 bytes, compared exactly without trimming, normalization or truncation. This bounds reply metadata; it does not weaken binding. Invalid shape/type/version/labels return rejected/invalid_request with no plan, receipt or snapshot; untrusted request_id/epoch are echoed as empty strings. A well-formed foreign domain returns rejected/domain_mismatch. Optional fields explicitly supplied as null are invalid, not equivalent to omission. All counters are canonical u64 decimal strings; revision zero is not a valid record revision.

## Input-only shared driver

Trusted CLI drivers accept `--input <scenario fixture> --output <external report path>`; paths never enter a renderer API. Format: `{scenario_id, seed:"baseline"|"lost-reply", steps:[{request:{op,...}, plan_id_from?:integer}]}`. Drivers use the fixed executable and map the two seed selectors to owned seed files. For each step they add protocol=0, request_id="step-<zero-based index>", the seed domain and display_epoch="epoch-0" unless explicitly overridden. `plan_id_from` must refer to an earlier actual reply with a non-null plan; its plan.id alone supplies request.plan_id. It never supplies an expected reply. Drivers must reject ambiguous explicit plan_id plus plan_id_from. No implicit retry, commit or reset is permitted. Each fixture is executed in a fresh actual Rust process.

Output: `{scenario_id, replies:[<actual validated Rust replies>]}`. No wall-clock/path/client-specific metadata is added. Two independently executed outputs are compared by B after execution; fixtures contain only commands and causal plan references. Separate adapter tests must also exercise their actual presentation/controller state and unresolved-intent protections, rather than treating protocol equality as UI proof.

Reply: protocol=0, request_id, kind:hello|snapshot|prepared|committed|conflict|rejected|unknown, reason:string-or-null, domain, display_epoch, display_admission:current|stale, snapshot:object-or-null, plan:object-or-null, receipt:object-or-null. Snapshot includes cursor:{store,scope,stream,seq:decimal-string} and suppliers:[{id,name,revision:decimal-string}]. Plan includes id,intent,object_id,expected_revision,normalized_name,parameters_digest. Receipt includes kind=synthetic,id,intent,object_id,expected_revision,result_revision,normalized_name,parameters_digest,commit_cursor. Client transport/meta validation is permitted; name normalization, CAS, intent dedup, receipt verification and recovery decisions execute in Rust, not alternate JavaScript/Kotlin business algorithms.

## Actual laboratory business chain

Raw UTF-16 reaches RD-P01 unchanged: length guard/XML-before-trim/NFC/length. read/preview route through actual Rust domain functions. Preview validates but is not an effect or grant. Commit checks the fixed synthetic domain, immutable registered plan/raw/intent/revision, then actual domain edit_candidate; atomically swaps cloned lab record/reducer/receipt state only on success. Generate synthetic receipt from the actual result, never an expected table. RD-P02 receives/commits the corresponding same-domain event and verifies the actual ledger receipt in lookup. Clone-before-effect or equivalent staged swap must prevent half-state on injected precommit failure.

Business fingerprint binds domain store/scope, action, object, original raw/expected revision and plan; excludes request_id/display_epoch. Same intent+same original business command returns the original receipt without another revision/event; same intent with changed payload conflicts. New explicit intent with same normalized name is independent and increments once. Projection stream/cursor identity must not be laundered into new business intent. Missing lookup remains unknown and performs zero commit/dispatch; it does not prove never dispatched.

Only trusted startup fixture faults may inject precommit failure or one lost commit response. The latter applies the real synthetic effect/receipt first, replies unknown without exposing successful effect data, and lookup recovers the original effect with zero extra writes. Reconnect changes presentation epoch through RD-P02 without dropping ledger/unknown. A stale epoch's genuine receipt remains independently verifiable; it cannot regress current projection/draft. Snapshots and receipts are separate axes.
