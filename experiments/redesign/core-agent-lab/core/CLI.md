# Core Agent lab process protocol v1

Experimental Linux/private single-owner fixture only. All flags are trusted host
inputs. Provider text cannot set flags, scope, risk, approval or paths. No real
model/network, production issuer, TTL, tokenizer or remote exactly-once claim.

`muyon-core-agent-lab start --dir NEW_DIRECTORY --script FILE [--input TEXT]
[--mode read-only|ask-every-time|auto|full-allow] [--risk low|high]
[--scope TEXT] [--hard-ok true|false] [--revoked true|false]
[--scope-ok true|false] [--classification-ok true|false]
[--confirmed true|false] [--tainted true|false] [--new-destination true|false]
[--max-steps N] [--max-calls N] [--max-context N] [--max-output N]
[--max-total N] [--tool-behavior normal|fail|lose-response]`

Defaults: auto, low, scope `fixture`, hard/scope/classification true,
revoked/confirmed/tainted/new-destination false; steps/calls 16, context 65536,
output 16384, total 262144. All limits are positive and <= 1000000.
Start persists immutable script, input, facts and limits, but does not run it.
Task/attempt IDs are generated by host. `fixture.record` is the only tool.
Input and script <=65536 bytes, max128 script events, identifiers <=64 ASCII
letters/digits/underscore/hyphen/dot. Script grammar is CONTRACT.md. Fail reason
is an identifier. Reject malformed/unknown events/tools/extra fields before start.

`run --dir DIR [--confirmed true|false] [--hard-ok true|false]
[--revoked true|false] [--scope-ok true|false] [--classification-ok true|false]
[--checkpoint dispatch|effect|projection] [--io-fault dispatch|effect|projection]`

Run advances until terminal/wait/unknown/budget. Host overrides apply to current
facts; confirmation authorizes only the currently pending exact invocation and
is consumed once. `start --confirmed true` authorizes only the first invocation.
No mode/scope/budget/script override on resume. A run after unknown never calls
provider or tool. `lookup --dir DIR` reconciles a matching original receipt, then
an explicit run can continue; absence/corruption/unavailability stays unknown.
`cancel --dir DIR` persists cancellation; if dispatch is pending it performs
read-only receipt lookup. Before dispatch it stops with zero effects; after
commit it retains receipt and prevents further provider calls.
`inspect --dir DIR` observes durable state without modifying effect storage.

Checkpoint emits `checkpoint=NAME` on stdout and flushes, then waits for one
newline on stdin. Checker sends SIGKILL without sleeps, or writes newline to
continue. A concurrent `cancel` writes a durable cancellation request even while
the main directory lock is held; running process checks it at the checkpoint
return and before each provider/effect admission. Kill automatically releases
Linux flock. `io-fault` creates a deterministic IO error at that named write
boundary, leaving truthful unknown after dispatch. These are host-only test hooks.

Each successful command prints key=value lines: `status` (ready, waiting,
completed, denied, failed, cancelled, outcome_unknown, budget_exhausted),
`task`, `attempt`, `turn`, `invocation`, `receipt`, `effects`, `value_hex`,
`answer_hex`, `model_calls`, `steps`, `context_bytes`, `output_bytes`,
`total_units`, `provider_position`, `cancelled`, `confirmations`, `reason`.
Unknown effect storage reports `effects=unknown`, not zero. Extra observation
keys may be added. Errors exit 2 and print `error=...` on stderr; no fabricated
successful observation. Semantic stops return 0. Text fields are strict UTF8 hex.

Context roles are user/assistant/tool. Tool role is constructed only from a
verified original receipt: `receipt=<ID>;value=<VALUE>`. The scripted provider
receives actual context and replaces `{{tool_result}}` in an answer with the
last actual trusted tool message (empty if none). This permits follow-up
assertions against the physical tool result rather than expected-result tables.
Counters measure actual request-context/event UTF8 bytes, not model tokens.
Every attempted provider call increments persistent step/call counters before
provider invocation. Context/output/total limits checked before and after work;
no rejected response can dispatch a tool. Confirmation wait consumes no calls.

## Physical evidence format

`task.db`: strict bounded `CORE_TASK_V1` header and unique tab-separated key/value
rows. `script_hex`, `context_hex`, `pending_hex` encode UTF8 subrecords. Journal
status `outcome_unknown` plus pending original binding is durable before dispatch.
`effects.db`: strict `CORE_EFFECT_V1` header followed by `count<TAB>N`,
`value<TAB>hex-UTF8` and zero or more rows:
`receipt<TAB>invocation<TAB>task<TAB>attempt<TAB>turn<TAB>scope_hex<TAB>value_hex<TAB>receipt_id`.
Count equals receipt-row count; last receipt value equals physical value. Each
row is a real executed effect and original receipt in the same atomic snapshot.
Binding also fixes the only registered tool, `fixture.record`.
Task and effect snapshots are separate files, atomic temp-file/fsync/rename/
directory-fsync writes. Original receipt is never inferred from task success.
Missing/corrupt effect store is never reseeded. Readers bound files at 1MiB.
`.lock` uses Linux nonblocking flock, automatically released on SIGKILL. All
fixture files are private regular files; directory owned by current UID and
mode0700; no symlink fixture paths. `cancel.request` is an independent durable
host signal. Private directory assumes a trusted owner, not hostile same-UID edits.

`context_hex` decodes to zero or more exact lines
`ROLE<TAB>hex-UTF8-text<NEWLINE>`, where ROLE is exactly `user`, `assistant`,
or `tool`. Assistant tool requests are text `tool=fixture.record;call=REF;value=VALUE`.
Only the host adds tool-role text, exactly `receipt=ID;value=VALUE` from physical
original receipt. Both repeated and conflicting provider call-ref reuse fail
with `duplicate_or_unknown_call` and never allocate a second effect. Exact
host Binding replay is separately supported by the typed ToolPort and returns
the same original Receipt; a provider call-ref is not a replay capability.
Concurrent cancel output may still show the executor's durable pending status,
with `cancelled=true`; the executor consumes the durable request on release.

Author inverse mutations: `python3 core/mutations.py --evidence-dir /tmp/OUTPUT`
requires preinstalled Cargo. Five fresh private source copies weaken hard policy,
unknown hold, duplicate suppression, original-receipt validation and persistent
counters. Each must compile
and fail behavioral Rust assertions; source-under-review remains untouched.
ToolPort direct callers must hold the private directory lock around lookup/execute;
the CLI Agent commands do so. No cross-task/shared-host storage service is provided.
