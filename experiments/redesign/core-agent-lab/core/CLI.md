# Core Agent lab process protocol v1

Experimental Linux/private single-owner fixture only. All flags are trusted host
inputs. Provider text cannot set flags, scope, risk, approval or paths. No real
model/network, production issuer, TTL, tokenizer or remote exactly-once claim.

`muyon-core-agent-lab start --dir NEW_DIRECTORY --script FILE [--input TEXT]
[--mode read-only|ask-every-time|auto|full-allow] [--risk low|high]
[--scope TEXT] [--hard-ok true|false] [--revoked true|false]
[--scope-ok true|false] [--classification-ok true|false]
[--confirmed true|false] [--tainted true|false] [--new-destination true|false]
[--max-steps N] [--max-calls N] [--max-context N] [--max-output N]
[--max-total N] [--tool-behavior normal|fail|lose-response]`

Defaults: auto, low, scope `fixture`, hard/scope/classification true,
revoked/confirmed/tainted/new-destination false; steps/calls 16, context 65536,
output 16384, total 262144. All limits are positive and <= 1000000.
Start persists immutable script, input, facts and limits, but does not run it.
Task/attempt IDs are generated by host. `fixture.record` is the only tool.
Input and script <=65536 bytes, max128 script events, identifiers <=64 ASCII
letters/digits/underscore/hyphen/dot. Script grammar is CONTRACT.md. Fail reason
is an identifier. Reject malformed/unknown events/tools/extra fields before start.

`run --dir DIR [--confirmed true|false] [--hard-ok true|false]
[--revoked true|false] [--scope-ok true|false] [--classification-ok true|false]
[--checkpoint dispatch|effect|projection] [--io-fault dispatch|effect|projection]`

Run advances until terminal/wait/unknown/budget. Host overrides apply to current
facts; confirmation authorizes only the currently pending exact invocation and
is consumed once. `start --confirmed true` authorizes only the first invocation.
No mode/scope/budget/script override on resume. A run after unknown never calls
provider or tool. `lookup --dir DIR` reconciles a matching original receipt, then
an explicit run can continue; absence/corruption/unavailability stays unknown.
`cancel --dir DIR` persists cancellation; if dispatch is pending it performs
read-only receipt lookup. Before dispatch it stops with zero effects; after
commit it retains receipt and prevents further provider calls.
`inspect --dir DIR` observes durable state without modifying effect storage.

Checkpoint emits `checkpoint=NAME` on stdout and flushes, then waits for one
newline on stdin. Checker sends SIGKILL without sleeps, or writes newline to
continue. A concurrent `cancel` writes a durable cancellation request even while
the main directory lock is held; running process checks it at the checkpoint
return and before each provider/effect admission. Kill automatically releases
Linux flock. `io-fault` creates a deterministic IO error at that named write
boundary, leaving truthful unknown after dispatch. These are host-only test hooks.

Each successful command prints key=value lines: `status` (ready, waiting,
completed, denied, failed, cancelled, outcome_unknown, budget_exhausted),
`task`, `attempt`, `turn`, `invocation`, `receipt`, `effects`, `value_hex`,
`answer_hex`, `model_calls`, `steps`, `context_bytes`, `output_bytes`,
`total_units`, `provider_position`, `cancelled`, `confirmations`, `reason`.
Unknown effect storage reports `effects=unknown`, not zero. Extra observation
keys may be added. Errors exit 2 and print `error=...` on stderr; no fabricated
successful observation. Semantic stops return 0. Text fields are strict UTF8 hex.

Context roles are user/assistant/tool. Tool role is constructed only from a
verified original receipt: `receipt=<ID>;value=<VALUE>`. The scripted provider
receives actual context and replaces `{{tool_result}}` in an answer with the
last actual trusted tool message (empty if none). This permits follow-up
assertions against the physical tool result rather than expected-result tables.
Counters measure actual request-context/event UTF8 bytes, not model tokens.
Every attempted provider call increments persistent step/call counters before
provider invocation. Context/output/total limits checked before and after work;
no rejected response can dispatch a tool. Confirmation wait consumes no calls.

## Physical evidence format

`task.db`: strict bounded `CORE_TASK_V1` header and unique tab-separated key/value
rows. `script_hex`, `context_hex`, `pending_hex` encode UTF8 subrecords. Journal
status `outcome_unknown` plus pending original binding is durable before dispatch.
`effects.db`: strict `CORE_EFFECT_V1` header followed by `count<TAB>N`,
`value<TAB>hex-UTF8` and zero or more rows:
`receipt<TAB>invocation<TAB>task<TAB>attempt<TAB>turn<TAB>scope_hex<TAB>value_hex<TAB>receipt_id`.
Count equals receipt-row count; last receipt value equals physical value. Each
row is a real executed effect and original receipt in the same atomic snapshot.
Binding also fixes the only registered tool, `fixture.record`.
Task and effect snapshots are separate files, atomic temp-file/fsync/rename/
directory-fsync writes. Original receipt is never inferred from task success.
Missing/corrupt effect store is never reseeded. Readers bound files at 1MiB.
`.lock` uses Linux nonblocking flock, automatically released on SIGKILL. All
fixture files are private regular files; directory owned by current UID and
mode0700; no symlink fixture paths. `cancel.request` is an independent durable
host signal. Private directory assumes a trusted owner, not hostile same-UID edits.

`context_hex` decodes to zero or more exact lines
`ROLE<TAB>hex-UTF8-text<NEWLINE>`, where ROLE is exactly `user`, `assistant`,
or `tool`. Assistant tool requests are text `tool=fixture.record;call=REF;value=VALUE`.
Only the host adds tool-role text, exactly `receipt=ID;value=VALUE` from physical
original receipt. Identical repeated provider call-ref/tool/value uses its persisted original host
Binding to look up and return the original Receipt/tool result with zero added
effects or confirmation consumption. Changed arguments produce `binding_conflict`.
Missing/corrupt/unresolved original evidence stays lookup-only unknown. The
provider reference never creates a new invocation or grants authority.
Concurrent cancel output may still show the executor's durable pending status,
with `cancelled=true`; the executor consumes the durable request on release.

Author inverse mutations: `python3 core/mutations.py --evidence-dir /tmp/OUTPUT`
requires preinstalled Cargo. Eight fresh private source copies weaken hard policy,
unknown hold, duplicate suppression, original-receipt validation, terminal-control
restoration, pre-effect context admission, receipt-own-binding validation and
persistent counters. Each must compile
and fail behavioral Rust assertions; source-under-review remains untouched.
ToolPort direct callers must hold the private directory lock around lookup/execute;
the CLI Agent commands do so. No cross-task/shared-host storage service is provided.

Task journal now persists `correlations_hex`: decoded lines are
`call-ref<TAB>hex-UTF8-binding<NEWLINE>`; the binding decodes to the same six
fields as pending_hex / physical receipt binding. `result_pending` tracks whether
the admitted tool call still needs its trusted tool-result context message.
`resume_status`/`resume_reason` preserve the prior control barrier while a cached
receipt's original evidence is unavailable. Restoring original evidence restores
that status/reason; completed/cancelled/failed/denied/budget_exhausted never become
ready solely because lookup found a receipt. This unpublished snapshot revision
fails closed on older incomplete task records; no product migration is implied.

For the fixed synthetic tool, the complete trusted result-message size is known
from the host binding/receipt ID before execution. Dispatch reserves that context
space before consuming confirmation or committing the first effect. A context
limit40 with empty input and `tool c1 fixture.record hi` therefore stops with
zero effects/confirmations. Total units remain measured request-context plus
provider-event bytes; these are synthetic byte counters, not token/billing claims.

R2 historical-evidence state: `receipt_binding_hex` stores the retained receipt's
own exact host Binding, independently of `pending_hex` (which may describe a
newer prepared/waiting invocation). `evidence_hold` records unavailable historical
evidence; `unresolved` continues to mean the current invocation requires outcome
lookup. Losing historical evidence does not set `unresolved` on a never-dispatched
new call. Observations expose `evidence_hold` and `dispatch_unresolved` separately.

While historical evidence is absent/corrupt/unavailable, status is outcome_unknown
and fresh provider/tool work and positive confirmation are blocked. Explicit
lookup verifies `receipt_binding_hex`, then restores `resume_status`/`resume_reason`
without replacing the pending binding or consuming confirmation. If the current
invocation was actually dispatched, its separate outcome lookup still applies.
Restoring a waiting operation requires a subsequent fresh exact confirmation;
restoring terminal controls never resumes execution. Cancellation remains durable
and cannot manufacture a no-effect outcome for an actual unresolved dispatch.

## P1 offline stdio provider

`start --dir TASK --provider chat-sse --wire-helper ABSOLUTE_PYTHON_FILE --wire-fixtures ABSOLUTE_DIRECTORY`
selects the frozen WIRE-CONTRACT profile. Optional start flags: `--wire-chunk-size` (8192, 1..8192), `--wire-idle-ms` (2000, 1..10000), `--wire-total-ms` (5000, 1..30000), `--max-wire-total` (262144, 1..1048576). `--script` is incompatible. Script remains the default provider. All settings are persisted; run accepts no replacements.

The core launches `python3 -B HELPER --fixture-dir FIXTURES --turn N --capture-dir TASK/wire-capture`, clears its environment except `/usr/bin:/bin` PATH, writes request JSON and closes stdin, consumes raw SSE, and requires clean EOF plus successful exit. Linux nonblocking pipe I/O handles blocked input, silent output, and EOF followed by a hanging child. Handled cancellation/failure/limit kills and reaps the child. External SIGKILL has no supervisor guarantee; the independent harness cleans surviving fake helpers.

`run --checkpoint wire-open|wire-args` uses the existing flushed `checkpoint=NAME` / stdin-newline handshake. `wire-open` means request bytes were written and stdin closed. `wire-args` means Rust consumed a complete supported argument event but has not consumed finish/DONE or admitted a tool. It fires once at most; later argument fragments remain subject to final validation. State is saved before ACK; cancellation is checked after resume. Hooks are host test barriers, not provider text.

Additional CLI and task.db rows: `wire_sent_bytes`, `wire_received_bytes`, `wire_total_bytes` (sum), `provider_inflight`, `usage_prompt`, `usage_completion`. Usage is decimal or `unknown`, never inferred zero. Original task.db `calls`, `steps`, `confirmations` remain directly readable at a paused hook; CLI retains `model_calls`. Bytes are measured protocol bytes, not tokens/prices/billing. A successful/handled exchange accounts actual writes and reads, including invalid/truncated data. Read counters may include later bytes buffered but not yet parsed at `wire-args`. An external SIGKILL between syscall and snapshot leaves a durable measured lower bound; the already-persisted inflight marker permanently blocks resend and further admission for that task, so it cannot reopen its budget.

Private snapshot additions: `provider` (`script`/`chat-sse`), `wire_config_hex` (UTF8 JSON config), `native_history_hex` (UTF8 JSON tagged arrays), `pending_call_ref`, and counters above. Native rows are `["user",text]`, `["assistant",text]`, `["call",call_ref,registered_name,value]`, `["tool",call_ref,original_value,original_receipt]`. These typed rows are never inferred from semantic message text. Existing snapshot version marker is retained for this unpublished lab; new loader requires the added rows. Existing script CLI and fixtures are unchanged.

Reported usage describes the latest admitted wire turn: admission persists `unknown` before any bytes, and only a successful current turn fills the values. Failed, cancelled and interrupted turns cannot inherit previous usage. Private history escape expansion is bounded by the existing1MiB task-file envelope; this storage bound does not relax the65536-byte wire request/response limits.
