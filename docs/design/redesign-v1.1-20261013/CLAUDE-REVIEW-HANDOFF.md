## 2. 已定决策：审查可挑战理由，但不得暗改产品语义

1. 技术主线已定：Electron 桌面、Kotlin Compose Android、Rust 本地离线内核；iOS 只预留边界。React/TypeScript、具体 ABI/桥接方案、PDF/OCR 引擎与支持平台细节仍需确认或实测。
2. 本地筛选、排序、折叠、草稿编辑直接响应。业务动作交 Rust 校验授权、目标、版本和参数，只有需要重新理解、生成或规划时才再调用模型。本地执行不自动等于无副作用；模型回合也不是授权边界。
3. **全部允许**：在已选工作区、现有访问权限和有效范围内免额外询问，高风险也不额外询问。仍保留访问权、到期与撤权、操作系统和第三方硬限制、合同合法性、版本/CAS、去重以及结果未知核对。此模式不授予任意扩权，也不是本次审查或未来生产操作的授权。
4. **独立 Auto**：宿主确定性规则将已授权低风险动作自动执行、高风险请求确认、禁止类拒绝。不能由模型任意判风险，不能与全部允许合并。
5. 安全暂停与全部允许并存：有具体可复核条件时暂停受影响能力，以证据与恢复判据清除，恢复后重新验证。安全暂停不能成为“高风险一律确认”的隐蔽改名。必须分开硬禁止、版本/参数失败、权限失效、审查暂停、需要事实补充、Auto 确认和外部结果未知。
6. 已有对象版本校验、旧卡失效、授权披露、执行账本、回执、取消和撤权应被迁移继承。不要把已有机制报成“首次发现的缺失”；可以指出迁移合同未充分覆盖，并附准确证据。

你可以明确建议改变已定决策，给出理由和替代方案，但应标为“建议重新决策”，同时评估保持现有决策的最小可行方案。不得把自己的建议写成用户已经批准。
