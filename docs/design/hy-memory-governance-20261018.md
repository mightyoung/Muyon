## 2 状态事实与页面语义

读用封锁和物理清理是两个轴。墓碑/撤权提交并被当前读取门禁接纳后才能显示“已不可读”；这不等于清理完成。提交失败显示“删除失败，尚未确认不可读”；回执不确定则显示“状态未知，正在核对”，不自动再次制造新删除意图。UNKNOWN 不可转换为 ABSENT、空列表或成功。

| 页面事实 | 展示与行为 | 不允许的推断 |
| --- | --- | --- |
| 当前封锁已确认，outbox pending | 已不可读；清理待办 | 已全部物理删除 |
| 当前封锁已确认，某 sink retry | 已不可读；清理重试，列失败范围及次数 | 重试失败恢复可读 |
| 所有受控必需 sink 有可核回执 | 已清理（列明范围） | 日志、备份、第三方副本已全擦除 |
| sink 结果未知/未覆盖 | 已不可读；清理状态未知或未覆盖 | 没找到即已清理 |
| authority/存储核对不可用 | 状态未知；禁止该内容进入上下文 | 无结果或不存在 |

S06 条目与删除结果、S05 存储清理详情和 A01 引用详情均使用此分轴。没有生产接入时，这些仅是目标页面规范，现有产品不显示实验通过为功能已提供。允许重试同一清理操作，保留原请求身份；错误不伪装额外授权确认。已发往模型/工具/第三方的内容不能承诺撤回。

## 3 治理对象和清理边界

治理单位绑定稳定 memory/source identity、scope、lineage 与用途。枚举受控 sink：主记忆正文、经验/candidate、主题及组合摘要、全文与向量索引、检索缓存、未发送上下文及模型请求候选、整理 run snapshot/proposal、排队通知草稿、导出候选及 diff sidecar（若以后采用）。每个 sink 必须有名称、覆盖对象/版本、清理方式与核对回执；新增 sink 在登记前不可宣布全范围完成。

审计只保留获准最小无正文身份、参数摘要和操作结果；日志/备份按既定保留政策单独记录“未覆盖/保留范围”，不因 outbox 完成承诺全物理擦除。已生成的外部导出、第三方和不可控制副本属于边界外。独立人工事实可保留自身获准来源；派生内容不得通过改名或新 revision 绕过来源墓碑。删源、多来源剩余支持、停用、可恢复删除、彻底遗忘仍保持原有区别。

本批实验只覆盖单 SQLite 中权威 fixture、墓碑、outbox 及合成派生 sink，不能把实验枚举当生产存储盘点已经完成。

## 4 原子封锁与持久删除 outbox

删除输入绑定稳定 request_id、目标、expected_revision、authority_revision、当前同域 policy_generation、用途及 canonical payload digest。相同 request_id 相同 payload 返回同一持久回执；相同 key 异 payload 拒绝，不重用旧成功。版本、权限、policy 与墓碑只做各自域内核对，不交叉大小比较。

单 SQLite 实验中，在同一写事务内：核对当前 CAS、当前权限与策略 → 写墓碑/拒绝投影并增加治理 generation → 写清理 manifest 与唯一 outbox 项 → 写幂等回执 → commit。任何失败全部回滚；不能先返回成功再内存入队。删除目的本身不受已关闭的自动记忆开关阻止，但必须有当前合法管理权限。自动写入、组合读取仍服从当前用途和各自控制。

worker 只执行清理，不决定授权或复活内容。每个 sink 操作身份绑定 request、sink、目标和治理 generation；清理必须能幂等重放。claim/lease、attempt、结果及下一次重试持久保存。清理后、确认前崩溃可再次删除同一副本；只有取得核对证据才能记 done。显式 failure 与 unknown 分开，所有必需 sink 确认 done 才显示该 manifest 清理完成。重启扫描未完成和过期 claim；重试不降低墓碑、策略代次或关闭封锁。错误/未知不自动无限快速循环。

生产域外 ForgettingReceipt 与业务库跨库不具备此 SQLite 原子性；仍按既定先持久凭据、再封锁/清理、重启对账顺序。本批不实现整 root 恢复、凭据备份、跨设备、日志清除，不能声称覆盖灾难恢复防复活。

## 5 组合召回与撤权竞态

候选命中只提供身份和版本提示。组合每个成员都重新核对当前 authority、allowed_uses、scope、content revision、source revision、当前 policy、墓碑、disabled/expiry 及 lineage；摘要文本本身不构成授权。任一成员撤权、失效、版本改变或来源不明时，旧组合整体失效；只有按有效成员重新构建且语义仍完整时才可继续，不从旧文本简单删一句后宣称安全。UNKNOWN 返回独立错误/不确定结果并阻断该内容，不作为 ABSENT 缓存。

核对必须与消费有线性化边界。Rust 宿主最终投影持有与撤权/删除共享的治理锁直到发送/消费提交，或者使用 generation ticket，并在同一临界区内于消费提交点重新核验 ticket 后接纳；单纯“读取时校验→释放锁→异步发送”不合格。ticket 覆盖所有成员、来源、权限和策略相关代次，不能只绑定主条目版本。生产外发接线后置；实验以锁内 synthetic consume 记录证明撤销先提交则不能消费旧投影，消费先线性化只记为已经发生，不声称可撤回。

## 6 脱敏与可定位引用

来源保留 source_id、source_revision、原文内容 digest 和原始 UTF-8 **字节**半开区间 `[start,end)`。所有边界必须处于合法 UTF-8 字符边界，验证不越界；不能把字符序号混作字节位置。脱敏输出由有序 segments 构成：原文片段（带精确原始范围）或替换片段（标记 redacted 及其原始范围、替换原因类别）。不得持久化或在 UI 中暴露被替换原文来证明定位。

未替换片段只可按当前来源版本、权限及范围引用；脱敏替换文字不能算原文证据。跨替换区间的展示必须明确“部分内容已脱敏”，不能去掉标记后作为一段连续逐字引文；摘要/改写另标生成内容。来源更版、撤权、墓碑或无法核验 digest 时引用失效/未知，不借历史 span 读取已撤销正文。保留定位不意味保留原文访问权。

## 7 采用与交付边界

本批确定性机制：隔离 Rust/SQLite 原子墓碑+outbox、幂等重放与崩溃恢复；成员当前状态与消费竞态；UTF-8 source spans/脱敏引文合同。先保存 RED 失败输出，再实现并保存 GREEN、进程重开、故障负例与固定 SHA。独立设计审查先于代码实现，独立代码审查先于交接。具体执行状态与证据仅以任务表和原始日志为准。

专用 writer 仅作后续有界 A/B 候选：模型提出建议，Rust 核验与落库；diff 索引先对比现有 Git/事件引用的存储与有效历史恢复，不预设收益。允许合成 fixture，不调用付费模型、不下载权重、训练、安装 MemHub 或读取真实私人会话/凭据。收益未验证，方案不代表部署决定。
