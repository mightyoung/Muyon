# 给 Claude Design 的修正提示词（第八轮：v6 收尾）

用法：在原项目里粘贴「提示词」整段，一次发完。依据见 [v6 审阅](../../../reviews/2026-10-07-design-v6-review.md)。第七轮里已经满足的条目（A1～A4、B1～B3、C1～C3、D1～D2、E3）不再重复。

## 提示词

v6 采纳为目标稿。本轮只修下面列出的问题，不新增功能、页面或组件。已定决定全部不变。

**关于尺寸**：开发时控件高度会按内容自适应，48 只作为最小点击区。所以本轮不需要再把旧稿里的按钮逐个补到 48 像素，只需要把上一轮误改的地方改回来（见 F）。

### A. 补齐 `warn` 定义（最要紧）
1. `Muyon Mobile`、`Muyon Desktop` 的浅色、深色两套调色板，都加上 `warn` / `warnbg`（取值与 `tokens.md` 相同）。现在这两个文件用到了 `var(--warn)`，却没有定义，警告条渲染出来没有底色，最明显的是「外部内容」提示条。
2. 这两个文件里原来用红色表示「需注意」的警告类状态，改用 `warn`。红色只留给失败、危险和外传。
3. `Muyon Research` 里残留的私有变量 `amb` 改用 `warn`。
4. 规则：任何文件只要用了 `var(--warn)`，调色板里就必须定义 `warn` 和 `warnbg`。

### B. 外部内容开启时，不再提供任何「放行」类选项
依据：任务里一旦进入外部内容，写入和外传必须逐次确认。
1. 在 `Muyon Assistant Auth` 中，只要满足下面任一条件，就进入「逐次确认」模式：
   - 确认卡状态为「因外部内容需逐次确认」；
   - 叠加开关「外部内容」打开。
2. 在逐次确认模式下：
   - 写入卡只保留「仅这一次 / 拒绝」，**不显示「更多」**；
   - 「外传 · 已授权端点」卡只保留「仅发送这一次 / 拒绝」，**去掉「本次对话允许」**；
   - 远程模型请求卡同样去掉「本次对话允许发往此端点」。
3. Mobile、Desktop 里的同类卡片照此处理。

### C. 只保留一种「助手权限」页
1. `Muyon Assistant Settings` 的「助手权限」页，换成 `Muyon Assistant Auth` 里的新版：模式、四类开关（只能收紧）、授权列表、变更审计、外传内容审查、固定说明。
2. 全稿删除「逐次确认不可关闭」「写入与外传无论开关如何……不可关闭」这类说法，包括 `Muyon Mobile` 规则详情里的「每次确认（不可关闭）」。
3. `Muyon Mobile` 顶部说明里的「红/绿仅用于失败/成功」，改成现行规则：红表示失败、危险、外传，`warn` 表示需注意，绿表示成功。

### D. 对话页里放真正的确认卡
1. `Muyon Mobile`、`Muyon Desktop` 的**对话页**里，放入写入确认卡（带可以展开的「更多」）、批量确认卡，以及它们在外部内容下的变体。直接复用 `Muyon Assistant Auth` 的组件和状态切换，不要在收件箱里画静态副本。收件箱里的卡片也换成同一个组件。
2. 其他地方的旧式确认按钮（「拒绝 / 允许本次请求」「确认外传」等），统一换成同一个确认卡组件。涉及的文件包括 `Muyon Platform Gaps`、`Muyon Exchange Hub` 的发布确认、`Muyon Inquiry Core` 的智能导入。
3. `round7-notes.md` 里 E1 的说法要按实际情况更正。

### E. 标签与工具 ID
1. 「向远程模型发送摘要」这类卡片，全稿统一叫「**远程模型**」，标签用 `red / redbg`。现在 `Muyon Mobile`、`Muyon Desktop`、`Muyon Accessibility` 各有一处用的是 tint 底。
2. 删除虚构的工具 ID：
   - `inquiry.search_material`（`Muyon Exchange Hub`）；
   - `hub.publish_quote`（`Muyon Platform Gaps`，外传示例改用 `transfer.send`）；
   - `inquiry.create_project`（`Muyon Mobile`）。
3. `inquiry.search` 在 `Muyon Exchange+System` 里的描述「待办汇总」不对，改成「搜索询价数据」。
4. 「接纳报价 / 状态改为已采纳」不要对应 `inquiry.record_quote`，改用 `inquiry.set_inquiry_status`，或者删掉这个示例。
5. `research.*`、`catalog.*` 的工具名在稿里统一标注「示例名称」。

### F. 撤回上一轮误改的尺寸
1. 原本是 44×44 的方形或圆形元素，上一轮只改了高度，变成了 44×48 的椭圆，一共 19 处。统一改成 48×48，保持方形和圆形。
2. 纯视觉元素恢复原来的尺寸：
   - 所有手机状态栏（9:41 那一行）恢复 44；
   - 空占位、骨架块、tint 提示条、搜索框占位恢复原尺寸；
   - 数据中心本体图里的节点恢复原尺寸，并检查节点有没有重叠。

### G. 深色模式的对比度
1. 链接一律用 `acc` 变量，不要写死浅色蓝 `#2458D3`。它在深色面上只有约 3:1，涉及 `Muyon Assistant Auth`、`Muyon Assistant Settings`、`Muyon Research` 里的链接。
2. `Muyon Inquiry Core` 深色模式下，红色危险按钮上的白字对比度只有 2.54:1，改成深色字，或者给按钮换一个更深的底色，保证 ≥ 4.5:1。

### H. 无障碍预览框
在 `Muyon Accessibility` 里，给第五至七轮的新画面补上 320 宽和 200% 字号的预览框，浅色、深色各一屏。新画面包括：确认卡、批量确认卡、外部内容提示条、已授权端点外传卡、事件时间线行。另外核对一处：现有 200% 预览框里，设置行的文字被裁切，弄清是预览框太窄，还是真的溢出。

### 交付
- 仍然是 `.dc.html`。
- `round8-notes.md` 只写当前的真实状态：A～H 每一条写「已改」或「未改，原因」。凡是写「已改」的，要能在稿里直接找到对应位置。
- 不要渐变，不要吉祥物；不要把「待确认」画成黄色；不要虚构指标或工具 ID。
