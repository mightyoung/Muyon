# 沐阳 AI 原生界面重新设计（参考 OpenAI Intelligent UI）

日期：2026-10-09 · 作者：leader A · 状态：**已采纳**（用户 2026-10-09：§10 全部按建议，由 leader A 统一派发；并新增 §4.4 本体驱动的业务卡片）
依据：用户 2026-10-09 要求「全面使用 AI 原生界面重新设计 UI」；[AI Agent 与智能交互整体设计方案](../superpowers/specs/2026-10-08-ai-native-architecture/Muyon_AI_Agent与智能交互整体设计方案.md)（下称「整体方案」）；[ADR-0002](../adr/0002-graded-assistant-authorization.md)；[ADR-0004](../adr/0004-module-contract-v2.md)；[设计稿 v6](v6/README.md) 与[前端开发备忘录](v6/frontend-memo.md)。

## 0. 结论

1. 沐阳的主界面改为**以对话为中心**：用户提出目的，助手的回答本身就是可以操作的界面，例如可以改参数的比价表、可以拖动的预算、可以直接确认的清单。固定的业务页面不取消，降为「从回答里打开的工作区」和兜底入口。
2. 技术上不推倒重来。整体方案和 UI-3a～4c 已经做出了正确的骨架：模型只规划表达、宿主校验后渲染、数值只能绑定宿主给的事实、事件分三路。本方案补三样东西：**流式编译**（回答边生成边出现）、**组件库 v1**（约 24 个组件）、**以对话为中心的外壳**。
3. 设计稿 v6 不再作为页面稿使用，只保留它的视觉层（token、组件外观、深浅色）；前端开发备忘录里的安全要求继续有效。
4. **能力的演进放在本体与工具这一层，不放在插件页面上**（用户 2026-10-09）。业务插件的固定页面冻结，只负责固定入口和固定展示方式。新的业务能力通过在插件里登记本体（字段、关系、动作）和工具来增加，由沐阳在对话里生成卡片、执行与组合呈现。所以插件页面不更新，沐阳的能力也能持续跟上数据结构的变化。
5. 路线图里原来的 UI-2～UI-9 由本方案的 AIUI-0～AIUI-8 取代。Leader B 已经完成的 UI-2a、3a、3b、4a、4b、4c 作为 AIUI 的地基保留，不重做。

## 1. OpenAI Intelligent UI 是什么（公开资料，2026-10-07 发布）

| 要点 | 内容 |
|---|---|
| 形态 | 回答里混合文字、图表、表单、按钮、可点的示意图、地图、清单、小计算器；调整其中一个数字，结果当场更新，不用再问一遍 |
| 何时用界面 | 由模型判断：对比用并排卡片，复杂概念用可交互的示意图；文字足够时仍然只给文字。不需要特殊提示词 |
| 实现 | 一个**原生、可流式的组件库**，加一个**编译器**：界面在模型生成的同时逐块出现，不等全部生成完 |
| 回传 | 多选题式的追问、表单提交，会把用户的选择交回模型继续对话 |
| 用户控制 | 设置里可以关闭「布局与可视化」，但不保证完全只出文字 |
| 限制 | 只在网页和新版应用、特定推理档位下可用；没有公开 SDK |

社区的开源实现 [open-intelligent-ui](https://github.com/thesysdev/open-intelligent-ui)（基于 OpenUI）用 `defineComponent` 注册组件，模型流式输出 OpenUI Lang，表单通过 `@ToAssistant` 把选择回传给模型。思路和整体方案一致。

来源：[MacRumors](https://www.macrumors.com/2026/10/07/chatgpt-intelligent-ui/)、[TechRepublic](https://www.techrepublic.com/article/news-gpt-6-intelligent-ui-charts-forms/)、[open-intelligent-ui](https://github.com/thesysdev/open-intelligent-ui)。

## 2. 沐阳与 Intelligent UI 的根本差别

ChatGPT 的回答大多是一次性的解释；沐阳的回答对应的是**真实业务数据和真实写入**。所以必须多守住四条，这四条也是本设计和 ChatGPT 最大的不同：

1. **数值不由模型生成**：界面上每个数字都绑定宿主给的事实（`DataSnapshot`），或者由宿主按登记过的公式算出（`ComputedValue`）。模型只决定「怎么摆」，不决定「是多少」。
2. **写入和外传必须经过确认卡**：回答里的按钮只能触发登记过的动作；写入和外传一律走 ADR-0002 的授权与确认卡。外部内容进入任务以后，不提供任何放行类选项（备忘录、Q11）。
3. **回答是可持久、可恢复的**：重开应用后，回答仍然可以操作；数据变了，回答上显示「数据已更新，查看变化」，不会悄悄改数。
4. **本机和离线可用**：小模型或离线时，退回到文字加固定组件；本地交互（排序、展开、本地重算）不依赖模型。

## 4. 产品形态

### 4.1 外壳：以对话为中心
| 区域 | 手机 | 桌面 |
|---|---|---|
| 主区 | **助手对话**（打开应用直接到这里），回答以卡片和小工具呈现 | 中间是对话；右侧是「当前工作区」（从回答里打开的表格、阅读器、对象页） |
| 底栏 / 图标轨（4 项） | 助手 · 任务 · 资料 · 设置 | 同左，竖排 |
| 任务 | 进行中和待我确认的任务、子对话、执行记录（取代收件箱和工作台） | 同左 |
| 资料 | 对象和文件的检索入口：询价、科研、原型、知识库都在这里按对象浏览；也可以从这里打开原来的固定业务页面 | 同左 |
| 设置 | 模型、助手权限（ADR-0002）、「界面与可视化」开关、数据去向、插件 | 同左 |

原来的「业务插件」「数据交换」不再单独占底栏：业务插件的页面从回答或「资料」里打开；数据交换并入任务（发送和接收都是任务）。

### 4.2 回答的四种形态
| 形态 | 什么时候用 | 例子 |
|---|---|---|
| 文字 | 简单问答、解释 | 「这家供应商在哪个城市」 |
| 文字加补充卡 | 结论加证据 | 一句结论，下面是对象 chip 和来源卡 |
| **交互小工具** | 用户可能要换条件再看 | 比价表：改数量、选含税或不含税，总价由宿主当场重算；预算：拖动加价率，看毛利变化 |
| 工作区 | 内容多、要长时间编辑 | 导入审阅的分组表格、论文阅读器；回答里只显示摘要卡和「打开工作区」 |

回答的末尾可以带**追问选择**（单选或多选 chip、条件表单）。用户的选择以结构化的方式回传给模型，不需要再打字。

### 4.3 动作与确认
- **本地动作**（排序、筛选、展开、改小工具里的参数）：不经过模型，立刻生效，只改界面状态。
- **业务动作**（新建询价单、录入报价）：生成确认卡（v6 `Muyon Assistant Auth` 的版式，按备忘录只做一个组件）。用户批准或者存在授权时才执行，执行结果以真实回执回写回答。
- **语义动作**（「再比一家」「换成按交期排序并解释」）：作为一条新意图交回模型。

### 4.4 本体驱动的业务卡片（用户 2026-10-09 新增要求）
各业务插件都在 v2 契约里注册了本体（ADR-0004 §4.3：对象类型、字段、类型、必填、枚举、关联目标、敏感度、关系、动作）。助手据此可以**在对话里直接生成业务表单卡片**，替代一部分插件页面的功能：

| 卡片 | 生成依据 | 执行 |
|---|---|---|
| 新建卡（如「新建供应商」「新建询价单」） | 对象类型的字段清单：类型决定输入组件（文本、数字、日期、枚举 → Choice、关联 → 对象选择器），必填项标出，敏感字段按 Q7 遮盖 | 提交时走该插件注册的写工具，经确认卡或授权执行，成功以回执为准 |
| 编辑卡 | 当前记录的事实快照加字段清单，只显示用户或模型选中的字段，其余可展开 | 只提交改动的字段；带记录修订号，记录在此期间被改过就提示冲突 |
| 关联卡 | 关系声明（例如 询价单 → 供应商） | 选择已有对象，或者就地新建一个再关联 |
| 批量卡 | 多条同类记录（例如导入审阅），用 Table 加逐行状态 | 走 BatchConfirmCard |

演进方式：插件新增或修改字段、关系、动作时，只需更新本体声明和对应工具，再过契约合规测试（REG-5）；对话里的卡片会自动跟上，不需要改插件页面，也不需要改宿主。本体加了字段而固定页面没有加，属于预期情况：固定页面只保证原有展示，新字段在对话卡片和「资料」的对象详情里可见可改。

规则：
- 卡片的结构由**宿主按本体生成**，模型只决定「出哪张卡、预填哪些值、先显示哪些字段」。模型预填的值标「建议」，用户确认前不算数。
- 校验用插件自己的校验器（询价是 `supplier_core` 的 validate），宿主在提交前和执行时各校验一次；不合法的字段就地标红，不发请求。
- 只有插件注册了写工具的对象类型才出新建或编辑卡。覆盖清单（ADR-0004 §8.2）里标为不开放的操作，卡片显示「请在原页面操作」，并给出入口。
- 敏感字段（`personal`、`commercial`）默认遮盖，`credential` 永远不进卡片。
- 询价先做：它的本体已经完整注册（`apps/muyon/lib/app/adapters/inquiry_module.dart:308`）。还要补按本体通用的新建、修改、删除工具（REG-4c），现在宿主只注册了 4 个具体的写工具。科研、原型等 REG-3 迁移到 v2 后再做。

## 5. 技术设计

### 5.1 流式界面协议
模型输出一串**界面片段**（JSON Lines），每行一个操作：

```
{"op":"node","id":"n1","type":"Heading","props":{"text":"3 家报价对比"}}
{"op":"node","id":"n2","parent":"root","type":"CompareTable","bind":{"rows":"fact:quotes@rev12"}}
{"op":"patch","id":"n2","props":{"highlight":"min:total"}}
{"op":"action","id":"a1","on":"n2.select","route":"business","operation":"inquiry.award"}
{"op":"end"}
```

- **编译器**在宿主侧逐行接收，每个节点按组件模式**单独校验**后立刻渲染；通不过的节点换成占位，并记录原因，不影响其他节点。
- 绑定只能引用快照里存在的事实或登记过的公式；动作只能引用目录里登记过的动作。这两条在编译时检查，和现有的 `ValidatedUiPlan` 规则一致。
- 用 `op:"end"` 收尾；流中断时保留已经渲染的部分，标「未完成」。
- 文字和界面可以交替出现：文字片段 `{"op":"text","md":"…"}` 按段落流式显示。
- 不支持原生工具调用或不能稳定输出这种格式的模型，退回「文字加固定卡片」，由宿主按任务阶段选模板（整体方案 §10 的默认表达）。

### 5.2 组件库 v1（合并现有两份目录）
| 类别 | 组件 |
|---|---|
| 版式 | Heading、Prose（流式 Markdown）、Section、Columns（宽屏并排、窄屏堆叠）、Tabs、Disclosure（多级展开） |
| 数据 | Table、CompareTable（候选对比，标出最优、不满足和未核验）、KeyValue、Metric（单个数字加口径）、Chart（柱、折线、饼；数据只能来自绑定） |
| 输入 | Choice（单选、多选，可自填）、Form（字段组）、NumberStepper、Slider、Toggle、DateField |
| 业务 | ObjectChip、SourceCard、FileCard、ProgressCard（任务阶段）、Checklist、Timeline（事件或血缘） |
| 安全 | ConfirmCard、BatchConfirmCard、WarnBanner、ScopeChip（沿用 UI-1a，按备忘录收紧） |

每个组件都要有：属性模式、绑定规则、事件、只读态、加载态、错误态、降级态；能用固定样例单独渲染，并有 golden 测试和对比度测试。尺寸按内容自适应（UI 方案 §8 第 19 条）。

### 5.3 本地重算
小工具里的数字由宿主算，不由模型算。可用的公式先只登记一小组：求和、乘积、按含税或不含税换算、加价率与毛利、按数量取阶梯价。公式按名称引用，参数只能是绑定或用户的输入值，不允许任意表达式或代码。模型只选公式和参数。

### 5.4 持久与恢复
每条回答保存：`UIPlan` 的最终版、所绑定事实的版本号、本地界面状态（参数值、展开项）。重开时按当前事实重新计算；版本变了，就在回答上显示「数据已更新」，点开可以看前后差异。正在编辑的内容不被流式更新覆盖：保持稳定的节点 id、焦点与滚动位置（整体方案 §10.2）。

### 5.5 用户控制与无障碍
- 设置里提供「界面与可视化」三档：自动（默认）、少用、只用文字。
- 每个组件都要有文字等价物（读屏朗读和复制时用），图表附数据表。
- 减少动态效果时，流式出现改为整块出现。

## 6. 不变量（验收时逐条测试）
1. 界面上的任何数值都来自事实绑定或登记过的公式；模型输出的裸数字不渲染为数据（只能出现在文字里，并标「模型所述」）。
2. 任何写入或外传都只能经过确认卡或授权执行；点击回答里的按钮本身，不等于「成功」，成功以回执为准。
3. 外部内容进入任务后，回答里不出现放行类按钮（与 Q11、备忘录一致）。
4. 校验不过的节点不渲染；流中断不产生半截的动作。
5. 「只用文字」档下，所有功能都仍然可以通过文字和固定页面完成。
