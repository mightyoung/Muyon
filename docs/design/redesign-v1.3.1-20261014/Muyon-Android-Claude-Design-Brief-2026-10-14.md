# Muyon Android 设计需求与 Claude Design 交付简报

版本 1.0｜2026 年 10 月 14 日 北京时间｜交付对象 Claude Design 与后续产品 交互 Android 客户端评审

## 1 任务与交付目标

请为 Muyon 设计一套可实施的 Android 手机与平板应用界面，覆盖助手对话、科研与 PDF、询价报价、任务执行、公司资料中心、记忆和身份管理。目标是让用户表达意图后，始终能找到真实业务对象、检查来源、继续手工编辑，并知道哪些动作已经发生、哪些仍待核对。

本次交付是设计稿、可点击原型、组件与状态规范，不是产品代码、上线证明或竞品复刻。不得调用外部 Claude、上传项目或私密资料来替代这份设计任务。后续是否将本简报交给外部服务，由用户另行决定。

总体方向：参考 WorkBuddy 的工作型页面组织和任务规划感；参考 Muse 对用户信息、助手身份、表达偏好与记忆的可见管理；参考 Claude 的长文阅读节奏、对话与独立成果、研究及执行摘要；参考 ChatGPT 的工具动作与可交互结果。Muyon 的导航、视觉、权限和本地业务状态须独立设计，不能把四款产品的界面拼贴起来。

成功标准：

1. 用户能区分“助手说了什么”“我正在编辑什么”“系统真正做了什么”
2. 所有核心工作均能从固定业务页面继续，不依赖重新向模型描述或找回某张聊天卡
3. 手机单手可操作，平板利用双栏；旋转、分屏、大字体、离线和进程重建不丢合法保存的工作
4. 正常路径简洁；版本冲突、撤权、结果未知、取消与恢复不以一张通用错误页敷衍
5. 设计清楚标出已有迁移能力、新增能力、待决能力和不可用能力，不以高保真外观暗示已经实现

## 2 产品 用户与核心任务

### 2.1 产品定义

Muyon 是以本机数据与可编辑业务工作台为基础的个人助手。用户可以自然语言提出目标，也可以直接操作业务页面；两条路径必须进入同一套受控业务命令与真实数据对象。

Android 技术方向为 Kotlin 与 Jetpack Compose；业务事实、授权、对象版本、执行账本与恢复由本机 Rust 内核承担。与桌面共享 Rust 代码和合同，各设备仍有独立本地库和账本。页面不能暗示存在一个云端 Rust 总账。

“非云端依赖”表示应用的本地浏览、手工编辑、已具备的本地计算与恢复不以云端常驻服务为前提，不等于禁止联网模型、连接器或公司部署的可选 Hub。连接和执行位置要按动作显示：此设备、指定外部服务，或当前不可用。未配置本地模型时不能承诺离线生成。

### 2.2 核心用户与工作情境

下列是为设计组织任务的目标情境，不是经访谈证明的人群统计。

- 科研使用者：阅读长 PDF、做批注、核对结论、整理结构化记录、构建论证与报告
- 询价与选型使用者：维护需求版本、查供应商和同事共享报价、比较配置与费用口径、编辑草稿和台账
- 持续使用个人助手的人：管理上下文、助手名字与风格、个人事实和经验，理解数据何时被使用或外发
- 同一用户在手机碎片时间和平板长时工作之间切换：手机审阅、补充和核对；平板阅读、比较和编辑；不得据此假定两台设备自动共享任务

### 2.3 设计必须支持的工作闭环

| 闭环 | 开始 | 用户可检查的中间物 | 明确结束条件 |
| --- | --- | --- | --- |
| 普通问答 | A01 提问与附件 | 本次上下文、来源、未送达状态 | 回答已生成；不冒称产生业务效果 |
| 确定性业务操作 | D01.1 修改供应商名称 | 我的修改、当前保存版、差异 | Rust 持久回执定位同一对象的新版本 |
| 科研 | 文献与问题 | 原文选区、批注、证据、人工草稿 | 可追溯记录或稿件；导出另有回执 |
| 询价选型 | 已确认需求 | 候选证据、技术缺口、费用口径 | 草稿、比较快照或台账；不等于采购 |
| 公司资料中心 | 已配置公司远端服务 | 服务状态、同事/供应商资料、历史报价、发布预览 | 发布回执或明确未知并可核对 |
| 设备研究交接 | 收到研究说明 | 接受责任、导入研究、人工工作、结果包 | 原任务核验并导入结果；不等于远程代理自动执行 |
| 记忆管理 | 用户编辑或发起整理 | 来源、核实、用途、提案、冲突 | 真实保存/核实/遗忘回执，界面与后续使用一致 |

## 3 借鉴方法与证据边界

### 3.1 借鉴不是复刻

每处参考必须同时写明“观察或资料指出了什么”“Muyon 采用什么原则”“Muyon 不继承什么”。设计稿旁标参考 ID，不写“完全还原某某 App”。像素、字体、间距和布局尺寸在本简报中均是 Muyon 提案。

竞品研究主要是静态 APK 报告，不是本轮登录 App 后的屏幕与行为测试。WorkBuddy 的被引用配图缺失，Claude 样本仅 base APK，ChatGPT JADX 约 66% 中止。不能用这些资料宣称完整功能不存在、所有界面都长某样、或恢复及外部效果获得严格保证。公开帮助与官方文章只能支持其明示范围，不能补造 Android 私有实现。

### 3.3 用户任务优先于竞品外观

WorkBuddy 负责启发“工作怎么分布在页面中”，Muse 负责启发“我与助手的持久信息怎么管理”，Claude 负责启发“长内容、成果和过程怎么读”，ChatGPT 负责启发“结果如何直接操作”。发生冲突时，以用户能完成真实任务、核对事实和保留手工修改为准，不为追求像某款 App 而改变合同。

## 4 已确定的交互约束与待决范围

### 4.1 必须直接落实的决定

1. 三主入口为助手、工作台、任务；设置保持稳定可发现入口
2. 业务动作可从固定页面或生成卡直接交给 Rust；不强制先调用模型
3. Auto 与 FullAllow 是独立模式，不能合并、同义翻译或在视觉上混为一个“自动”
4. FullAllow 在已选工作区、现有访问权和当前任务范围内，个人及商业敏感资料的模型请求/业务外发默认允许，覆盖此前未用过的新网站/API 目的地；不因高风险、新目的地或仅来源风险再加一次批准
5. FullAllow 仍检查真实任务范围、访问权、撤权、参数、版本、CAS、稳定意图、业务不变量与不可绕过的系统/第三方限制；这些失败不是“再点允许即可修复”
6. 凭据不进入模型载荷或普通业务 payload；服务认证只走专用凭据通道，界面展示配置状态或安全引用，不显示真实密钥
7. `unreviewed` 在可信分类完成前禁用派发；完成分类并满足当前模式及硬条件后按既定规则放行，不为分类结束追加一轮审批。未分类不等于永久禁止，第三方文字也不能自称已分类
8. ordinary personal / commercial-sensitive、credential、unreviewed 的区别要在 A03、S04、T02 和发送/发布预览看见；不能藏在实现附录
9. 未知外部效果先查询原操作和回执，不能把“重试”做成显眼通用主按钮
10. 用户明确要求“再做一次”时，创建关联旧 unknown 的新 intent/operation，页面就地提示可能重复，旧操作仍保持 unknown；FullAllow 不加额外弹窗。模型自行重试或断线重连不构成用户新指令。本机导出的显式新副本仍单列新目标与冻结内容语义
11. 模式已确定为只读、每次询问、Auto、FullAllow 四档，首次默认 Auto，低风险并入 Auto；旧配置迁移不得自动扩大权限
12. 自动对话记忆提取和助手跨会话历史检索已确定纳入整体改造，首次默认关闭、分别开关，继承来源/用途/版本/墓碑约束；独立排期，不阻塞 Rust 首个切片

### 4.2 未定项如何呈现

以下保留在设计决策页，不做默认启用或假可操作开关：临时会话、可选聊天留存及退出清理细则、记忆/附件/索引容量上限、Android 屏幕读取及范围、账号类型限制；旧模式的逐字段兼容迁移仍需落实，但四档组成和默认 Auto 已经确定。

“全部允许”已定范围、默认 Auto 和两项新增能力不能重新列成待选项。允许设计两个视觉方案，但不得给同一已定模式设计不同权限语义。容量显示有依据的实际占用，不能写无限；屏幕入口不使用暗示正在采集的图标或红点。

### 4.3 当前已有与新增的标识

| 领域 | 代码基线中可保留的基础 | 新设计需要单列的能力 |
| --- | --- | --- |
| 助手与业务 | 会话、任务、资料、业务页面、对象版本绑定等迁移基础 | 三入口编排、统一摘要、多轴恢复展示 |
| 记忆 | 手工维护记忆、有效记忆筛选/注入、经验和用户发起整理 | 四个独立控制、新 CAS/回收/遗忘恢复合同 |
| 自动记忆 | 不能由已有 memory 表推定完整自动提取器已实现 | 已批准新增自动提取、自动写入开关及在途阻断；首次默认关闭，独立排期 |
| 历史 | 现有聊天会保存；同会话历史/最近上下文已有基础 | 已批准新增独立助手跨会话历史检索，首次默认关闭；不写成基线已接通 |
| 留存 | 当前保存行为要如实显示 | 可选聊天留存控制、新临时会话策略未提供或待决 |
| 公司资料中心 | 既有 Hub 远端服务、查询、发布及恢复链须保留 | Android 新编排，状态与用途投影更明确 |
| 设备研究 | 既有设备通信与研究说明/结果交接链须保留 | 新页面明确区分接纳/导入/人工工作/回传，不虚构自治 agent |
| 询价外发 | 既有草稿与导出等基础 | 真正邮件发送适配未完成前不可画成可用 |

“现有基础”仅表示源码迁移依据，不表示本轮真机验证。全部新页面稿仍是目标设计。

## 5 信息架构与导航规则

### 5.1 顶层结构

- 助手：A01 对话、A01.1 专题、A02 历史与全局搜索、A03 本次上下文
- 工作台：W01 最近工作与模块入口，W01.1 受限原型；科研 R01–R08；询价 Q01–Q06；数据 D01 与 D01.1–D01.3
- 任务：T01 任务列表、T01.1 消息中心、T02 活动与执行详情、T03 动作决定
- 设置：S01 外观和无障碍、S01.1 呈现策略、S02 模型、S03 连接器、S03.1 MCP、S04 权限、S05 存储导出、S05.1 设备交换、S06 记忆经验整理、S07 助手身份

手机底部三项导航一直显示文字标签。深层编辑、阅读或决定页面可以隐藏底栏以保留空间，但必须有原生返回；返回不取消任务、不批准动作、不重放工具。设置从顶栏命名菜单固定进入，A01 身份、模式、上下文标签有直达入口。

平板使用导航栏/导航轨与列表详情。任务、项目和文献都有独立身份；不通过复制卡片创建第二份业务对象。搜索结果、通知、对话结果与工作台必须深链到同一个对象与版本。

### 5.2 返回与恢复

每条路由保留 `objectRef + revision + origin + reading/editing anchor` 的设计注释。返回恢复原搜索词、筛选、滚动、选区与编辑草稿。项目切换保留各自合法草稿；不把当前项目当作全盘读取授权。

系统返回顺序按当前交互：退出选区/键盘/局部面板，再回上一页；有未保存修改时显示准确影响与保留/放弃选项。退出页面与停止生成、取消任务、撤权分别设计。平板缩回单栏保留当前操作对象，不跳回首页。

## 6 Android 布局 排版与视觉系统

以下为 Muyon 原创起始值，需设计验证与真机测量。不是竞品测量结果。

### 6.1 视口与自适应

| 当前可用窗口 | 起始布局 | 主要行为 |
| --- | --- | --- |
| 小于 600dp 宽 | 单栏、底部三导航、详情全屏 | A03/T03/复杂表单全屏；来源用可展开层或跳页 |
| 600–839dp 宽 | 宽单栏为默认，内容足够时尝试轻量列表详情 | 不强制双栏；短高度、大字体、键盘占用时退回单栏 |
| 840–1199dp 宽 | 导航轨加两栏 | 对话/成果、列表/详情、PDF/证据，主任务优先 |
| 1200dp 及以上 | 仍以两栏为主，允许按需辅助栏 | 限制长文行长；不能因空位而常驻三块复杂表单 |
| 任意宽度的短高度、折叠铰链或 200% 字体 | 重新检查可用空间 | 按内容和姿态调整；按钮、输入与安全字段不得压缩消失 |

Android 当前官方窗口分类以可用窗口决定，而不是以设备名决定；尺寸可随分屏、折叠和旋转动态变化。设计必须交付至少 360dp、412dp、600dp、840dp、1024dp 宽的代表帧，并给 600/840 附近的连续重排说明。以上代表帧是验证样本，不是支持设备白名单。来源见 AND-04。

PDF 不按正文重排原始版式。手机正文区内的复杂业务表优先转换成对象卡或双候选比较，保留完整表格入口；表格横滚必须有明确提示，不能把关键状态藏在右侧屏外。

### 6.2 排版

采用 Android 系统可用字体与中文回退；不导入 Claude/Muse/ChatGPT 专有字体。中文长文与数字混排优先可读性。品牌字体若以后引入，须单独列授权和字体缩放验证。

| 用途 | 起始规格 | 约束 |
| --- | --- | --- |
| 页面标题 | 24sp / 32sp 行高，medium | 长项目名可换行，短栏可转为 20sp 级标题 |
| 分区标题 | 18–20sp / 26–28sp，medium | 不用全大写或纯颜色制造层级 |
| 对话与正文 | 16sp / 25–26sp，regular | 长文自然分段，避免整段卡片底色和每句独立气泡 |
| 表单字段与结果值 | 16sp / 24sp | 字段名、单位、错误和来源相邻 |
| 次级说明 | 14sp / 21sp | 不能用小字承载唯一风险、目标或未知提示 |
| 元信息 | 13sp / 18–20sp | 时间、版本等可用；重要状态仍采用正文/次级级别 |
| 代码/原始标识 | 系统等宽 13–14sp | 只在展开诊断里出现；不迫使用户理解哈希才能完成任务 |

对话正文建议维持约 32–44 个中文字符的舒适行长，平板限制内容最大宽度而不无限拉长。此为阅读起始建议，需真实长中文验证。答案允许标题、列表、引用入口、表格/成果卡；不得把模型思考过程伪装成透明执行信息。

### 6.3 间距 形状与颜色

- 间距：4、8、12、16、24、32dp；手机内容边距起始 16dp，平板主内容 24dp
- 形状：普通卡片圆角 12dp，输入区 16dp；表格、差异和可信决定面板优先清楚边界，不把所有元素做成胶囊
- 浅色：背景 `#FAFAF9`，表面 `#FFFFFF`，正文 `#202020`，次级 `#666666`，装饰边界 `#D9D9D6`，强调 `#245D55`
- 深色：背景 `#171717`，表面 `#222222`，正文 `#F2F2EF`；次级文字、强调、焦点和状态色独立建立并测量，不反相推导
- 语义令牌至少有 surface/base/raised、text/primary/secondary/disabled、border/decorative/interactive/focus、action/primary/secondary、status/info/success/warning/error/unknown
- 成功、等待、未知、失败、历史与示例都使用文字和图标，不能仅靠颜色；强调色不作为唯一成功色
- 不使用大面积渐变、持续光效、假思考呼吸动画或未知百分比来制造活跃感

### 6.4 触控 键盘与无障碍

交互命中区至少 48×48dp，邻近目标不能重叠；24dp 图标可放在更大命中区。仅有图标的动作须有可见说明或可发现标签，并有语义名称。原生状态栏/导航栏、屏幕缺口、IME 安全区、系统返回与系统文件选择器按 Android 行为设计。来源见 AND-01。

普通正文对比度以至少 4.5:1、必要非文字识别以至少 3:1 作为验收目标；当前色值未宣称全部已测。200% 字体与最大系统显示缩放检查重排，不用固定高度裁字。TalkBack 需读出名称、角色、当前状态、错误原因；只读文本不重复播报冗余图标。

异步流式文本按段落节流通知，不逐 token 抢读；新消息提供“有新内容”回到底部，不强迫滚动。展开后焦点进入合理标题，关闭回原触发器；表格提供逐行语义替代。中文输入法组字时 Enter 不发送；手机默认换行，发送使用明确按钮。平板键盘与指针可完成所有核心动作，拖动重排必须有“移到…”替代。

动效起始 120–180ms，尊重减少动效；动效结束不决定业务状态。加载占位稳定布局，避免跳动正在编辑的字段。未知与断连使用静态说明及最近确认时间，不无期限伪装运行中。

### 7.2 按钮必须有可审查的动作类型

| 类型 | 示例 | 交互与执行规则 |
| --- | --- | --- |
| local_ui | 展开、筛选、排序、换候选对 | 即时响应，不调用模型，不触发风险审批 |
| local_draft | 本机草稿改句、填字段、临时试算参数 | 明确未提交；不能自动写正式台账 |
| business_command | 保存名称、提交记录、核对发布、应用记忆提案 | 直接 Rust；对象、版本、参数、稳定意图和模式重新核验 |
| model_request | 重新理解、生成新内容、重新规划 | 显示模型与实际发送范围；也是可能的数据外发 |

复制、外部导航、日志和导出根据真实效果归类，不能凭名字一律视为 local_ui。生成组件仅能使用白名单与可信引用；不能注入任意脚本、改写业务真值、伪造权限或生成“确认”宿主控件。W01.1 的受限脚本原型另有沙箱和宿主桥，不等于普通原生生成卡。

### 7.3 产物与摘要

产物可以同时是“可交互”和“可调用能力”，但能力徽标由宿主提供；它说明能做什么，不说明已获授权或已完成。模型正文写“已保存”不能改变徽标或账本。

摘要先展示确定性动作/回执，生成摘要后补说明。研究 0 个来源就显示 0；“3 个动作、4 次尝试”不能写成 4 个动作。并行时长不直接相加为总耗时。无可靠时钟显示估计或未知。摘要失败、过期、历史不完整均不改写已确立的业务效果。

## 8 逐页设计要求

以下每页都继承第 9 节公共状态合同。页面稿必须画入口、主操作、返回落点与至少一个关键异常；同组共享样式不等于省略业务字段。

### 8.1 助手与工作台

#### A01 助手对话

目的：表达意图、阅读回答、看见真实任务与成果；入口为主导航及历史/通知返回。

手机顶部为会话标题和项目，第二层用可读文字显示模式、上下文/记忆、模型目的地；任务条贴近内容上方，不占满屏幕。正文尽量留给阅读，底部为多行输入、附件与发送。平板可按需打开成果或来源支持栏，历史列表不长期挤压编辑区。

必备：当前身份入口、附件生命周期、送达状态、来源链接、执行摘要、真实/示例产物、停止生成与取消任务的分离入口。用户滚到旧消息时新内容不强制拉回。点击业务卡直接进入 Rust，卡片筛选不发模型；补充在途任务时标明目标任务与范围变更。

原型异常：发送超时保留原发送身份；压缩中输入保留；撤权清旧内容；摘要失败但保存已成功；同一任务部分成功和一项未知。聊天保存、读取记忆、自动写入和历史检索各自说明，未提供的新控制不显示为已生效。

#### A01.1 专题会话

目的：在主会话下组织相关讨论，不复制任务或扩大父授权。手机列表进入独立对话，顶部清楚回主会话；平板可在会话列表显示层级。

显示主题、父会话、自己的上下文、草稿与关联任务；主题同名仍是不同对象。创建/重命名/归档是确定命令，继续讨论才发模型。归档不取消运行任务。专题已有只读边界须保留；不因主会话模式改变而静默扩展专题写入范围。

#### A02 历史与全局搜索

目的：找回对话、任务、文件和结果，不重新执行。搜索框、类型/项目筛选、范围说明与匹配片段置于首屏。

手机单列，平板列表和只读预览。标题、对象类型、项目、时间、版本、是否本机可用清楚分层。无结果、尚未索引、索引部分完成、读取失败分别设计。“助手跨会话检索”是已批准、首次默认关闭的新增能力；用户手动浏览自己获准历史不受它的开关代替。

点击命中回原对象与锚点；归档不取消任务；删除有范围/恢复说明。撤权与遗忘在查询和片段展示时立即过滤，不等索引物理删除才隐藏。

#### A03 本次上下文与使用范围

目的：回答本次“用了什么、用于什么、发往哪里、哪些被排除”。手机全屏，平板支持栏；不是每次发送必弹拦截。

分区为项目资料、附件、记忆、历史、能力、模型/业务目的地。每项展示来源、版本、用途、候选/实际选用/排除状态与可读原因；凭据仅显示已配置/缺失，不呈现值。当前消息、当前任务、项目默认的范围分别表达。

移出本次不删除原资料；更改范围使相关旧计划失效。FullAllow 合法任务范围内个人/商业外发和新目的地不逐对象批准；真正缺读权、已撤权、credential 或未完成可信分类按具体原因阻止。实际选用清单来自核心，不接受模型自称已读。

#### W01 工作台总览

目的：继续真实工作。手机先最近项目/草稿/结果，再科研、询价、资料、公司资料中心与原型的有名入口；平板项目列表与最近工作并排。

不做空泛 AI 功能九宫格。最近项带模块、对象、版本、可用性和真实任务状态；待决定独立标识，不能由模型虚构紧急优先级。科研、询价和 Hub 保持业务身份，返回助手保持原消息。

空态给创建项目、导入文件、打开已有资料。模块缺失/停用/不兼容给具体说明；保留获准历史入口。导入先选目标用途，不默认为云解析或全盘访问。

#### W01.1 受限原型页面

目的：承接既有原型模块，展示可运行的受限交互成果。Android 全屏受限 WebView，可信顶栏固定显示来源、内容版本、真实/示例与能力详情，原型内容不能覆盖它。

重新载入不重复业务动作；网络、剪贴板、文件、模型和写入逐项声明。失败、资源缺失、版本不兼容、桥接被撤销各有状态。关闭不取消关联任务；无可访问性支持时不能成为唯一业务入口。

### 8.2 科研与 PDF

#### R01 科研项目与文献库

目的：管理研究问题与文献集合。项目名/问题、搜索、全部/已批注/待核验筛选、文献卡、导入入口；平板列表/摘要两栏。

文献项显示题名、作者/年份（未知留空）、文件版本、页数、可达性和阅读位置。导入多文件展示逐项结果与重复候选；移出项目与删除原文件不同。离线只承诺本机已可读文献，不标“已同步”。

#### R02 PDF 阅读器

目的：读原版文档并创建准确选区。手机画布最大化，工具栏可收起，页码/大纲/批注可达；平板画布与证据/草稿双栏。

物理页码与印刷页码分开，文件版本固定可查。选区浮条不能盖住原文；跨页片段分别显示。无文本层、OCR、损坏页、部分加载分别说明。替换文件后旧证据标版本失配，不静默重定位；缩放/旋转不改变原选区身份。

#### R03 文档大纲与定位

目的：在长文档中准确跳转。手机全屏大纲/缩略图/查找；平板为阅读器辅助栏。

区分原生书签、规则识别、模型建议；搜索显示覆盖页数，不把部分文本层检索写成全文已搜。跳转和返回原位置不重新解析。无书签、无文本层、无命中和部分页失败有不同文案；建议刷新不覆盖人工改名。

#### R04 批注列表与编辑

目的：保存用户自己的阅读判断。原文只读区、批注编辑区、标签和关联证据分层；手机编辑时铺满可用高度，键盘上方主按钮，平板右侧编辑。

高亮无正文与评论有正文都可存在；颜色外另有文字类型。模型建议不能覆盖人工正文。保存中/保存失败/未保存草稿/正式保存分别显示；冲突并列当前版与我的修改。删除批注不删除原文件或独立证据。

#### R05 证据卡与来源核验

目的：检查某项结论由什么范围的原文支持。结论、原文、版本页码、提取方式、核验状态、相反证据置于同一路径。

手机纵向，平板原文和核验表单并排。定位来源、核验通过、标记冲突、用于草稿是独立动作。读取成功不等于核验通过；摘要不等于全文；修改结论或来源使核验失效。缺原文不补造来源，不默认绿色。

#### R06 结构化提取与人工草稿

目的：把明确范围的资料变为可修正字段。先展示插件/用途/目标/页范围，再记录卡与问题汇总；平板原文和编辑表并排。

每行有稳定身份，字段含原值、规范值、单位、来源、人改标记与校验。重新提取只更新机器建议层，人改继续优先，差异逐项采纳。停止提取不丢已得行；解析结束不等于业务入库。预览保存进入 R07。

#### R07 保存预览与提交结果

目的：在提交前看清实际目标、差异及原子性，提交后核对真实效果。

必须区分 atomic 原子组与 independent 独立操作集：前者整体提交/核对，不设计组内任意行续办；后者可逐操作显示成功/失败/未知。手机卡片、平板预览表；主按钮写“提交整组”或“提交已选 N 项独立操作”。

成员变化、版本变化令旧计划失效；FullAllow 自动重新核验不加风险确认，Auto 按合同决定。双击不创建两次意图；超时未知先查原组/原操作回执。只有回执显示成功，不能由动画或提取完成决定。

#### R08 科研写作与论证大纲

目的：组织用户稿件的主张、段落和证据，与 PDF 目录分开。

手机“提纲/本节/证据”切换，编辑节全屏；平板论证树与正文/证据支持栏。保留一级至三级及稳定节点，支持程度为未评估/充分/部分/不足/反证，显示依据。引用区分研究记录、笔记、已接纳运行，不因 ID 同号混用。

新增、移动、删节、关联、移除引用、准备报告分别有影响预览。移动提供选择器，不能只拖拽；删父节先定子节处理。模型建议不覆盖人工正文。导出能力未接通则只读预览；真正导出冻结版本、来源和范围，文件成功不等于已外发。

### 8.3 询价与商业工作

#### Q01 询价项目与清单

目的：定位需求、待处理设备与报价。项目切换、需求版本、状态筛选、设备卡和新增入口；平板项目/清单双栏。

清单显示名称、数量、单位、候选数、报价数、业务阶段和最后修改。未知数量为待确认，不填零。条件到 Q02、候选到 Q03、报价到 Q04，业务阶段与任务状态分开。重名对象仍按 ID 操作；归档不丢历史回执。

#### Q02 技术条件与需求版本

目的：把需求形成可核验版本。必需、偏好、交付条件分组，原文和解释可展开；平板条件与差异并排。

字段含运算符、范围、单位、配置、来源、备注。未知必需项不标完整；用户明确修改/移除才改变条件，系统不能自动放宽。确认新版本先看增删改和受影响候选；旧结果仍关联旧版本。人改优先，单位不明先保留未知。

#### Q03 候选检索与筛选

目的：找到配置明确、来源可检查的候选。需求摘要、真实检索进度、候选卡、筛选、已选比较栏；平板条件/结果加按需证据。

显示必需通过/未知/冲突及价格是否可用，不默认隐藏无报价候选。线索数、已读来源数、失败数分别统计；摘要不能计全文已核验。检索可停止，已得成果保留；修改条件回 Q02，新版本不混用旧结论。

#### Q04 报价记录与询价草稿

目的：区分报价事实、可编辑询价和实际提交/发送。

分段为报价记录、询价草稿、动作回执；手机完整表单与正文编辑，平板字段/正文和证据支持栏。报价含型号配置、供应商、单位价格/币种、数量阶梯、税、运费、其他费、有效期、来源及时间；未知有原因。

保存草稿、写台账、发送询价是三个不同动作。发送能力尚未提供时只有编辑/显式导出，不显示可用发送。提供时显示发送身份、具体接收者、正文附件与用途；FullAllow 当前任务范围合法个人/商业外发无需追加风险批准。超时先核对，不再发一封；取消不宣称撤回已发内容。

#### Q05 候选与报价比较

目的：分开看技术符合、价格可比和缺口。手机双候选逐项比较并可切换候选对，平板冻结属性列与候选头的矩阵，证据按需打开。

必需不通过不能被偏好分数抵消；无来源参数标未知。价格显示配置、数量、币种、税运、有效期；条件不齐则不给伪精确完整总额或“最低价”。仅看差异即时响应；标首选写理由但不入账、发送或采购。试算入口到 Q06，不覆盖原报价。

#### Q06 价格试算与假设

目的：计算明确假设的预算情景。始终有“试算”语义，不能看起来是供应商正式报价。

数量/币种、税运、汇率按段展开；手机底部结果摘要可展开，平板参数和公式并排。汇率有方向、来源、适用与取得时点，人工输入标假设；税未知不作零，缺换算只给已知小计。保留逐步舍入说明。保存情景不更改源报价，页面不提供采购付款。

### 8.4 任务与真实执行

#### T01 任务列表

目的：识别需要用户处理和正在发生的工作。待你处理、进行中、已结束分组，按项目/状态/执行位置筛选；平板列表和 T02 并排。

每项显示目标、当前步骤、等待原因、运行位置、最后确认时间、部分结果/未知数。角标只数有效需要决定项，不能把每条日志做红点。未知总量不画百分比；失联不凭旧状态显示仍运行。重开/筛选不启动任务。

#### T01.1 消息中心

目的：回到有效任务和结果，不成为第二套待办数据库。待处理、结果、系统分组；每条有来源、时间、状态及深链。

已读不等于批准，删通知不删回执或取消任务；事件重放不重复未读。通知权限拒绝与空消息不同。锁屏仅最小获准摘要，敏感决定进应用可信页；撤权后消息片段与迟到通知同步失效。

#### T02 活动与执行详情

目的：看清做了什么、谁在执行、已发生何种效果、现在能做什么。

手机上部为目标与多轴摘要，下方逻辑动作时间线；点动作全屏看尝试、输入版本、来源与回执。平板列表/活动和按需支持栏。默认显示人能理解的事实，技术 ID 放展开详情。任务、尝试、模型回合、工具调用、效果回执是不同身份；逻辑动作计数不能被重试放大。

必须分别画：补事实、Auto 高风险待决定、校验失败、工程能力暂停、内容分类/复核、执行器不可用、结果核对。FullAllow 普通高风险不制造审批。取消后可能“后续已停，但此动作已成功”或“停止未确认，效果仍未知”。核对结束无证据显示仍未知；不留永动动画或自动再执行主按钮。若用户明确要求再做一次，宿主记录可信新指令并创建关联旧 unknown 的新操作，inline 提示可能重复；旧操作不因此变成功/失败，FullAllow 不另弹批准。

#### T03 动作决定与审批详情

目的：只承载当前模式确实需要用户决定的动作。全屏可信宿主页；不能由生成卡自画授权控件。来源为真实 awaiting_confirmation，FullAllow 不因高风险/新目的地进入本页。

首屏展示动作、目标/接收者、数据与用途、影响范围、模式原因、具体确认/拒绝。字段差异、正文附件、金额等按动作展开。确认绑定当下版本与有效计划，变化使旧决定失效。参数错误、能力缺失、冲突和未知效果不能由“允许”解决。

拒绝只处理该请求，保留合法草稿；系统返回不默认允许。离线旧按钮无权成为新决定；同设备其他入口在决定后同步显示最终事实。确认提交、执行中、真实成功为三个状态。

### 8.5 数据与公司资料中心

#### D01 数据模块与记录管理

目的：查看、编辑和导出真实结构化对象。手机模块/项目到记录卡到字段，平板模块/记录加详情。

显示模块版本、对象类型、字段/单位/来源、修订和引用位置。系统字段只读；schema 未知先只读保留，不丢字段。保存差异与 CAS 共用组件；停用模块不同于删除数据。生成结果和数据页链接同一 ID，不另建“AI 数据副本”。

#### D01.1 供应商目录与名称编辑

目的：完整供应商业务入口，也是第一批验证切片。首片仅合成 `supplierId/name/revision` 读取改名，不把联系人、邮件或删除塞进首片；后续完整迁移仍保留原字段。

手机列表到详情再全屏编辑；平板列表和详情。编辑建立稳定意图；输入只改草稿，预览 Rust 返回差异/计划，保存直达 Rust。FullAllow 合法自动，Auto 按风险规则；无模型回合。冲突并列当前保存版与我的修改，不能换成最新 revision 覆盖。双击/恢复用原操作核对一次效果，返回同一 ID。

#### D01.2 物料目录与详情

目的：维护物料身份、型号配置、规格单位与业务关联，不等同项目清单项或报价。

手机字段分组和关联卡，平板列表/规格。未知不补事实，同型号不同配置不合并；编辑不改历史报价，停用不删历史引用。扩展字段尚未映射则只读保留。导出明确选中对象、版本和单位；比较/试算仍回 Q05/Q06。

#### D01.3 公司资料中心 Hub

目的：保留 B02 Hub 的完整业务价值，包括公司部署的可选远端服务、同事共享的供应商与历史报价查询、自己的发布和原操作核对。它不是只维护公司名称的静态表单，也不是全应用同步中心。

手机主页至少包含四个命名区：服务状态、查询资料、我的发布、历史与核对；平板左侧查询/发布列表，右侧详情或预览。连接配置归 S03，Hub 页给状态和可达入口，不能把密码放普通业务表单。

必画六条能力：

1. status：公司服务、当前账号脱敏标识、连通/身份/能力状态、最后核验时间；离线显示旧状态，不假称刚联网
2. search：同事/供应商及报价查询；来源属于谁、发布时间、配置/币种/税运/有效期和版本清楚；缓存与远端结果区分
3. history：本人发布历史与可追溯记录；历史不是当前全部资料，旧回执不被新搜索覆盖
4. preview：冻结选中发布集合、对象版本、目标、用途和载荷；预览字段由核心投影，联系人等实际包含范围明确
5. publish：发布进入受控远端业务命令，按模式执行；响应成功要有真实回执，不能因预览或上传动画完成而变绿
6. reconcile：已派发超时显示结果未知，按原 publication/operation 查询；核对本身不创建新发布意图，不盲重发；用户明确要求再做一次时才能走关联旧 unknown 的新操作路径

联系人默认不带属于既有序列化行为，要标“旧行为待迁移映射”；不能把它扩大成 FullAllow 永久禁止商业或个人数据外发。最新产品规则按实际任务范围、可信分类及专用认证通道投影。普通商业报价可以在合法 FullAllow 范围默认外发；credential 无论藏在备注还是附件都不能当业务正文发送。

空搜索、无发布、身份失效、远端不可达、部分条目不可读、预览过期、发布未知必须不同。用户看到的是哪个公司服务和哪些真实资料，不是无对象的云图标。保留本机业务可用性；没有 Hub 配置不阻断本地询价。

### 8.6 设置 记忆与身份

#### S01 设置首页 外观与无障碍

目的：提供稳定的非对话控制。模型与执行、连接、权限、数据、记忆、身份、外观、通知、关于分组；手机列表，平板目录/详情。

外观提供跟随系统/浅色/深色、大字体预览、减少动效、发送键、通知预览等真实能力。恢复默认仅作用于列明的外观，不清文件/记忆/权限/身份。失败保留有效旧值；系统权限拒绝给系统设置入口，不反复弹窗。

#### S01.1 界面与可视化呈现策略

目的：保留“自动、少用、只用文字”的呈现三档，与授权 Auto 严格分开。

三项单选加固定示例；手机纵向、平板预览并排。少用仅在可信明确展示请求时规划；只用文字抑制可选动态呈现，固定业务页面、必要审批/错误/回执仍存在。保存成功才更新有效值；旧请求的显示标志不能跨切档充当新授权。

#### S02 模型与执行位置

目的：看清模型、实际端点和何种数据离开设备。当前模型、位置、能力、账号类型、凭据配置状态、上次连接测试在前；配置详情按本地/远端分开。

连接测试展示最小测试内容，不带默认项目。远端失败不静默换服务商；本地模型未安装不假设离线生成。默认变化用于新请求；在途影响另说明。安全凭据仅掩码/引用，不能进入聊天、普通 payload 或诊断。

#### S03 连接器详情与接入

目的：连接明确的数据服务和业务端点。介绍、域名、账号、可读可写能力、资源范围、连接状态与依赖任务；Hub 公司服务配置在此可达。

认证通过专用安全流程。选单文件不等于整盘；新增能力与换账号不能静默沿用旧授权。取消认证不显示连接成功。断开解释后续访问与在途影响，不称删除远端数据或撤回已发内容。

#### S03.1 MCP 服务配置与运行状态

目的：正确表达 StreamableHTTP 客户端与独立只读 MCP 服务的不同角色。

显示传输、端点、认证引用、协议/工具版本、能力范围、握手时间和错误阶段。添加/测试/发现工具/停用为独立动作；新工具不自授权限。Android 不能启动桌面程序不等于 HTTP 客户端不能迁移。未来新增 stdio 适配或 Android 服务端能力未定就不画假启动；既有独立只读 MCP 服务按实际平台兼容范围保留。诊断只用掩码，重连不重放旧工具。

#### S04 权限与数据使用记录

目的：让当前模式、范围与外发规则可理解、可检查。模式与工作区在前，四类操作 read/model request/write/outbound、范围/期限/目的地和使用记录分区。

必须有易读的 FullAllow 说明：任务范围内、现有访问权内个人/商业外发默认允许，包含新目的地；高风险无额外 Muyon 询问；访问权、撤权、credential 专用通道、可信分类、参数与业务约束仍有效。说明残余提示注入风险是模式解释，不是每动作追加确认。

Auto 高风险需具体决定；呈现策略“自动”不在此冒充 Auto。四档为只读、每次询问、Auto、FullAllow，首次默认 Auto，低风险合并进 Auto；旧三档规则逐字段迁移不得扩大权限。`unreviewed` 显示等待可信分类和实际阶段；完成后按既定规则放行，不出现“分类已通过，请再批准”。撤权清当前受限投影与待发上下文，已发送内容不能假称已撤回。

#### S05 本地数据 存储与导出

目的：区分原始文件、草稿、索引、缓存、结果和日志，管理导出与恢复。

占用必须实测，未知标未知；清缓存列出失去的离线能力，不能删唯一原件。询价 .siq 交换与整应用备份分区，不承诺包含所有任务/设置。合并导入与替换资料不同；恢复先预览版本、重复/冲突、范围与遗忘保全，再验证激活。

导出成功以文件和回执校验；已有显式新副本路径单列影响，不覆盖原件，不泛化远端重发。恢复不能重建密钥、放宽权限或复活遗忘；备份中的在途任务先历史/未核对，不立即重跑。失败保留原件与清单，容量不足给准确下一步。

#### S05.1 设备消息与研究资料交换

目的：保留两个有联系但不同的区域：设备消息/附件传送，以及研究说明与人工研究结果交接。不能简写为远程 agent，也不能写接受后自动研究。

手机设备列表到通信详情；平板设备/消息双栏。对端设备身份、配对状态、最近可达时间、消息和附件状态清楚；发送、送达、附件收妥、已读独立，不以已读证明文件已导入。

研究交接流程必须画全：收到研究说明 offer → 用户明确接受责任/所有权 → 用户另行发起授权导入研究说明 → 用户在本地科研页面开展工作 → 用户提交人工工作结果包 → 原任务端按任务身份、版本和范围校验后导入，导入结果仍待人工评估，不自动成为已接纳研究证据。接受本身不启动模型，不承诺对端一直在线，也不授权接收者的新工具动作。

至少独立显示 offer/接纳、说明导入、人工工作、结果发送、原任务接纳/导入。任务过期、目标改版、附件缺失、身份不匹配与重复包可解释；未知远端收妥先查询/核对，不重复业务导入。撤配对不删已独立保存且仍获准的业务对象；不自动同步模式、审批或长期记忆。

#### S06 记忆 经验与整理

目的：让用户看见、编辑并限制助手持久使用的信息。顶部概览，下设记忆、经验、整理三片区；手机列表/详情，平板列表/来源编辑。

必须分开：关于用户的事实/偏好、经验 candidate/verified/retired、用户发起整理运行/提案。每条包含正文、核实与推断、来源、范围/用途、版本、到期/停用/删除状态和使用位置。单条编辑是确定性本地补丁，不为手动改字强制联网模型。

四控制目标合同为读取记忆、自动写记忆、助手跨会话历史检索、聊天留存；四者独立。当前已有手工记忆/筛选注入、用户发起整理和聊天保存；自动提取器、独立跨会话检索及可选留存开关不是基线已交付。自动对话记忆提取与跨会话助手历史检索已批准新增，首次均默认关闭、分别开关，设计必须同时给“交付后关闭/启用/暂停/失败”和“当前尚未提供”两组形态，不能永久画成不可用。二者按来源、用途、版本和墓碑过滤，独立排期、不挡 Rust 首片。可选留存控制按独立合同设计，不能把当前聊天说成不保存。内部每会话写入标志不是第五个页面开关，也不等于临时会话。

整理先选离线确定性或模型辅助，显示范围与目的地；产出提案不等于应用或核实。提案应用走版本/来源/用途验证；人改后回滚不能覆盖。停用排除使用但不等于失权清空；彻底遗忘分“已阻止后续使用”和“可控副本清理进度”，包括派生摘要、整理快照、索引等，不说清空列表就已完全擦除。

#### S07 助手身份

目的：独立管理助手称呼、头像和表达方式，采用 Muse identity/soul 的分域启发，但为 Muyon 原创表单。

手机预览/字段/样例纵向，平板编辑与预览并排。名称、头像、语气选项、自由风格说明、语言/生效范围、保存状态；不混入用户事实、账号认证或权限模式。

固定样例必须标示例，离线即时，不读真实聊天/记忆/项目，不调用工具。若以后提供模型新预览，要单独披露目的地和内容。保存后用于后续回答；历史消息和在途响应不混用新旧身份。styleText 实际用于模型时属于披露内容，不假称永不外发。

风格文本不能授予 FullAllow、读取新资料或跳过约束。输入“全部替我允许”仅提示到 S04，不自动改授权。保存失败/冲突保留草稿；只有配置持久回执显示已保存。更名不改任务、会话、记忆或业务对象 ID。

## 9 全局分轴状态与恢复文案

### 9.1 不合并成一个颜色的状态轴

下表是设计读模型，不另建一套权威枚举或账本；具体编码沿两册单一 schema。各轴独立，不能把停止、摘要、连接状态塞进同一个任务字段。

| 轴 | 代表状态 | 用户要看见什么 | 合法下一步 |
| --- | --- | --- | --- |
| 页面取数 | loading / ready / empty / error | 正在载入、真空集合或具体读取失败 | 保留可读缓存/草稿；重载只重取数据 |
| 连接与新鲜度 | connected / reconnecting / offline / disconnected | 执行位置、最后确认时间、缓存标记 | 重连/查核；不能据断网猜失败或继续运行 |
| 任务/尝试 | queued / running / waiting / succeeded / failed / cancelled | 目标、当前尝试、部分结果、等待原因 | 输入、查看结果、合法续办或请求取消 |
| 权限/校验 | allowed / denied / validation_failed / stale / revoked | 缺哪项前提、影响哪个范围 | 改字段、看差异、合法接入；禁止用确认覆盖缺失事实 |
| 取消请求 | none / requested / executor_stopped / stop_unconfirmed | 请求受理、后续是否已停分别显示 | 等停止证据或核对；不声称撤回已发生效果 |
| 执行阶段 | queued / prepared / authorized / dispatching / running / stopped / completed | 当前到哪一步；completed 不自动等于成功 | 按实际阶段判断取消与核对；不能用阶段代替效果 |
| 外部效果 | none / succeeded / failed / outcome_unknown | 哪个原操作产生了什么证据 | unknown 查原操作；用户新指令重做另建关联操作 |
| 摘要生成 | absent / pending / ready / failed / stale | 事实先显示、摘要可迟到/失败 | 查看真实动作与回执，不影响业务终态 |
| 内容可用性 | current / historical / partial / expired / revoked / unavailable | 哪部分可读、哪个版本、覆盖到哪里 | 看允许历史、补资料、重核；无权内容不回填 |
| 上下文压缩 | preparing / running / ready / failed / invalidated | 压缩本身的状态和未送达输入 | 保留合法原历史/输入；不能自动升级长期记忆 |
| 可信分类与复核 | unreviewed / classifying / classified，复核另有结果 | 当前是否具备可信分类、理由类型 | 分类未完成禁派发；完成按模式放行，不多加审批 |
| 工程能力 | available / unavailable / capability_hold | 哪个能力及版本被暂停、为什么 | 仅合法替代或修复发布后解除，不接受用户“允许”清除 |
| 记忆与清理 | active / disabled / expired / recoverable / forgetting / forgotten | 可使用状态与可控副本清理独立 | 管理、核实、查进度；不能以列表消失证明完全遗忘 |

### 9.2 必须绘制的组合

- 已保存名称 + 历史部分缺失：保存仍成功，历史缺口可修复
- 停止后续工作已确认 + 某已派发效果未知：不能把整组涂成已取消
- 任务已完成 + 生成摘要失败：结果正常，摘要可查看失败原因
- 本地草稿可编辑 + 模型离线不可用：保留手工工作，不锁死整个页面
- 来源已撤权 + 用户仍有另一独立对象的管理权：只保留当前允许部分，不能无差别清空或泄漏源文
- 旧比较可读 + 新需求已更新：历史标记清楚，当前提交必须重核
- FullAllow + unreviewed：暂禁派发，可信分类完成后按有效合同推进，无额外风险批准
- FullAllow + 新网站目的地 + 普通个人/商业资料 + 当前任务范围：校验通过可执行，不弹逐站点确认
- 两个并发动作一成功一未知：摘要“已完成 1 项，1 项待核对”，不能只写完成
- 旧 unknown + 用户明确新操作：两条关联记录并存，新操作成功不能改变旧 unknown 的事实

### 9.3 unknown 与用户明确再做一次

默认主操作为“核对结果”，使用原 action/operation/publication 身份查询，不改变载荷或目标后偷重试。核对没有证据后显示“仍无法确认 · 最后核对时间”，不把没有找到写成未执行。

用户明确表示“再做一次”时，可提供清楚标识的“创建新的同类操作”流程。宿主需捕获这条可信用户指令，关联旧 unknown 引用及内容版本；模型自己提出重试、页面恢复或重连不够。交互注释沿主册使用宿主铸造的 acknowledged_unknown_ref，绑定 user_instruction_ref、原 unknown/current-display 版本、scope/action、目标参数与新 intent/plan；它不是授权 token，不能由模型或卡片正文生成。就地提示示例：“旧操作的结果仍无法确认。新操作可能造成重复；两次操作会分别记录。”这不是 FullAllow 的额外批准弹窗；其他模式仍按本身合同执行。

新操作拥有新 intent/operation，保留关联，不能伪装“恢复旧操作”；新成功不会让旧记录自动变成失败。若实际目标/内容已变化，展示新范围和差异。必须仍遵守读权、credential、可信分类、CAS 等硬条件。

本机导出的既有显式新副本路径另外注明新保存目标、同一冻结内容、新 exportId 与新 A/B 阶段引用；不得以改文件名类比远端发布就是安全续办。设计稿要给这两种路径独立注释。

### 9.4 压缩 进程重建与备份恢复

压缩、重新订阅、恢复界面、恢复模型回合、恢复业务执行是不同动作。重开会话先显示“缓存 · 正在核对”，不自动重发消息/模型/工具。旧摘要、旧连接回调不能覆盖新状态或撤权后的内容。

未发送草稿与已提交发送身份独立保存；是否跨进程保留正文依实际留存策略，不无条件承诺崩溃后恢复所有输入。压缩期间输入和光标不被替换；失败保留仍获准内容。压缩摘要不能自动变成已核实长期记忆。

恢复旧备份先保全当前遗忘、停用/撤权和真实业务回执，再验证候选数据后激活。界面给进度阶段和失败原因，不能只画百分比。恢复成功不恢复旧权限、不重建密钥、不重派备份中的 prepared 操作，也不复活已遗忘派生内容。

## 10 权限 数据范围与新增记忆能力的交互细则

### 10.1 四档模式

| 模式 | 目标语义 | 设计注意 |
| --- | --- | --- |
| 只读 | 允许有效读取与相应获准模型处理；禁止实际业务写入/外发动作 | 允许形成草稿/预览；模型请求也可能外发，不写“所有数据不出设备” |
| 每次询问 | 对其合同要求的受控动作展示明确对象与用途再决定 | 不把筛选/折叠等纯 UI 动作做成审批；读取/模型等维度按合同标注 |
| Auto | 低风险按确定性规则自动，高风险具体确认，禁止动作拒绝 | 首次默认；和 S01.1 呈现策略“自动”分开命名及说明 |
| FullAllow 全部允许 | 工作区、现有访问权、任务范围内自动执行，包含普通个人/商业外发和新目的地 | 不按风险追加询问；可信硬条件仍检查，不能隐藏风险说明 |

低风险不再是第五档。旧 standard/readOnly/custom、grant 期限与范围不得因迁移自动扩大；保留兼容解释和迁移差异，默认 Auto 不等于把所有旧用户自动升级授权。模式选择只影响明确范围及后续派发，不抹去既有回执、不解除工程暂停、不重发 unknown。

### 10.2 必须可见的数据分类

- 普通个人资料：显示任务使用目的及真实接收方；FullAllow 合法范围默认允许
- 商业敏感资料：如报价、需求和业务条件，显示实际范围与目的地；不能因“商业”标签全局禁止 FullAllow 外发
- 凭据：仅专用认证通道使用，普通模型/业务载荷排除；误嵌在备注或附件时不能靠更名降级为普通数据
- 未可信分类：禁派发并显示分类阶段或无法分类原因；可信完成后按模式处理，不默认为永远禁用或要求额外批准

同页同时有模型目的地与业务接收方时分别显示。审查的风险意见与可信硬约束分开；suggested risk 不得偷偷把 FullAllow 改成 Auto。外部文档的指令、模型自评和插件描述不能自授范围或可信分类。

### 10.3 自动记忆与跨会话检索

这两项已纳入改造，但不是产品基线已实现。设计组件要能表示“当前版本未提供”以及交付后的正常开关、运行、等待、失败和禁用，不能永久停留在占位状态。

首次均默认关闭，独立开关，启用一项不能开启另一项或改变聊天留存。自动提取形成有来源/用途/版本的候选或提案，不因模型输出就成为 verified。关闭后在提交点阻止在途自动写入，重开不自动批准旧候选。手工编辑与用户主动发起整理保留，不因关自动而消失。

跨会话历史检索启用后仅在有效范围和读权内检索；展示本次实际使用的会话来源，可到 A03 检查。关闭不删除用户手动可浏览的聊天，也不关闭当前会话正常上下文。删除源内容、撤权与墓碑约束在检索和注入时立即生效，不能等索引后台物理清除。

两项独立排期；第一批供应商名称 Rust 切片不以它们完成为前置。容量、临时会话与留存期限不因新增这两项而自动确定。

### 13.1 内容与信息架构

- 29 主页面与 9 子页都有规格/画板映射，页码未错置；D01.3 完整保留 Hub，S05.1 完整保留两区

- 现有聊天保存、手工记忆/整理与已批准新增自动提取/跨会话检索清楚区分

### 13.2 正确性与受控动作

- 纯筛选无模型调用概念；业务按钮直达 Rust 合同；模型不自授能力或成功状态
- 四档为只读/每次询问/Auto/FullAllow，默认 Auto；旧配置不扩权；呈现三档独立
- FullAllow 新目的地、普通个人/商业、高风险合法任务无额外风险确认；credential 不进普通载荷，unreviewed 完成可信分类后不加批准
- 参数/CAS/读取撤权/工程暂停不能靠确认绕过；审批只出现在真正需要决定处
- 原子组不被 UI 拆成独立逐行写；草稿/预览/提交/回执不混同
- unknown 默认只核对；用户明确新指令创建关联新操作、inline 提示可能重复，旧 unknown 保留；自动重连/模型重试不满足
- Hub 没把预览成功当发布成功，reconcile 未找到不能写确定未执行
- S05.1 接受/导入研究说明不自动运行研究，人工结果导入仍核版本

### 13.3 恢复与数据生命周期

- 离线、loading、empty、error、unknown、revoked、stale、cancelled、compaction、recovery 均有可演示状态；不同轴能组合
- 取消请求、执行器停止、外部效果分开；部分成功与迟到回执不消失
- 进程/配置重建不重发意图，摘要或历史缺口不改真实成功
- 人工修改在刷新、提取和冲突后保留；合法草稿恢复受真实留存政策约束
- 记忆自动提取/历史检索首次默认关、各自开关、源用途版本墓碑校验；关闭后在途自动写入不能换成待批准绕过
- 遗忘与恢复不复活派生内容，通知/搜索/摘要/导出使用当前读取投影；第三方副本不承诺绝对擦除

## 16 可直接交给设计代理的开工说明

请按本简报设计 Muyon Android 手机和平板应用。先交信息架构、视觉基线、组件库和第 11 节批次一完整可点击路径，再扩展科研、询价、Hub 和设备研究交接。保留 29 主页面与 9 子页的 ID，不把工作台业务删成聊天附件。
