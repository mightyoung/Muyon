# Muyon：Perplexity 借鉴改进项 v1.0

日期：2026-10-22，北京时间。执行位置：云端。性质：改进规格与任务拆分，未写代码、未创建 Issue/PR、未启动实验或真实请求。

## 一、目标与证据边界

目标不是把 Muyon 变成 Perplexity 的外观复制品，而是让现有本地科研能力形成可解释、可定位、可恢复的信息工作流：**问题与材料 → 实际处理过程 → 回答 → 证据 → 项目沉淀**。

Muyon 基线：[PR100](https://github.com/mightyoung/Muyon/pull/100)，提交 **f4781e16ddf4e542b983fbd77f266a0071148255**。已核有 Kotlin→Service→UniFFI→Rust→SQLite、本地科研项目/PDF附件/快照、OCR/embedding/带页码与来源身份的索引、持久任务及回执。这些不是本次从零新建的内容。当前真实 provider 费用证明仍阻断；产品 CI 不等于当前设备验收。

Perplexity 借鉴来源为用户提供 APK 的静态报告：2.101.0（260665），SHA-256 **643142eb02102f466c5b8e051e78ae006a5675c969dab56ae9ff1d2fcb3be86f**。附件状态、搜索步骤、MarkdownCitations、Ask 等结构属于静态证据；不证明实际 UI 布局、账号权益、后端算法或功能启用。未运行该包，未确认官方发行证书归属。

现状用词：
- **已证实已有**：复用，先补特征测试，不另造一套。
- **明确缺口**：本轮已有证据能指出，如生产费用证明未接入。
- **待核差距**：目前没有足够证据证明端到端完整。不能改写成“完全没有”。实施前先核已有接口与测试，存在则接线/补验收，缺失才实现。

UI v0.2 的五张图是展示规范，不是生产功能清单。不得照图开放 Word、拍照、连接器或网络能力；来源可定位也不等于主张已被证实。

## 二、共同架构约束

1. 数据层保留稳定对象 ID、项目/会话归属、文档版本和操作身份。优先沿用已有类型与存储，不并行创建第二个任务台账或第二套 PDF 索引。
2. 宿主/Service 是权限、实际状态、成本和回执的权威；模型文字不能制造“已完成”“已核实”或可执行审批。
3. Compose 只投影真实状态。统一 EvidenceCard、TaskSummaryCard、ReceiptCard 等组件；不把整张生成图切成按钮贴入应用。
4. unknown 独立于失败：写操作结果未知时先查回执，不自动重试；预占与实际费用分开，未知不能显示0元。
5. 所有新增视图都要有无数据、失败、部分成功、取消/恢复和长文本状态；重大错误不能只出现短暂 toast。
6. 本批不新增系统权限、账户连接、第三方写权限、后台持续收集或真实付费调用。不改 Kotlin/Rust/Electron 既定路线。

## 三、10 项改进规格

### PX-01｜附件处理生命周期可见化〔P0〕

**现状/差距**：已证实有私有 PDF 附件、OCR 和索引；“保存→解析→索引”的持久状态是否在所有入口一致展示尚待核，不是缺少 PDF 功能。

**借鉴证据**：Perplexity AttachmentState 区分 localFile/remoteFile/uploading/uploaded，且有附件 chip 与汇总。

**改动**：
- 数据：为已有附件处理记录补齐或复用阶段、尝试 ID、已处理页范围、失败原因、处理器/模型版本。页面数未知须可表示未知。
- 宿主：只根据真实处理结果推进状态；重新进入时恢复状态，重复回调不重复计数/入库；重试只处理符合条件的失败阶段。
- Compose：附件条展开显示“已保存、提取中、已提取、索引中、可检索、部分失败”，不把已保存标成已读全文。

**验收**：正常 PDF 能从原始回执复核各阶段；混有失败页时显示成功页范围及失败页；中断重启后不回到假成功；重复完成事件不重复索引；不支持格式保留草稿且明确拒绝。

**依赖/边界**：复用当前附件/索引与回执；与 PX-02 可并行。首批仅现有支持类型，不借此新增 Word/相机能力。

### PX-02｜主张—证据—原文定位链路〔P0〕

**现状/差距**：已证实索引具有页码、来源及修订身份过滤；尚不能据此认定每条聊天引用都完整绑定原文与版本。

**借鉴证据**：MarkdownCitations、CitationAttribution、单条/分组引用点击以及失效引用错误路径。

**改动**：
- 数据：把回答块/主张 ID 与现有来源 ID、文档版本/hash、页码和片段定位关联。片段范围沿用现有定位格式，不另造不兼容坐标。
- 宿主：打开引用前核身份与访问权；文档更新、删除或引用不存在时返回明确状态；不静默跳到最新同名文件。
- Compose：点击编号先见证据片段，再进入对应 PDF 页；返回保留原对话锚点。原文可定位和主张待核分别标识。

**验收**：正确编号进入正确文件版本/页码；同名不同文件不串引；来源被删或版本变化明确提示；伪造 source ID 不被打开；来源存在但不支持结论时仍为待核，不显示“事实已验证”。

**依赖/边界**：复用当前索引、PDF查看和权限边界；先做固定本地样例，不依赖在线模型。为 PX-04/06/08 提供身份基线。

### PX-03｜真实过程事件与任务状态统一〔P0〕

**现状/差距**：已有持久 root/child 任务、取消恢复保护和回执。待核的是解析/检索/生成步骤能否在聊天、任务页一致呈现；不是重建 Agent 调度器。

**借鉴证据**：SearchResultsStep(uuid, goalId, webResults)、SearchResultsReceived 及按工具区分的进度文案。

**改动**：
- 数据：在既有任务身份上关联步骤、事件序号、阶段、关联附件/来源与结果。区分排队、执行、等确认、取消中、已取消、失败、完成、待核对。
- 宿主：规定事件去重与乱序处理；晚到事件不能覆盖更新终态。显示计数必须来自已记录事实，未知总量不显示百分比。
- Compose：摘要卡可展开实际步骤；停止生成与取消业务任务分开，展示查询/资料范围，不展示私有内部推理。

**验收**：重复/乱序事件不使进度倒退；退出再入状态一致；取消中不会瞬间冒报取消完成；部分失败可展开；unknown 请求不会获得一键重试；终态与持久回执相符。

**依赖/边界**：沿用既有任务协议；与 PX-01 对齐阶段名。属于原 Agent 任务的可观测性补强，不扩并行层数或调用额度。

### PX-04｜回答正文、引用来源与检索结果分层〔P0〕

**现状/差距**：已有聊天、任务结果与本地语义检索；“被引用来源”与“全部检索候选”是否完整区分待核。

**借鉴证据**：Ask 同时保存 resultMarkdown、webResults、markdownCitations、structuredAnswerBlocks、workflowResearchReport；citedWebResults 不等于 webResults。

**改动**：
- 数据：复用现有结果容器，明确正文块、实际引用集合、候选来源集合及产物引用；不把模型任意 JSON 当可执行组件。
- 宿主：去重来源身份并验证引用关系；模型请求不支持的块类型安全降级为普通文本/不可展示提示，不能映射成工具动作。
- Compose：先读回答，再展开“本回答引用”“其他检索结果”。有结果但无支持证据时明确“尚无可核对引用”。

**验收**：检索10条、引用2条时两集合不混；一源多处引用不会伪增独立来源数；表格/卡片异常不吞正文；流式新增引用不使已有编号指向另一来源；Markdown伪造审批按钮无执行能力。

**依赖/边界**：依赖 PX-02；复用 v0.2 对话/证据板，不要求新增所有复杂 widgets。首批只本地来源。

### PX-05｜资料范围选择与追问上下文可见〔P1，本地部分可提前〕

**现状/差距**：已有项目与来源身份过滤；用户是否能清晰看见本次/追问使用范围待核。

**借鉴证据**：source 与 mode 选择资源、relatedQueries、parent_info 与 collection_info。

**改动**：数据保存明确项目/材料选择快照与范围版本；宿主按选定范围检索，不以 UI 筛选代替授权；Compose 在输入区显示“当前项目/选定材料”，追问默认继承并可显式调整。公开网络入口仅在 PX-10 通过后启用。

**验收**：切项目时旧范围不会无声沿用；追问显示实际继承范围；删除/失权资料不会仍被检索；“当前项目”不会命中其他项目私有附件；切范围不视为同意外发。

**依赖/边界**：与 PX-01/02 共享来源身份；不新增跨项目读取权或默认全库检索。

### PX-06｜可解释的来源详情与证据等级〔P1〕

**现状/差距**：已有来源/修订信息，v0.2有证据卡设计；完整作者、时间、证据类别、核验状态的生产展示尚待核。

**借鉴证据**：来源分组、trust_level/trust_type 及详情入口。没有证据能证明竞品评分算法，应借鉴可解释入口而非复制信任分数。

**改动**：数据分开资料元信息、阅读/代码/实验核验程度、主张支持状态；未知字段保留未知，并记录是谁何时作出的判断。宿主不根据域名自动升为“已证实”。Compose 来源卡支持标题、页码、版本、证据类别与访问状态，详情解释判断来源。

**验收**：官方网页仍可有未证实主张；AI推断不变成人工真值；元数据缺日期不填当前日；来源标签改变不自动改历史报告判断；同源转载不冒充独立佐证。

**依赖/边界**：依赖 PX-02/04；首次以人工选择/既有可信元信息为准，不另做无人审核可信度模型。

### PX-07｜草稿、附件与建议追问分离〔P1〕

**现状/差距**：已有输入与资料功能；统一草稿中的附件关联、恢复及建议追问行为需要逐入口盘点。

**借鉴证据**：attachment chip/summary、relatedQueries/pendingFollowups、输入来源入口。

**改动**：数据保留当前草稿与附件关联；宿主区分“移除草稿引用”和“删除资料”；Compose 展示可移除附件 chip、可编辑建议追问，点击建议先进入草稿或明确发送行为，不能暗中开始付费任务。

**验收**：移除 chip 不删除原PDF；切页/重启按既有草稿规则恢复；导入失败不丢问题文本；连点建议不多次发送；附件未解析时提示可用范围而非声称已全文阅读。

**依赖/边界**：依赖 PX-01/05；无新增录音、拍照、系统助手或后台监听权限。

### PX-08｜证据、会话与报告按版本归档〔P1〕

**现状/差距**：已有科研项目、快照与持久回执；不能等同已具备“从回答存证据、报告版本关系、历史判断保留”的完整产品流程。

**借鉴证据**：collectionInfo、bookmark_state、Projects 对文件/指令/任务的组织。

**改动**：数据在现有项目/快照机制上建立证据、报告版本和来源快照的关联，追加新版本，不静默覆写；宿主保存遵守当前写权限/CAS与回执；Compose 将“收藏证据”“保存报告版本”与普通会话收藏区分，展示实际保存结果。

**验收**：重复保存不多写；用户编辑冲突不被覆盖；新报告引用固定来源版本；删除源后历史版本明确缺失；保存unknown先查回执，不能再次写入；预览未执行不显示已保存。

**依赖/边界**：依赖 PX-02/04/06；复用已有快照/原子写/删除设计，不建第二个研究库。

### PX-09｜错误、unknown、隐私边界统一表达〔P0约束，P1全入口补齐〕

**现状/差距**：已有权限和unknown保护；UI规范提出独立未知状态，但尚未完成全入口实现验收。

**借鉴证据**：引用失败路径、附件错误与隐私相关资源提醒我们必须分层解释，不能以竞品文案承诺零留存。

**改动**：数据分别表达确认未执行、确定失败、结果未知、部分完成，以及预占/实际费用；宿主决定可否重试与是否要重新确认；Compose unknown用持续卡片提示查回执，失败仅在已确定无副作用或幂等保证时给重试。历史可见性、保存、模型改进与外发说明分开，不笼统称“隐私模式”。

**验收**：网络超时后写入结果未知不出现危险重试；预占0.002620与实际未知可同时展示；未配置外部服务不会显示已上传；取消界面不暗含撤销外部副作用；关历史不承诺服务端零保留。

**依赖/边界**：为所有PX任务的共同验收约束；不因此新增隐私设置或更改账户配置。保留原两次真实请求unknown，不重新调用。

### PX-10｜网络资料与本地资料边界及费用披露〔P1后置〕

**现状/差距**：明确缺口是生产FFI价格验证器仍传None、远程调用门禁未闭合。资料范围UI不能代替费用证明和真实授权。

**借鉴证据**：来源/模式选择、read/write权限区分、按需检索与同步的不同文案。

**改动**：沿原费用证明任务，数据记录provider/model/价格版本、预算、将外发材料范围及回执；宿主在发送前核对权限、价格有效性和预算，变更材料/目标使原确认失效；Compose 清晰显示本地处理与将外发动作，网络/学术来源未就绪时禁用并解释，不用虚构搜索结果占位。

**验收**：离线反例覆盖缺价格、过期价格、模型不匹配、超预算、材料范围变化与重复确认；本地问答不产生网络请求。真实验收须另行明确服务、预算、次数、停止条件，结果与费用可核对后才启用网络入口。

**依赖/边界**：复用原待做6、7，不另造费用系统；本次不连接新账号/配置凭据，不做定时抓取或第三方写操作。

## 四、建议最小第一批

**第一批仅做一个本地闭环：导入既有支持的PDF → 看真实处理状态 → 本地检索 → 阅读结果 → 点击原文页 → 查看失败/unknown。**

纳入 PX-01、PX-02、PX-03、PX-04，并将 PX-09 的unknown/重试规则作为强制测试。先做离线固定样例与生产入口连线，不依赖远程模型，也不把设计稿中的示例能力同时上线。

实施前置检查：
- [ ] 按f478基线盘点这些链路现有实现和测试，逐项写“复用、接线、补测、新增”，减少重复开发。
- [ ] 修正当前候选证据索引，承认 PR99设备失败和当前模型重验要求；本清单不能解除HOLD。
- [ ] 固定已有附件、来源、任务、回执的接口与唯一权威，先补失败测试，再做最小实现。

建议并行：PX-01附件状态、PX-02引用身份可以在各自隔离分支推进；PX-03与PX-01先约定阶段/事件字段；PX-04等待PX-02接口稳定。共用数据契约只能有一份，不能各自命名后再拼接。

第一批完成判据：
- [ ] 所有引用点击能定位正确版本；缺失/失权/变化场景明确降级。
- [ ] 附件各阶段和任务终态与实际事件/持久记录一致，中断恢复后仍成立。
- [ ] 引用来源与候选检索来源分开，重复/同源不虚增支持度。
- [ ] 不支持入口不可用；无网络调用；unknown不自动重试；无假百分比、假保存、假“已证实”。
- [ ] 当前精确提交与当前模型的设备测试、独立复审和必要依赖通过；由唯一合入者裁定develop集成。

这不是对每项工期或完成比例的估算，也没有自动启动任务。
