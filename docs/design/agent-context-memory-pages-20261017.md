## 1. 对话中的压缩边界

默认显示低打扰状态行：“正在整理本次任务上下文”“上下文已整理”“整理失败，保留原上下文”。
第三条只在旧上下文仍合法且已实际保留时显示；已撤权或超预算时显示“上下文暂不可继续”及真实原因。
未提供能力时不显示假成功、节省 token 或装饰性进度百分比。token 统计区分估计与服务端实际值，不显示无依据节约成本。

展开明细：压缩范围、版本、主线摘要、有效补充记录数、原始记录可查询性、缺口、最近核验时间。
不展示软 token 可读解释为真实解码；可选后端尚未开放时不提供可点击开关。
本节新增的上下文压缩摘要正文仅可查看、复制获准文本、导航来源或发起新请求，不直接触发业务工具。既有执行摘要卡的已注册业务按钮仍按 plan_ref 经 Rust 校验直接执行，遵循当前授权模式，不额外强制模型回合；结果未知的再发限制仍按原合同。

## 2. 三类补充记录

失败观察显示：尝试对象、结果类别、发生条件、工具版本、证据与“何种变化后可重新评估”。不要使用“永远不要重试”文案。
决定替代显示：新旧决定、用户来源、替代范围及仍生效部分；不能把模型提议画成用户已同意。
证据关联显示：来源名称、版本、核验范围、unknown/conflict 标识。缺失来源显示缺口，不用成功颜色填补。
这些是任务上下文视图，不自动变成永久个人记忆；不添加临时会话页面或改变已定留存语义。

## 3. 执行详情与结果未知

摘要卡“完成”须来自真实执行回执投影。超时、停止、撤权与结果未知分别表达；未知记录不能因压缩从任务详情消失。
保留核对入口；入口动作按既有能力和授权运行。缺少查询能力时如实显示。
重新发起沿既有 unknown 新意图合同关联旧记录；不通过摘要卡新增一键重发副作用。
真实迟到回执到达后刷新事实视图，并说明状态更新时间；不得用旧摘要覆盖它。

## 4. S06 与遗忘状态

展示对象来源、用途及任务范围；来源被删除/撤权后提示相关派生视图已失效或等待重建。
“已遗忘”仅在既有删除与派生失效核验条件满足时出现；异步处理中显示真实未完成范围。
不让用户直接编辑原始执行回执。可编辑的偏好/记忆继续走原有 CAS；纠正决定通过新的来源记录表达，不覆盖审计历史。
关闭记忆、检索与保留控制沿既有合同，不新增隐形读取/写入路径。

## 5. Android 与桌面一致性

Android 使用状态行及详情页/底部明细，Electron 使用同一语义投影；两端不自行推算执行成功。
无障碍标签包含状态和原因，不能只靠颜色。窄屏折叠详细来源，但未知状态与关键阻断不能折叠隐藏。
不因大段摘要阻塞停止操作或用户新输入；新输入使正在构建的旧候选按内核合同失效。
