# Real Android Agent slice — plugin/native-host feasibility review

2026-10-15. Independent read-only assessment of merged source **`0ab2c4f667681b9aacb017f8cd2eea6f576cf78e`**. All code references below mean that immutable SHA. No implementation, tests, installs, builds or pushes. Original native owner was sent the transport/terminal-state findings; ownership remains unchanged.

## Decision

**Feasible within the already deferred private ContractTransport direction.** The minimum plugin change is a transport seam inside the existing native composition, retaining the existing child-backed path and adding one persistent in-process Catalog per native session. It must continue through the actual registered handler, live host authority, durable original receipt and existing Agent driver. A new registry-only demonstration, direct handler FFI call or second Agent loop would not satisfy this goal.

Replacing the transport alone does **not** complete a usable Android Agent. The present native composition has an offline-only model gateway, thread-local session, Linux-oriented private storage and cancellation delivery. The concrete Android worker/lifecycle, app-private storage, installed record source and model-provider scope must be specified before implementation. These are listed below without inventing a new permission round or freezing M03.

## Smallest implementation route

1. Original native owner introduces a private `request(Json) -> Result<Json>` and close abstraction, or equivalent small enum, in native-host composition. Keep existing child constructor/PluginProcess behavior intact. Add an explicit in-process constructor that receives/creates the transport while using the same NativeSession fields, Enrollment, RuntimePorts, dispatch, ModelGateway and NativeStore. Do not auto-fallback to in-process after child failure or create a second receipt owner.
2. In-process transport owns **one** Catalog for the entire session, plus terminal state. It validates the same bounded serialized request/reply envelopes with the existing parser and then calls actual `Catalog::handle`. Do not rebuild Catalog for every call and do not introduce a permissive second parser. Keep raw transport frames private; the Android API must not expose arbitrary authority/ticket/enrollment frames to a model or UI caller.
3. The Android worker constructs and owns the non-Send session/provider/handlers on its own thread. Pass typed commands/results across the FFI worker boundary; do not mark Rc/RefCell or trait objects Send/Sync by assertion. Reuse the same Agent entry point for user tasks and acceptance tests. Keep existing declaration diagnostic as an independent capability, not the implementation of task execution.
4. Enroll host-owned handlers and explicit selected-record scopes from an actual app-owned source. Exercise the same physical read/authority/receipt chain. A scripted local endpoint is useful as an acceptance fixture for this path; a hardcoded response shown as a user Agent result is not a substitute for the chosen actual provider.

No Catalog schema, DDL/write/CAS support, dynamic plugin loading, Rust domain migration or public IDL framework is required for this transport seam.

## Child → in-process semantic differences that cannot be skipped

**Envelope admission and terminal errors.** P/src/lib.rs:28–46 bounds/schema-validates Json, but the child executable has additional behavior at **P/src/main.rs:11–25**: raw frame cap, parser validation and terminal invalid JSON/protocol-envelope/version/unknown-command/unknown-field handling. Calling Catalog.handle directly is not equivalent. Typed `Json::Number(String)` also permits construction of strings not accepted by the wire parser; request and response serialization/parser roundtrips prevent bypassing that seam. Preserve the64KiB boundaries, existing numeric grammar and bounded depth/nodes; do not use an unbounded new serializer/parser at the FFI edge.

The current process adapter closes on transport error (**H/src/plugin_process.rs:65–79,103–126**) and has a closed latch. Catalog's own `inspect` and `close` are handled *before* its closed check (**P/src/lib.rs:40–42**), so an external closed-session guard is required. After host close/terminal transport failure, later requests must fail without entering Catalog. Distinguish `transport.close()` from a successful wire `command=close`: the latter closes Catalog but does not make current main exit, and a subsequent inspect is still possible on that wire. Freeze that distinction in the parity corpus rather than silently changing the child protocol. Keep ordinary schema/authority rejections distinguishable from fatal envelope/transport failures rather than killing or reviving every denied session indiscriminately. The new adapter can preserve equivalent stable outcome categories without pretending an in-process failure is a literal OS EOF.

**Generation, epochs and one-shot tickets.** Catalog owns generation, ticket table, serial and epoch (**P/src/lib.rs:13–26**). Atomic successful registration increments generation at96; prepare binds canonical args, exact authority snapshot, generation, invocation and receipt owner/identity at124–137. Invoke and accept_result consume/check tickets at139–153; cancel removes a ticket, close clears all. Keep all these in the same Catalog; host owns no shadow ticket map. A newly created session starts a new Catalog and cannot recover old live tickets from NativeStore. Epoch is a correlation namespace, not a grant or cryptographic authenticator. Do not expose it as such. Persistent receipts do not resurrect Catalog authority.

**Authority remains external to registration.** Catalog checks the ten-field authority shape and allowed/binding values at99–108, and exact authority/generation equality on use at136–153. It trusts the host-supplied authority object; it does not authenticate its source. Host snapshot, purpose policy and selected typed refs remain mandatory, including final checks after prepare/invoke and receipt persistence (**H/src/lib.rs:323–401**). An in-process caller's ability to reach Catalog is not permission to manufacture `allowed:true`. Keep sealed catalog and current-advertised-subset checks; registration/discovery never grants physical access.

**Receipt and source facts remain host-owned.** In-process Catalog still admits metadata/tickets and validates projections, not physical reads. Keep host dispatch identity equality at361–369, original receipt owner/binding/identity at371–387, durable raw result before projection at409–435 and post-accept review/currentness at436–445. Store failure poisons further export. No raw/error/summary fallback and no direct return of raw to Android/model. Existing purpose/classification and final payload review must run even though no IPC occurs between earlier checkpoints.

**Isolation and cancellation.** In-process Catalog is trusted compiled code sharing host memory. It provides no child crash isolation, forced timeout kill, EOF or reap evidence. A bounded pure Catalog call should be synchronous and finite; do not run it on a detached thread and falsely report timeout/close while it still mutates state. If unexpected unwind is caught, terminate/drop that transport/session state rather than continue a potentially partially mutated Catalog. OOM/abort cannot be recovered by catch_unwind. Untrusted dynamic plugin code would require a separate isolation design and is outside this route.

The existing `NativeSession::cancel(&mut self)` closes the child (**H/src/lib.rs:227–232**); Android cannot deliver it by waiting for the same RefCell/worker request to finish. Existing cancel-file checks occur before handler and after handler/result acceptance (**H/src/lib.rs:281–296,396,419,442**). A cross-thread signal or controlled existing signal path must be deliverable independently of the busy command queue. Poll at actual safe points; cancellation request/pending is not terminal acknowledgment. A physical read already completed may leave its original raw receipt while exporting no projection. UI dismissal must not erase that evidence or free a busy worker slot.

Worker close must reject new work, request cancellation independently, wait/drain the active finite work, invalidate presentation generations and release store/transport ownership only on actual worker termination. A blocking trusted handler or provider needs its own bounded/cooperative contract; losing child termination does not create one. Preserve unknown outcome/restart evidence and no automatic replay. Linux child EOF/deadline/reap tests remain on the child backend rather than being falsely claimed for Android in-process.

## Effective tests required for the new seam (planned, not run)

Use paired transports where meaningful and the real Agent/host pipeline; do not count duplicate helper assertions as an integration pass. Tokens/epochs are intentionally nondeterministic: compare bound outcomes and replay rejection, not equal token strings across transports.

- Actual prepare/invoke/accept chain on both transports; invalid register publishes zero and leaves generation unchanged; successful new registration invalidates older prepared generation. Host advertisement still seals enrollment and an unadvertised-but-known operation executes zero.
- Wrong scope/empty refs/wrong selected key/type/schema_version, revoked binding/source/rule/read revision: reject before handler. Deterministically change snapshot after invoke/durable begin and assert handler0, preserving original running receipt where applicable. Existing anchors: H/tests/native_read.rs:591,838,884,941.
- Double invoke/accept, cross-session ticket, canceled ticket, old-generation ticket, mismatched original owner/binding/receipt and wrong projection/ref reject with handler count and receipt identity assertions. P/tests/read_contract.rs:5–60 contains existing cases to reuse through the transport boundary.
- Terminal bad protocol/missing/nonstring command/unknown field/invalid number or over-limit envelope followed by a valid request cannot revive the session; business rejection's expected recoverability is separately checked. Explicit close is idempotent and rejects inspect as an external transport request. Input/output escaping, byte/depth/node limits must hit the real adapter, not only Catalog helpers.
- Existing four-mapping physical-store/two-turn test runs through the in-process constructor and **same Agent drive**; exactly one physical execution/original receipt, actual second encoded payload contains only validated projection/reference. Rename fixture remains free of Agent business-name switches.
- Receipt-time and pre-send historical revocation suppress projection/send without deleting receipt/facts; invalid result retains raw only; ledger begin failure sends zero; store shape/size/depth failure cannot create unreadable persistence. Existing anchors: H/tests/native_read.rs:220,260,371,390,414,528,976,1038.
- Controlled cancel before handler, during a held handler/provider and after raw receipt: no duplicate dispatch, no subsequent projection/send, correct pending versus terminal UI state. Closing/reopening holder cannot start a second worker or accept late stale results. Release the held operation explicitly; no sleep-based ordering or invented hard cancellation.
- App-private directory validation, lock lifetime, file/symlink rejection, atomic write+fsync, cancellation delivery and restart evidence on the chosen Android execution environment. Static ABI linking or prior stateless FFI acceptance does not prove them.

No new fixed count or acceptance claim is assigned to these planned tests. Original owners should freeze exact new case identities before implementation/RED evidence; retain prior Linux/child/native gates.

## Decisions required before coding beyond the transport seam

These are concrete unanswered product/platform contracts, not reasons to restart design or re-request already granted permissions:

1. **Actual model-provider scope.** H/src/lib.rs:254 requires `profile == "offline-fixture"`; H/src/model_gateway.rs:10 and43 use OfflineEndpoint and the offline encoder profile. A production HTTP provider/credentials/network permission, different purpose profile or new wire format is genuinely beyond the approved transport substitution. Choose the actual provider boundary explicitly; do not flip an allow flag or label a scripted fixture as a live Agent.
2. **Installed data and policy source.** Which existing app-owned records may the first actual task read, and which host-owned authority/purpose implementation grants them? Preserve the static selected-record binding for the first slice if sufficient. General dynamic query/resolver, writable business migration or interpreting Kotlin/model-supplied declarations as authority needs a separate decision.
3. **Private FFI session/worker lifecycle.** Specify start, status/result, independent cancel request, terminal acknowledgment, close/drain and ownership of a session token. Existing stateless diagnostic single-flight is useful precedent but is not an execution lifecycle API. Do not export NativeSession directly as a Send/Sync UniFFI object or publicize raw Catalog frames.
4. **Android persistence/restart policy.** Choose trusted app-private directory ownership and test the current private Unix file/lock/fsync behavior (**C/src/store.rs:5–40**) on Android. NativeStore::open validates evidence, but NativeSession has no restore-to-live-session constructor; restoring receipts is not automatic task resume. Supporting arbitrary hard-stop/replay/resume or another storage backend is beyond the minimal transport seam.

Root can retain the original native/plugin, core, UI and checker owners for their existing boundaries. No competing writer or implementation has been started by this review. The proposed route is an integration of existing execution machinery, with explicit platform contracts still needed; M03 remains unfrozen.

Owner coordination: the original native owner confirmed the same persistent-Catalog/private-transport approach and the distinction between wire close and host transport close. Their proposed shipping result is only task/attempt/terminal plus opaque original receipt outcome, with no UI projection export; this is a sensible way to avoid accidentally adding a new disclosure purpose. A durable running receipt must take precedence as an unknown outcome rather than being relabeled as a definitive cancellation/no-effect result based on the current generic `native_host_refused` reason. These lifecycle/result details still need their exact private contract and effective tests before coding; they do not require another registry or Agent implementation.
