## 提示词

v5 采纳为目标稿。本轮只修下面列出的问题，不新增任何功能、页面或组件。已定决定全部不变：
- 底栏：AI 助手 · 业务插件 · 工作台 · 数据交换 · 设置；记忆在助手设置里。
- 颜色：深色主色琥珀；待确认与选中同色系（tint + deep）。
- 点击区 ≥ 48；所有数字标「示意数据」；界面里不出现 “Folio”。
- 原型插件的 WebView 内部不设计；数据中心里的原型显示「不适用」。

### A. `tokens.md` 前后一致（最要紧）
1. 颜色表中 `red / redbg` 的用途改为「失败、危险、外传」，去掉「警告」。
2. 把文末「警告色」一节并入颜色表，作为正式的一行：`warn / warnbg`，浅色 `#8A5A00 / #FFF1D6`，深色 `#E8C547 / #2E2A10`，用途「需注意、外部内容、授权过期、范围变化」。
3. 改写规则段，只保留一种说法：
   - 红色表示失败、危险、外传；
   - `warn` 表示需注意，永远配 `warning` 图标和中文；
   - 绿色表示成功；
   - 琥珀只作深色主色；
   - 待确认与选中同色系；
   - 状态永远是图标 + 中文，不只靠颜色。
4. 在对比度表里补上 `warn / sf`、`warn / warnbg`（浅、深各一）。请用工具实测，不要估算，并写明用的是什么工具。
5. 在深色模式下截一张图，让「选中行」和「warn 警告条」同屏出现，证明两者能区分。

### B. `components.md` 与 tokens 对齐
1. 「警告条」的变体改为：`warn`（需注意）/ 红（会丢失、危险）/ tint（提示）。
2. 「报价状态徽标」的色调只用已定义的 token：success、danger、warn、neutral。删除 `info`，原来用 `info` 的改用 neutral。
3. 第六轮新增的 7 个组件已经写进文件，把 `round6-notes.md` 里「尚未写入」这句改成真实状态。

### C. 授权语义（`Muyon Assistant Auth`）
1. 外部内容打开时，授权列表里**所有写入类和外传类授权**都要显示「本任务中暂停」，包括 `transfer.send`。现在只有写入类显示了。
2. 补画「发往**已授权端点**」的外传确认卡：按钮为「仅发送这一次 / 本次对话允许 / 拒绝」，仍然不出现「始终允许」。现有的「新端点」卡保留。
3. 外部内容打开时，批量确认卡不显示「全部允许」，只保留「逐项决定 / 拒绝」，并在卡顶部显示外部内容提示条。

### D. 执行记录与插件（`Muyon Assistant Runtime`）
1. 事件时间线：用户手动确认（仅这一次）的操作，后面的「执行」事件**不能**标「由授权放行」。另加一组示例，展示真正由授权放行的情况：没有「确认」事件，执行事件标「由授权放行 · 查看授权」。
2. 询价插件的「可用操作」里删除 `transfer.send`，它是平台工具，不属于询价。外传示例放在「数据交换」或平台相关的画面里。

### E. 把新确认流程补进旧稿
1. `Muyon Mobile`、`Muyon Desktop` 的对话页，补上写入确认卡（带「更多」）和批量确认卡，组件与 `Muyon Assistant Auth` 完全一致。不要另画一套。
2. 询价的其余页面也加「问助手」入口：询价单、项目、技术要求、供应商、物料。入口位置和样式与概览、报价列表上的一致，打开时带上当前范围。
3. `Muyon Mobile` 的数据中心里，原型卡片的对象类型、关系、动作、流程四格都显示「不适用」，不显示数字。
4. 全稿核对「外传」标签：一律用 `red / redbg`。「写入」一律用 `tint / deep`。

### F. 第五、六轮遗留
1. 旧稿中 44 高的控件补到 48 点击区，不可见 padding 也可以。
2. 第五至七轮新增或修改的画面，逐页检查浅色和深色；320 宽和 200% 字号至少各查一屏，把查过的画面列进 notes。
