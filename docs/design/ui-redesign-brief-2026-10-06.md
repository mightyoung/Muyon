## 1. 现状

### 1.1 产品定位（来自产品总览）
Muyon（木易工作空间）= 个人 AI Agent 为核心的跨端工作空间：业务模块（科研、询价 Folio、原型）可完整手动操作，也可由助手通过受控工具调用；结果能跳回业务页面，来源可追溯；本地优先，写入与外传逐次确认。平台：Android / macOS / Windows，Flutter。

### 1.2 应用框架：三层嵌套，各有一套导航

```
MuyonApp (MaterialApp, 主题 muyon_ui)
└─ PlatformShell            ← 第 1 层：4 个入口 工作台 / 助手 / 资料 / 我的
   │  宽≥900 左 NavigationRail；<900 底部 NavigationBar
   │  宽≥1250 右侧 360 宽助手栏；≥900 AppBar 里 4 个图标（执行面板/消息/个人/设置）
   ├─ push → WorkspacePage   ← 第 2 层：模块宿主（工作区选择、模块切换 Folio/科研、导入菜单）
   │     ├─ Folio 模块 InquiryShell  ← 第 3 层：自带 11 个入口
   │     │    工作台 项目 报价 供应商 物料 问数据 同步与交换 数据中心 设置 AI任务 公司资料
   │     │    宽≥720 侧栏 / 窄屏底栏 4 项 + "更多"；自带标题栏、命令面板 ⌘K、自己的主题
   │     └─ 科研模块 workbench    ← 第 3 层：5 个标签 概览 文库 任务 结果 写作
   │          另有 阅读器、研究关系图、LAN 传输页、写作页
   ├─ push → PrototypeHome   （原型：列表/版本/反馈/受限 WebView）
   └─ push → 各"页面"：设备与通信、设备聊天、执行面板、消息中心、个人中心、记忆、
              数据与存储、数据去向、MCP 服务器、接口与工具、系统设置、对象详情…
```

关键事实（已核对）：
- `PlatformShell` 的"我的"是一个 9 张卡片的菜单，所有平台级功能都靠 `Navigator.push` 打开，**没有二级导航、没有面包屑**。
- 宽屏时 AppBar 还重复放了其中 4 个入口；"工作台"页上又用 ActionChip 重复了设备/任务/消息/个人/设置。同一功能 2–3 个入口。
- Folio 是从 software-cost-calculator 整体迁入的应用，**保留了自己的 Shell、标题栏、主题 (`inquiry_module/.../theme.dart`)、Section 枚举**；研究与原型模块用 `muyon_ui`。即 **2 套主题实现**，视觉 token 同源（Folio 设计基线），但代码是分开的。
- `docs/design/DESIGN.md` 是**逐字复制自 Folio 仓库**的设计文档，描述的是 Folio 的 11 入口，不是 Muyon 的平台壳。**Muyon 平台层没有自己的设计文档。**
- 对象详情页（`openObject`）对非知识/论文对象直接展示 **JSON 文本**。
- 平台层页面基本是 `ListView + Card/ListTile` 默认 Material 组件，无统一的页面骨架（标题、操作区、空/错/载入状态）。

### 1.4 核心业务流程

1. **助手问答 / 调用工具**：识别任务 → 筛选工具 → 提出调用 → 核对参数、范围、权限 → **用户确认（写入/外传逐次）** → 执行 → 核验 → 保存记录并返回对象/产物引用 → 可跳回业务页。
2. **询价 North Star（第一阶段验收主线）**：在项目中问"比价/预算"类只读问题 → 助手调用 `inquiry.compare_quotes` / `inquiry.project_budget` → 回答带依据 → 点击跳回项目/报价。
3. **科研链**：导入研究成果与论文 → 阅读/批注/研究卡 → 限定资料问答 → 创建任务并导出任务包 → 另一设备执行 → 导回结果包 → 人工评估接纳 → 关联提纲 → 导出报告。
4. **设备交换**：发现设备 → 核对码配对 → 发送 → 对端**待核验** → 人工接纳 → 导入业务（传输成功 ≠ 已导入 ≠ 已读 ≠ 已接纳，各自独立状态）。
5. **资料→检索→问答**：导入文件 → 解析/OCR → 索引 → 全文检索或限定资料问答 → 引用点击回到页码。
6. **记忆/Dream**：后台整理产生建议 → 用户接受/撤回；Dream 不扩大权限。
7. **模型与数据去向**：配置端点 → 每次外发可在"数据去向"查账；Folio 模型请求弹窗逐次确认（"仅发送这一次"）。
8. **备份/恢复**：创建备份 → 校验 → 恢复（关闭宿主→恢复→重开，失败回退原数据）。

### 1.5 必须保留的需求与不变量（设计不得破坏，出处：产品总览、安全不变量）
- 写入与外传**逐次确认**；确认框要显示目的地、摘要、实际发送内容。
- 模型回答/资料内容**不能授予权限**；UI 不得把"模型置信度"当授权。
- **状态分离**：已发出 / 已送达 / 已接纳 / 已读 / 已导入，各自展示，不合并，不只靠颜色。
- 失败/中断/未知结果明确显示；"已开始""局部完成"不得显示成成功；本地取消不冒称远端已撤销。
- 区分：无数据 / 筛选无结果 / 加载中 / 失败 / 不可用。
- 引用可点击回原对象，并保持项目与来源上下文；"无依据"的历史回答明确标记。
- 本地优先：无模型时仍可阅读、编辑、检索；离线工具模式保留。
- 桌面：导航 + 中央业务内容 + 可收起的上下文助手；手机：独立页面 + 明确返回；窄屏/大字体/键盘/减少动效可用。
- 报价、金额、计数来自真实数据，不补虚构指标；金额右对齐、保留精度。
- 业务模块的完整专业页面保留，不把所有操作塞进聊天。

## 3. 设计目标与原则

**一句话**：让 Muyon 像一个"带助手的工作空间"，而不是"几个应用的启动器"。

1. **一个壳，一套导航**。平台壳是唯一的全局导航；模块在壳内容区里提供**二级导航**，不再自带标题栏/侧栏/主题。
2. **助手无处不在，且知道上下文**。右侧上下文助手栏（桌面）/ 底部抽屉（手机）固定存在，顶部显示"当前范围：项目 X / 论文 Y / 全局"。
3. **"待你确认"是一等公民**。任何需要用户决定的事（工具调用、模型外发、设备来件、Dream 建议、冲突）汇入统一的**收件箱**，带数量角标。
4. **状态可扫读**。统一状态徽标（图标+文字+色），把枚举名翻译成业务词；多状态并存时并列显示，不合并。
5. **密度优先，克制装饰**。沿用 Folio 基线：中性色、蓝色=可操作、8px 圆角、无渐变/发光、表格保持密度。**视觉语言不推翻，推翻的是信息架构和页面骨架。**
6. **一个设计系统**。`muyon_ui` 成为唯一主题与组件来源，Folio 的 theme/title_bar/motion 并入。

## 4. 方案

### 4.1 新信息架构（全局 5 项，用户 2026-10-06 定；替代现 4 项 + "我的" 9 卡）

| 全局入口 | 内容 | 来自现有 |
|---|---|---|
| **AI 助手** | 主对话与专题对话列表；手机主入口；桌面同时有右侧助手栏（4.3）。**并入 Folio「问数据」** | 助手、Folio 问数据 |
| **业务插件** | 插件网格：询价 · 科研 · 原型；进入后内容区显示该插件的二级导航；工作区切换在此 | WorkspacePage + 各模块 Shell |
| **数据交换** | 两个标签：**局域网 IM**（设备发现、配对、一对一文字/附件聊天）与 **数据包**（导出/导入研究包、任务包、结果包，来件待核验）；Folio 的"同步与交换"并入此处 | 设备与通信、设备聊天、各模块交换页 |
| **工作台** | 待我处理（收件摘要）· 运行中任务 · 最近对象/对话 · **资料**卡片（→ 文件、全文检索、对象目录）与 **记忆**卡片（→ 记忆、Dream 整理、经验） | 工作台、资料、记忆 |
| **设置** | 外观、模型、权限；**数据去向、MCP/接口与工具、数据与存储**、各插件设置（含原 Folio 设置、公司资料中心连接）作为二级页 | 系统设置、数据去向、MCP、存储、接口 |

> 用户 2026-10-06 确认：「资料」「记忆」在**工作台里各放一张卡片入口**，点击进入完整页面（不是内嵌分区）。底栏顺序：AI 助手 · 业务插件 · 数据交换 · 工作台 · 设置。视觉与交互参考 Muse，见 §4.7。

另有两个**全局悬浮层**（不占导航位）：
- **收件箱**（顶栏铃铛，带角标）：分组「需确认 / 运行中 / 来件待核验 / 通知」，原消息中心 + 执行面板 + 任务中心 + 待确认合一。点击条目→就地确认或跳对象。
- **助手栏**：见 4.3。

桌面布局：`[图标轨 72] | [二级栏 240，可收起] | [内容区] | [助手栏 360，可收起]`（插件二级导航就在二级栏里，详见 §4.7）；顶栏：面包屑（工作区 › 插件 › 对象）、⌘K 命令面板（沿用 Folio）、收件箱、工作区切换。
手机：底栏 5 项，即上表五项，无"更多"；收件箱在顶栏；所有二级页独立页面+返回。

### 4.2 业务插件统一前端套件与接入规范（解决 D1/D5；用户 2026-10-06 要求各插件用同一套前端套件）
模块不再包含 `Scaffold`/AppBar/侧栏/主题。`muyon_module_api` 增加模块**导航声明**：`sections: [{id, label, icon, builder}]` 与可选 `quickActions`，由壳渲染二级导航（桌面：内容区左侧窄栏或顶部标签；手机：顶部分段/抽屉）。
- Folio 的 11 项 → 分组后 6 组：**业务**（项目、报价、供应商、物料）· **问数据**（并入全局 AI 助手，依据展示迁移为助手的"依据"折叠；用户已决定并入）· **AI 任务**（并入收件箱，模块内保留历史）· **同步与交换**（并入全局数据交换）· **公司资料**（作为插件内页面）· **数据中心** · **设置**（并入全局设置的插件分区）。
- 科研 5 标签保留为模块二级导航；阅读器/关系图保持全屏页。
- ⚠ 这是对 Folio 的大改，**必须保留业务页面与流程**，只替换壳。分阶段做（见 §6）。


**统一前端套件（`muyon_ui`，唯一来源）**——询价、科研以及今后的插件**只能**用它构建界面：
- 主题与 token（颜色、字号、间距、圆角、动效）、图标集（平台导航 + 业务对象图标目录并入同一包）。
- 页面骨架 `PageScaffold`、`MasterDetail`、`DataTable`、`StatusBadge`、`ObjectChip`、`ConfirmSheet`、`ObjectDetail`、空/错/载入态组件、表单控件（输入、选择、金额输入、日期、筛选条）、对话框、胶囊分段控件、Toast/Snackbar。
- 插件 **不得**自带 `MaterialApp`/`ThemeData`/`Scaffold` 顶层/标题栏/侧栏；不得硬编码颜色（lint 规则禁止 `Color(0x…)` 与 `Colors.*` 出现在 `packages/*_module` 的 UI 代码里，token 与 golden 测试除外）。
- 迁移顺序：研究、原型已依赖 `muyon_ui`（先清理硬编码）；询价（含 `supplier_core` 中的 UI）有自己的 `theme.dart`、`widgets/`、`motion.dart`，其中通用部件（data_grid、AppIcon、MaterialIcon、command_palette、motion）**迁入 `muyon_ui`**，询价特有的业务部件留在询价包内但只用套件组件拼装。
- 套件有一份**组件目录页**（开发用，仅 debug 构建可见）与 golden 测试，作为各插件对照的单一事实。

**原型插件例外（用户 2026-10-06）**：原型的内容是**导入的 WebView 页面**，页面内部的视觉**以导入内容为准**，沐阳不改写、不套主题。只有原型插件**外围**（列表、版本、反馈、导入/权限提示、受限 WebView 的边框与工具栏）使用统一套件。WebView 的资源与导航限制（`resource_policy`、`web_guard`）不变。
其余插件（询价、科研）一律使用同一套件，保持整体风格一致。
### 4.3 助手栏（解决 D3）
- 头部：**范围条**——"全局 / 工作区 X / 项目 Y / 已选 3 个对象"，可点击更改；切换项目时自动更新。
- 主体：对话流（保留 760 宽阅读列、用户消息气泡、助手正文直排）；工具调用以**内联卡片**呈现：工具名 · 参数摘要 · 影响（只读/写入/外传）· 按钮「确认/拒绝/仅这一次」；执行中显示阶段与"暂停/取消"；完成后显示产物引用 chip（点击跳对象）。
- 回答下方折叠"依据"（保留现有核验与记录跳转）；历史回答无依据时标"未保留依据"。
- 离线工具模式作为输入框旁的模式切换（"助手 / 离线工具"）。
- 手机：底部抽屉，可拉起为全屏。

### 4.4 页面骨架与通用组件（解决 D6/D7）
新增到 `muyon_ui`：
- `PageScaffold`：标题 + 副说明 + 主操作 + 次操作菜单 + 内容；内置 loading / empty / filtered-empty / error 四态插槽。
- `StatusBadge(kind, label)`：任务态、传输态、送达态、接纳态、索引态、模型位置（本机/本人设备/远程）。**图标+中文词+色**，不显示英文枚举。
- `ObjectChip` / `SourceRef`：模块图标 + 对象名 + 模块名；可点击；缺失对象显示"已不存在"。
- `DataTable`（沿用 Folio data_grid 规则：42 表头/52 行/表内横滚）、`MasterDetail`（≥1000 并排，窄屏独立页）。
- `ConfirmSheet`：统一的确认框，固定区块：**做什么 / 对谁 / 发送内容（可展开全文）/ 摘要散列 / 后果 / 按钮**。工具确认、模型请求、导入、恢复、删除都用它。
- `InboxItem`：统一收件条目。
- `ObjectDetail`：按 schema 渲染字段表 + 关联对象 chips + "在业务页面打开" + "针对此对象提问"，替代 JSON 文本；模块可提供自己的 `objectPage`（已有接口）。

### 4.5 关键页面设计要点
- **工作台**：三栏卡片区——「待我处理 N」（收件箱前 5 条，可就地确认）/「运行中」（任务进度行）/「最近」（对象与对话，带模块图标）；顶部一个全局搜索（资料+对象+对话）；底部才是模块入口。去掉说明大段文字和重复 chips。
- **收件箱**：左分组筛选、右详情（桌面）；条目含时间、来源（助手/设备/Dream/模型网关）、状态徽标、动作。
- **设备**：设备卡显示 名称 · 指纹后 6 位 · 在线 · 已配对；发送进度条+"已发出 / 对方已收到"分两行；来件"待核验"区置顶，带"核验 → 接纳/拒绝"；聊天标签沿用 chat 草稿的 4 状态+重发提示。
- **资料**：左目录（全部/文件/业务对象/记忆），中列表（表格），右预览；检索结果显示命中片段+页码+来源 chip；OCR/索引状态徽标。
- **设置 › 数据去向**：时间线表格，列：时间 · 调用方 · 目的地（本机/本人设备/远程域名）· 摘要 · 状态；顶部汇总"本周发往远程 N 次"（真实计数）。
- **对象详情**：见 ObjectDetail。
- **空/错/载入态**：每页必须有文案，写明恢复路径（沿用 DESIGN.md 的交互状态规则）。

### 4.6 视觉语言
沿用 Folio token（浅/深两套，见 `muyon_ui/tokens.dart`），**不换色**。调整：
- 全局壳层使用 `nav` 底色；内容区 `canvas`；列表/表格 `surface`；浮层不加阴影，用 `ruleStrong` 边。
- 字体沿用 Noto Sans SC；助手正文 15/1.7；表格 13；标题 24/16。
- 图标：现有 102 枚 Folio 业务图标继续用于业务对象；平台导航用 Material outlined，统一到同一套 24px 线性。
- 新增 token：`info`（模型位置/说明）可选；状态色保持 amber=待确认、red=失败、green=成功，蓝只表示可操作/选中。
- 动效沿用 DESIGN.md §8；尊重 reduceMotion。

### 4.7 Muse 参考（来自用户提供的 15 张手机截屏；含个人内容，**不入库**，只在用户本机）
我只看了这 15 张截图，**没有访问 https://ai.meta.com/muse/ 主页**，下面是对截图的观察，不是对产品的完整了解。

**Muse 的结构（移动端）**
- 底栏 5 个**纯图标**标签：聊天 · 动态（feed）· 点子 · 目标 · 构件（文件/影音）；选中态=图标变实心黑，无文字、无色块。
- 每页顶部居中是**吉祥物头像 + 名称胶囊**；左右是**圆形描边图标按钮**（菜单/邀请/筛选/更多）。
- 左滑抽屉：对话列表（主要聊天 / 旁聊）+ 底部「设置 · 搜索 · 新建」三个圆角胶囊。
- 页内切换用**胶囊分段控件**（如 构件/影音内容）；列表项是「大图标 + 标题 + 灰色副文本」，无卡片边框，用细线分隔。
- 助手"档案页"：5 个图标标签 = 活动记录（按日期分组）· **批准**（空态"尚未获得批准"）· 浏览器 · 提醒/定时 · 身份（SOUL、记忆两张渐变卡，标"请谨慎访问"）。
- 设置：顶部用量卡 + **分组圆角列表**（图标 + 文字 + 箭头），含 连接器、权限、数据控制、外观 等。
- 视觉：大圆角（卡片≈28、按钮全圆）、大留白、大字号、浅色近白底；深色为纯黑底 + 深灰圆角面板；主按钮为深蓝实心；弹出菜单为圆角浮层，带勾选态。

**我们采纳什么 / 不采纳什么**

| 采纳 | 理由 / 落点 |
|---|---|
| 底栏 5 项、纯图标、选中变实心 | 与用户选定的 5 项一致；**用户 2026-10-06 决定不加可见文字标签**。仍须有 `Semantics` 标签与长按/悬停 tooltip（屏幕阅读器与键盘用户），这是无障碍底线，不是视觉文字 |
| 助手档案页的 5 图标标签：活动 · **批准** · 提醒/定时 · 记忆 | 直接对应我们的**收件箱**：活动=执行记录、批准=待确认、提醒/定时、记忆；把"批准"做成一级标签，强化"逐次确认"这一核心卖点 |
| 圆形图标按钮 + 居中标题胶囊的页头（手机） | 统一手机页头：左返回/抽屉、中标题、右更多；桌面不用 |
| 左抽屉放对话列表 + 底部 设置/搜索/新建 | AI 助手页的对话列表（主要对话 / 专题对话 / 旁聊） |
| 胶囊分段控件 | 数据交换（局域网 IM / 数据包）、资料（文件 / 业务对象）等二级切换 |
| 设置的分组圆角列表 | 设置首页；把 模型、权限、数据去向、MCP、存储 分组 |
| 日期分组的活动流（今天 / 10月3日…） | 收件箱「运行记录」、数据去向时间线 |
| 记忆卡片 + "请谨慎访问" | 工作台的"记忆"入口卡片；进入前对含敏感来源的记忆给出提示 |
| 空态一句话（"尚未获得批准"） | 所有空态都写清含义，补恢复路径 |

| 不采纳 | 理由 |
|---|---|
| 吉祥物头像、纯消费级装饰 | 沐阳是业务工具；可保留一个简洁的助手标识，不做拟人形象 |
| 动态 / 点子 / 目标三个内容消费标签 | 不在需求内（冻结期也不允许新功能） |
| 过大的圆角与留白 | 业务表格需要密度（DESIGN.md 表头 42/行 52）；**圆角大尺寸只用在手机的助手、工作台、设置**；询价与科研的业务页面保持 8px 与表格密度 |
| 无边框列表遍布全局 | 业务页仍用 `surface` 底 + 细线；Muse 风格只覆盖壳层与平台页 |

**桌面端（用户打开了 Muse 桌面应用，我截图观察了「聊天」与「资源库」两页）**
- 三栏：**最左 78px 图标轨**（头像在顶、导航图标居中偏上、设置/菜单在底）→ **二级栏约 250px**（搜索框 + 当前区域的分类/对话列表，如 聊天=主要聊天/旁聊，资源库=所有构件/文档/网络构件/图片/视频/播客）→ **内容区**。
- 内容区居中、最大宽约 600–700 的聊天列；资源库是**缩略图卡片网格**（文档首页预览 + 文件名 + 类型/时间），顶部右侧一个主色胶囊按钮「+ 创建构件」、次级「选择」「排序」图标按钮。
- 浅/深两套，深色为近黑底、浅灰圆角面板。
- 助手栏：Muse 没有右侧上下文栏（聊天本身占内容区）。**沐阳保留右侧助手栏**，因为业务插件页要与助手并排；在 AI 助手一级页则助手占内容区，不再重复出现右栏。

沐阳桌面落点：`[图标轨 72] [二级栏 240：当前区域的列表/分类，可收起] [内容区] [助手栏 360，可收起]`。图标轨 = 底栏同 5 项同图标，选中实心；二级栏对应各区域（AI 助手=对话列表；业务插件=插件列表+插件自己的 sections；数据交换=设备/会话列表；工作台=卡片区无二级栏；设置=设置分组）。这样 Muse 的"轨 + 列表 + 内容"与 4.2 的"插件二级导航"是同一个槽位，不会出现第三层导航。

**视觉 token 变化（相对 Folio 基线）**：新增 `radiusLarge=24`（壳层卡片/抽屉/胶囊）、`radiusPill=999`；`canvas` 在手机壳层可用更接近白的 `#FCFCFC`/深色 `#000`，由 UI-1 评估对比度后决定；主色蓝保持。不引入渐变，**记忆卡片的渐变底不采纳**（DESIGN.md 禁渐变），用 `sunken` + 图标。
