# 对话事实卡接入、保存与恢复设计（CR-8，ChatGPT 6 Pro）

状态：**设计稿，D1～D5 已由用户采纳（全部按推荐，见 ADR-0001 末尾 2026-10-11 条）** · 依据：基线 `b521591`（task/decisions-20261011b）、PR42 `c7bbc94`、SN-3 任务 `4068bcf` · 只读静态设计 · 原稿由用户转交，leader A 整理入库，保留全部结论、规则、任务片、拒绝路径与待决事项，代码位置以原稿为准。

## 总结论
宿主统一管理对话事实卡：**固定事实卡、PR42 动态卡、SN-3 失败模板是同一张逻辑卡的不同呈现状态**；保存的是经过约束的恢复资料，重启后必须重新取得宿主证据才能恢复显示。七项核心设计：
1. 宿主拥有卡片身份：接受请求时冻结请求归属、目标对象、呈现资格；父回答或宿主离线说明保存成功后读取仍匹配原 pin 的事实接入固定卡，不等动态布局。
2. 同一事实区域只保留一个正式内容主体：动态计划通过完整校验、宿主复核并覆盖该区域必显内容后才原位替换；失败模板用同一位置；有过合法预览的中断保留并标「未完成」，来源失效时预览旧值同样撤下。
3. 事实、模型建议、用户草稿分开；没有建议就保持缺失。
4. 复用存储但增加安全投影：保存身份、完整 pin、可持久化的最终呈现或模板描述、允许保存的草稿与视图；不保存敏感原值、原始模型输出、未完成流、授权与回调。
5. 恢复先核验后显示：会话与任务归属、范围、模块、原 pin、revision、digest、字段策略、污染状态；恢复不重发模型请求、不自动执行、导航或激活模块。
6. 失效先撤值再异步处理：不能只禁用按钮，也不能等失效状态保存成功才撤值。
7. 三档控制所有内容卡；历史显示依据不能恢复成新的规划或执行能力。
保存恢复由接线任务负责、少用规则、重启不重新播种、真实建议覆盖等已由 ADR-0001 采纳，不再待决。

## 1. 接入时机、负责方与身份
- 新增宿主级「对话事实卡协调器」（暂名 `ConversationFactCardCoordinator`），负责关联、去重、排序、读事实、核来源、关联建议、固定 / 动态 / 退路切换、保存、恢复、失效与拒绝迟到结果；Widget 只订阅显示状态。`OntologyCard` 继续作为受约束呈现部件（不接模型组件、动作、回调，提交禁用）。
- 四步：(1) 接受真实请求时冻结请求、范围、目标对象、宿主入口的呈现资格，可预留 `cardId`；(2) 父回答（或宿主离线说明）保存成功后关联回答并读事实，不阻塞正文；(3) 复用 `InquiryReadonlySnapshots.read` 与适配器检查（模块运行、owner 未换、对象在范围、记录存在未删、revisionRef / contentDigest / 项目一致、读取前后 authority 一致）后发布固定卡；(4) 动态结果就绪由协调器决定是否原位替换；已采用动态布局后迟到的固定结果不能降级，失效后任何结果不能重装。
- 身份分层：回答归属 `conversationId + parentTaskId + answerMessageId`（不靠「最后一条回答」或文本相似）；逻辑卡 `cardId` / `surfaceId`（重建、切换、恢复不变）；去重位置 = 回答归属 + 宿主声明的呈现目的 + 对象实体身份；事实 pin 为完整 ObjectRef；呈现尝试 = request/attempt + 运行时 generation；对象版本、计划版本、草稿版本、存储 CAS 版本分开。
- 两个现有缺口：回答保存事务内部生成消息 ID，卡片 owner 拿不到稳定的任务—消息关联，需在同一事务形成可读关联记录；去重不能用 `SnapshotRef.id`（固定适配器用序列化 ObjectRef，PR42 把对象、模块生命周期、工作区 authority 一起散列）。
- 仲裁：读取或恢复核验中 → 无旧值占位；事实有效 → 固定事实主体 + 来源 + 只读说明；规划中 → 保留事实主体加进度或合法预览（无动作）；动态完整通过且覆盖必显事实、来源、遮盖、只读 → 原位替换（只负责图表或局部说明的合法计划不能让必显事实消失）；失败 / 超时 / 取消 → 同位置宿主事实退路与原因；来源失效 → 撤正文、建议、来源片段、预览；当前档位不允许 → 不挂载。SN-3 负责失败类别、预览保留与模板构造，协调器负责归属、去重与保存。
- 首个切片绑定**一个明确目标对象**（PR42 实际读 `refs.first`，不能据此声称覆盖多对象）；多对象另列逐对象能力，非原子聚合，不静默忽略其他对象。

## 2. 建议区
- 显示能力已有（`OntologyCardSnapshot` 建议为不可信提示，`OntologyCard` 有「建议（尚未写入）」），但 `suggestions` 默认空、PR42 生产 source 没传——不能写成「真实建议已接通」。
- 推荐给业务回答增加**可选结构化建议通道**，宿主解析与归属检查后进入建议区；每条至少带父任务 / 请求 / 响应引用、宿主提供的目标引用、本体字段名与候选值、来源类别与污染关联、候选身份、宿主固定的「尚未写入」状态。不另开模型请求补齐；模型没给就为空。
- 三区：已保存事实（只由重新取得的宿主事实更新）、模型建议（标「模型建议 · 尚未写入」，不覆盖事实）、用户草稿（标「用户草稿 · 尚未写入」）。采纳建议只表示移入待核对草稿，只读卡不产生业务提交。候选数字只作标注文字，不进事实绑定或计算；未知字段、错对象、旧 pin、凭据字段、超限、类型不符拒绝。
- PR42 把固定卡格式化字符串统一标 `verified`，可能包括遮盖或缺失占位；新投影须保留「有值 / 遮盖 / 缺失 / 未核验 / 读取失败」状态。

## 3. 保存
- 每张逻辑卡一份一致记录：身份与归属；宿主明确请求依据（事件引用，不存可执行请求对象）；完整来源 pin + 来源摘要 + 定位 + 投影规则版本；固定模板 ID/版本或满足持久化白名单的最终 UIPlan；允许持久化的用户草稿（含字段来源、draftRevision）；「敏感值未保存 / 需重新输入 / 字段不兼容」等元数据；合法字段与节点上的视图状态；上次呈现结果（固定 / 正式动态 / 失败 / 未完成 + 原因码）；CAS 版本；新事实卡的历史操作引用为空。
- **不能直接复用 `_capture` 输出**（会保存 `initialUiState`、覆盖值、视图值、隔离草稿与整份 UIPlan，无卡片级敏感过滤）。排除：业务完整数据、敏感原值、凭据；原始模型请求响应、正文副本、NDJSON 与半成品；来源全文；审批、grant、令牌、回调、执行上下文；未审查异常、调用栈、端点、本机路径。限制同时覆盖 UIPlan 文字属性、标题、草稿、视图、诊断与 metadata。含不可安全保存原文的计划只存模板描述与状态，重启恢复固定卡，不能删改后冒称同一计划。原回答由会话机制管理，卡片只存引用。
- 「未保存」不能伪装成字段值：`displayValues` 会合并提取值、覆盖、选择、隔离草稿，所以占位串或脱敏用的 `null` 不能进可编辑字段；「用户明确清空」与「因策略未保存」分开；未分类自由文本不自动进可恢复草稿；未采纳的模型建议正文首版不保存（D4）。
- 时点：固定卡首次接入、正式动态被采用、用户改草稿时保存；视图状态可合并，离页 / 关闭 / 进后台前 flush；失败或中断只存状态；来源失效先撤值，能保存时再更新状态。界面区分「已保存事实」（业务库）与「此视图已保存，可恢复」（检查点 CAS 成功）；CAS 失败显示「此视图尚未保存」，保留最后成功版本，不覆盖另一窗口的成功版本。
- `HostUiWorkspaceStore`：可复用 `load`（核 task/surface/scopeKey，但不证明范围成员、pin、模块、污染）、`save` CAS 与容量检查（不提供脱敏和来源验证）、`surfaces()`（无卡片类型与安全失败描述）、`encode/decodeUiPresentation`（解码结果不是已验证计划）、`UiWorkspaceController`（不能代替恢复准入）。建议加严格类型化卡片 metadata 与独立卡片格式版本，**不要把 `schemaVersion` 改成 3**（`library-2` 约束对应 schema 2）。另需安全发现能力：范围不匹配时可知「这里曾有卡片」的不透明身份与原因，不返回旧字段。

## 4. 恢复
- 从原回答的卡片入口恢复（启动先加载会话任务历史；原回答可见或用户打开保存卡时启动本地核验）；现助手页枚举 surfaces 打开通用动态工作区，需改交卡片恢复 owner。首帧不显示保存的事实值。
- 六层检查：(1) 身份与格式（task / conversation / answer / card / surface 关联、版本、容量、类型；未知版本不猜升级）；(2) 当前呈现资格（读当前三档，少用核对原明确请求依据，只用文字不挂载；不从保存的布尔重建运行时请求能力）；(3) 当前权限与来源（范围成员、模块、owner、项目、**原 pin**、删除状态；版本变了旧卡失效，不自动绑最新版，新版须用户重新选择并新请求）；(4) 重新调用 `authorizationFacts.readTask`，不信保存的 clean：clean 继续；tainted 可展示已获准只读事实但不恢复放行；unknown 或读取失败暂不挂正文；(5) 当前适配器重读事实、重新应用字段策略与遮盖，再验证保存的 UIPlan（`UiWorkspaceController.open` 需要调用方提供当前已验证计划，不会自行重建可信事实）；(6) 恢复安全草稿与视图，发布前再核 generation / authority / 归属，同步安装；初始化静默设置，不触发业务事件。
- PR42 的 snapshot ID 含运行时 authority，重启后可能变化；建议统一的宿主呈现投影身份 = 完整 pin + 投影规则版本，运行时 owner / authority / generation 单独作核验条件；无法证明等价的旧记录恢复固定模板，不改写 snapshot ID 来过校验。
- 失败显示：无记录「此卡没有可恢复的保存记录」；损坏 / 未知版本 / 超限「保存内容暂时无法读取」；范围不符「此内容不在当前范围内」；pin 不符或删除「来源已变化，请重新选择并请求」；模块不可用「相关模块当前不可用」（不为恢复自动启用）；污染未知「来源状态尚未核实，内容暂不显示」；原布局不兼容「已使用固定展示」；草稿不兼容「部分草稿需重新核对」；上次未完成「上次布局未完成，未自动重试」；历史操作结果未知「执行结果未知，未重放」。**不能通用复用现有「旧草稿仍可阅读」退路**（无 plan 时直接显示 `stored.displayValues`，会泄露应撤下的旧值）。

## 5. 持续失效
监听范围与成员、对象 revision/digest/删除、模块停用 / 重载 / owner 替换 / authority、污染事实、三档保存后的 generation。顺序：同步提升 generation 关闭旧发布资格 → 撤旧正文、来源片段、依赖旧 pin 的建议、详情与语义内容 → 释放旧 renderer/controller/router 使回调失效 → 显示无旧值的原因 → 按需本地复核（迟到结果须匹配当前 generation 与原 pin）→ 尝试保存无值状态（失败不影响前五步）。旧卡保留历史身份标失效，不改成新版；范围变化导致 CAS 拒绝时不改 scopeKey 绕过。只改 digest 或禁用按钮不足：`fact` 绑定直接读快照值，digest 检查只在 `sourceSpan` 分支，验收要检查视觉树与语义树中旧值已消失。

## 6. 三档
自动：准入通过允许固定卡，动态另经完整校验，失败有同位置退路，恢复时重核原 pin 只读恢复、不重新规划。少用：只有本轮宿主冻结的明确请求才出卡；恢复要求可核实的原明确请求依据（D5），缺依据则隐藏，等用户经新的「只读查看已保存卡」宿主入口明确请求，仍不调模型。只用文字：不显示固定卡、动态卡、预览、模板。区分「历史显示依据」与「新的运行时请求能力」，只恢复前者。三档先保存成功再生效；必要业务确认与拒绝入口始终保留。planner 返回的 `UiDisplayDecision.textOnly` 可能表示规划失败，不能当成用户选了「只用文字」而省略应出现的退路。

## 7. 任务片、验收与待决
| 片 | 交付 | 依赖与边界 |
|---|---|---|
| CF-1 回答身份与准入 | 显式任务—回答关联、cardId、去重位置、原 pin、明确请求依据 | 不靠消息顺序与文本猜 |
| CF-2 固定卡与呈现仲裁 | 真实固定事实接入、动态原位替换、SN-3 同位置退路 | 生产 stream/2 + library-2 先通过；保留全部必显内容 |
| CF-3 建议区接线 | 结构化候选解析、归属与字段检查、三区分离 | 不伪造建议，不增加业务提交 |
| CF-4 安全保存 | 类型化 metadata、来源 pin、安全序列化、CAS、保存状态 | 整份记录防回流，不直接存 `_capture` 全量 |
| CF-5 恢复入口 | 原回答内恢复、来源重建、计划再验证、安全草稿、零自动动作 | 不调模型，不自动换 pin |
| CF-6 持续失效 | 范围、版本、模块、污染、档位变化的同步撤值与迟到拒绝 | 覆盖固定、动态、模板、预览、恢复卡 |
| CF-7 同候选验收 | 观测点、拒绝路径、真实建议覆盖、持久检查点与手验交接 | 自动 1～4、7；重启手验 5、6；同一 SHA |
顺序遵守已采纳计划：生产编译器与新组件链先于卡片接线，三档真实策略与持久恢复先于默认开启。

拒绝路径（须观察到的结果）：重复到达只一张逻辑卡一个正式主体、旧尝试不覆盖新尝试；跨任务 / 回答 / 对象的卡或建议拒绝接入；范围撤销或成员变化后已显示与恢复中的旧值都撤下、模板详情语义树不泄露；revision/digest 变化、删除、项目不符则原卡失效不换新版；模块停用、owner 替换、读取中 authority 变化先撤值、旧异步结果不重装、恢复不激活模块；污染缺失 / unknown / late-taint 不恢复 clean、无新增放行、授权消费或写入、未知不显示正文；合法但缺必显事实或来源的动态计划不得替换事实区；坏行、缺 end、超限、整份校验失败无正式动态卡、按档位退路、合法预览标未完成；end 后额外行忽略并记 `after_end`；有效 end 后传输错误分开记录并保守撤销执行能力；取消或超时后的有效完成结果不复活、不自动重试；敏感值不出现在检查点任何字段；「未保存 / 明确清空 / 字段移除」三态可分；模型无建议、错字段或虚报已保存时保持缺失或拒绝、不用脚本建议冒充；并发 CAS、保存失败或崩溃只恢复最后成功版本、失败方不覆盖赢家；损坏 / 未知版本 / 超限不显示原始 JSON 或未检查的抢救内容；切只用文字或伪造少用请求后内容卡按真实策略消失；真正重启后恢复路径**零新增模型请求、零业务执行、零审批或授权消费、零自动导航与模块激活**（与正常启动、测试播种、人为扰动分开记账）。前提：先证明本轮真实卡出现再查控件禁用；固定卡出现、真实模型调用、stream/2 编译、正式动态卡分别记录；正常组至少一例真实非空建议。
