# 冒烟集成测试 `aiui_smoke_test.dart` 规格（CR-3，ChatGPT 6 Pro）

状态：**规格稿，第 6 节待用户决定**，未实现 · 依据：基线 `86525cd`、PR42 `c7bbc94`、Android 操作说明 `507011c`、SN-3 任务 `4068bcf` · 原稿由用户转交，leader A 整理入库，保留全部要求、错误分类与待决事项，代码位置以原稿为准。

验证链路：**真实助手页面 → 真实宿主与模型调用 → 本轮询价事实卡 → 可观察的执行结果**。缺生产接线、失败退路或必要观测点时**明确失败**。自动覆盖验收项 1～4、7；5、6 留给 Haiku 用 adb 杀进程手验（不能用同进程 `host.close/open` 代替）。

## 1. 文件结构
- 复用：`seedInquiry` / `NorthStarFixtureData`（项目、两家供应商、两条预算行、一张询价单、四条报价，经业务 Store 准备）；`northStarSetting` 模型配置解析（`--dart-define`，正式冒烟强制 `MUYON_EVAL_REAL=1`，缺真实模型配置即失败）；`EnvSecretStore` 测试凭据通道（不证明生产钥匙串安全）；`receiptRows/approvalRows/ledgerRows` 只读查询做前后增量比较；`checkReadResults/checkInvariants` 的断言原则（本冒烟要求**零业务写入**，不是 North Star 的恰好一次写入）。
- 不能原样复用：North Star 设备入口（没挂真实页面）、`FixtureModelServer`（普通 JSON，无流式暂停截断）、`publishNorthStarEvidence`（会输出端点、失败栈和本机路径）。
- 新增：`aiui_smoke_test.dart`（注册用例、前置检查、正常组与失败组、汇总，失败仍尽量输出脱敏证据并失败退出）；`support/aiui_smoke_fixture.dart`（隔离宿主、种子、真实流式模型、解析选中对象、挂真实应用、管理手验所需持久数据）；`support/aiui_smoke_driver.dart`（操作真实输入、发送、模型确认、呈现设置、取消、范围选择，数据库只作观察）；`support/aiui_smoke_probe.dart`（关联本轮提交、任务、规划请求、卡片与帧，采首字首卡时间，只读）；`support/aiui_smoke_faults.dart`（按请求控制连接中断、流停顿、协议故障，保留真实 gateway、授权、编译器、renderer）；`support/aiui_smoke_evidence.dart`（白名单证据、中位数、落盘与分段输出）。
- 数据：每轮只针对一个明确对象（推荐种子 `firstInquiry`），经真实 scope source 解析，带当前 `revisionRef`、`contentDigest`、项目归属；使用 `selectedObjects`（最多 5 个 inquiry 对象），不沿用 North Star 的 global 会话。
- 手验交接：自动结束时留下「测量完成、待手验」检查点——同一套隔离数据，保存阶段与对象 / 任务 / 卡片关联，重启进恢复页面不重新播种、不重发模型请求，不含密钥端点路径；自动失败时标明检查点是否完整。不能沿用 North Star 结束即删临时目录的生命周期。

## 2. 验收项
- **项 1 事实卡**：选中固定版本对象 → 真实输入框提交只读展示请求 → 真实确认入口处理模型请求确认 → 等本轮事实卡并核对本轮生产流式规划结果。断言：卡属于本轮任务与对象（非提交前已有、非测试单独挂载）；事实对应业务库已保存记录，来源标签对象与修订和当前 pin 一致；建议独立标「尚未写入」，不覆盖事实，模型未给的内容保持缺失；敏感字段遮盖、凭据不进卡；未知与未核验值不变成确定事实；真实模型调用、stream/2 编译、library-2 渲染各有宿主可观察证据——**固定事实卡出现本身不证明模型规划成功**。非确定性：不比整段回答、措辞、节点 ID、像素；比宿主事实、来源关联、必显结构、动作边界。至少一个样本有非空建议才算覆盖了「事实与建议分离」。
- **项 2 提交禁用、无写入确认**：先记业务数据与审批回执基线；检查本轮卡内全部业务提交控件，对禁用控件正常点按后再读。断言：先确认确实出了只读卡与限制说明（防空集合通过）；控件禁用；无新增业务写任务、写确认、写审批、业务写回执；业务记录值、版本、数量不变；业务写 grant 使用次数不增。只读回执、内部规划任务、模型请求确认可正常出现，模型 grant 消费单独统计。正常、失败退路、失效后的卡都做。
- **项 3 退路**：见第 4 节，四类故障各自检查任务终态、执行记录失败类别、原回答保留、按档位的退路、无有效半成品卡、无业务执行、迟到数据不能复活。
- **项 4 失效**：两个独立用例，分别在卡已可见后和规划进行中触发。范围撤销：经真实宿主范围入口移出目标（可换成另一有效对象，避免非法空 selected scope）→ 旧卡字段、来源值、语义树撤下，旧预览、模板、回调不能再用。版本变化：经真实业务保存路径产生新版本并触发真实变更通知 → 旧 revision/digest 卡失效，不能只改标签继续显示旧值；重新选当前版本并重新请求后才显示新值。业务扰动与助手写入分开记账。
- **项 7 延迟**：正常路径测量组，同场景同模型同档位，固定 5 个新请求；故障、无模型、文字档不混入；缺事件保留失败记录，不补零、不补跑替换。
- 三档贯穿：自动允许规划展示；少用只有本轮用户控件冻结的明确请求才允许；只用文字不显示内容卡、故障时只保留文字不显示模板卡。少用不能被模型写「请显示卡片」打开；只用文字不能关掉必要确认与拒绝入口。

## 3. 延迟与证据
- 事件：`submitAt`（生产入口接受发送）、`firstTextVisibleAt`（本轮首段非空可读正文完成首帧布局并可见）、`firstCardVisibleAt`（本轮引用当前已保存事实的第一张合格事实卡，必显内容完成布局并在约定视口可见）；两个指标为二者之差。单调时钟，不用测试虚拟时间。首卡来源分记：`host_fixed`（真实生产入口新建、pin 有效，可计时）、`validated_stream`（end + 整份校验 + 宿主复核后才计时）；失败模板、未完成预览、加载占位不计入正常样本。「已保存事实」指业务库，不等于卡片或 UIPlan 已持久化。
- 帧判定：属于本轮请求；RenderObject 已布局、尺寸有效、未隐藏 / 离屏 / 遮挡；必显字段、来源、只读状态成完整子树；动态卡当前宿主呈现有效；取首次满足条件的帧，不在 `pumpAndSettle` 结束后才取。测量用一张能在设备视口内完整显示的小卡。
- 旧 E-1 字段（`first_byte_ms`、`firstEventMs`、`firstResponseMs`）只作诊断或历史可比，不改名冒充「首字可见」。既有本机 < 1500ms、远程 < 3000ms 原样保留，归属未明前不输出混合「首字达标」结论；卡片延迟只记录不设阈值。提交到可见包含确认等待，另记确认次数与时长。
- 五次统计：测量前完成初始化与挂载，不藏热身请求；每样本新任务身份；不因失败删样本；缺打点用 `null` + 原因，绝不填 0；五个都有效才输出中位数（排序取第 3）；否则标「测量不完整」，可另报可测样本统计并写明分母；产品自身重试计入原请求。
- 证据 JSON 字段组：身份（schema 版本、完整候选 SHA、匿名运行 ID、Android 版本、设备与模型显示名）、范围（自动 `[1,2,3,4,7]`、手验 `[5,6]` 待验）、前置检查（结果 + 稳定错误码）、用例（ID、成败、失败阶段、事实来源匹配、业务写入增量、审批回执分类计数）、证据性质（真实上游 / 脚本夹具分开）、延迟（5 个原始样本、旧首事件辅助值、确认等待、有效样本数、中位数与完整性）、故障结果、手验交接、汇总（不自动声称默认开启全部通过）。文件、`binding.reportData`、分段输出用同一份过滤对象。禁止导出：密钥、凭据对象、任何端点、本机路径、调用栈、完整 profile、task payload、原始 ledger / receipt 行、原始模型回答与请求响应体、未审查的异常文本。

## 4. 失败与离线
故障打在**父回答完成后的 UI 规划请求**上，关联到父任务的内部规划任务（PR42 用 `previousAttemptId`、`uiPlanningInternal`、`uiPlanningStream`）。
| 场景 | 构造 | 期望 |
|---|---|---|
| 无模型 | 无 profile 的配置下创建新任务（必须在任务创建时成立），选定事实有效，经实际助手入口触发 | 无出站；宿主离线说明；自动或有效明确请求下显示当前事实模板；无模型成功卡、无业务写入 |
| 真实模型连接中断 | 请求已发出且已收到实际内容后、有效 end 前强制关闭本次连接（不调取消 API） | 出站有失败终态；无最终有效动态卡；原回答保留；按档位显示模板与未完成状态 |
| 用户取消 | 规划运行中点页面「取消」，再释放迟到数据 | 规划任务持久化为取消；无新发送或业务执行；迟到内容不能装 final card；出站收束为取消终态 |
| 生产规划超时 | 让规划请求不完成，等生产 deadline（PR42 默认 15 秒）自行到期；外层看门狗只防挂死 | 记 `planner_timeout`；退路出现前内部任务已完成取消清理（出站可能是 `cancelled`，属正确）；迟到完成不复活 |
- 关闭 `HttpClient` 只证明「真实上游连接中断」，不能写成 Android 已断网；没收到真实内容就失败的样本记「故障前置未满足」。gateway 有 `clientFactory`，但 bootstrap 未透传，需新增仅限 I/O 边界的测试接点。
- 外层测试超时一律是测试失败，不能记成产品超时通过，也不能用测试 timer 主动取消代替生产 deadline。
- 共同断言：有合法当前快照时模板只从宿主快照投影，不读被拒节点；快照失效只显示事实不可用；父回答保留，内部 NDJSON 或未完成草稿不冒充新回答；有过预览的中断保留明确标「未完成」的非交互内容；所有预览和退路无可执行业务动作；失败原因进入宿主执行记录；迟到数据后终态、卡片有效性、写入增量仍符合预期。「没有半截卡片」= 不遗留看似完成、可执行或可恢复成正式成果的半成品；单纯清空画面也不满足 SN-3。
- 另保留 5 个确定性协议场景（可用脚本流，须标夹具证据）：坏行、缺 end、超限、最终校验失败 → 拒绝并显示对应退路；end 后多余行 → 忽略并记 `after_end`。

## 5. 前置依赖与「缺失即失败」
| 前置 | 读取到的状态 | 候选必须具备 |
|---|---|---|
| 生产 stream/2、library-2 接线 | 基线仍用旧 source 且关闭规划；PR42 未合 | 实际生产请求走新 source、真实流、共享编译器、新目录 |
| 三档与持久化 | 仅在 PR42；缺省文字档 | 真实设置入口、生效、保存读回、旧值迁移与恢复 |
| 固定询价本体卡进入对话 | 固定卡与 adapter 已有；PR42 只投影首个选中记录给动态规划，固定卡未接对话与建议区 | 发送后出现关联本轮任务的正式事实卡 |
| SN-3 失败退路与诊断 | 未实现；PR42 失败清进度返回无计划文字 | 模板、未完成标记、执行诊断、三档差异、迟到拒绝可观察 |
| 固定卡持续失效检查 | adapter 有读取时检查；PR42 动态视图有通知复核 | 固定卡 owner 在范围、版本、模块状态变化后及时撤下 |
| 卡片持久化与重启入口 | PR42 inline 用内存 presentation/controller，未接持久保存 | 有实际保存记录与恢复 owner，能把同一数据交给手验 5、6 |
| 帧观测与故障注入接点 | 现有计时不是可见时间；bootstrap 未透传 client 工厂 | 只读观测与受限 I/O 控制，不能注入成功计划绕开生产流程 |
| 同一候选的构建、独审、组合 CI | 前提 | 源码、构建、测试、手验证据指向同一 SHA |
错误分类：`production_stream_wiring_missing`、`real_model_configuration_missing`、`streaming_model_required`、`conversation_fact_card_missing`、`presentation_policy_missing`、`production_fallback_missing`、`failure_diagnostics_missing`、`request_observability_missing`、`latency_samples_insufficient`、`manual_checkpoint_unavailable`。规则：不用 `skip`、空 `return`、catch 后只打印；找不到就不退回旧 source、旧目录、批量 JSON 或独立测试卡；不改私有字段强开功能；前置失败写明阻塞关系，汇总仍为失败；编译即失败时由执行者记录脱敏构建失败，不称冒烟已执行；`MUYON_EVAL_COMMIT` 要与构建来源核对；检查候选中的实际能力，PR 是否合入只作状态记录。本测试只覆盖只读事实卡切片。

## 6. 待用户决定（附推荐）
| 事项 | 推荐 |
|---|---|
| 首字口径与既有阈值归属 | 两种口径同时记录；正文可见作体验指标，旧值作历史比较；阈值归属明确前不输出混合「首字达标」 |
| 「断网」是否须含 Android 系统关网 | 自动套件必测真实上游连接中断并准确标注；如需系统断网证据，由 Haiku 加一项手动禁用 / 恢复网络检查 |
| 首卡「完整可见」的视口定义 | 固定一张在目标视口内完整显示的小卡，冻结方向、字号、键盘状态；长卡另验滚动可读 |
| 对话卡保存与恢复的 owner | 卡片接线任务明确保存对象、时点、恢复入口；复用既有宿主持久化，恢复时重核 scope/pin，不自动执行 |
| 自动测试包重启后的入口 | 用「测量完成 → 待手验」阶段交接，重启打开同一测试数据与真实恢复页面，不重新播种、不发模型请求 |
| 真实模型没产生建议时 | 正常组至少一例有真实非空建议；缺少记覆盖不足，不用脚本建议补；确定性分区测试另行保留 |
| 有效 end 后发生真正传输错误 | 编译结果与传输结果分开记录；保守撤销执行能力并显示故障状态；不混入 end 前中断主用例 |
实现风险：父任务成功可能掩盖规划失败（分开记录）；确认等待可能耗尽 15 秒规划 deadline（记录等待段，不靠放宽授权解决）；证据处理以白名单结构为主控制，APK 与含密钥产物不上传，执行后由 Haiku 实际卸载并验证。
