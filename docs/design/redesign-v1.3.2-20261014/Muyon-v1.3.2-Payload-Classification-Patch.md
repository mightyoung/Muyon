# Muyon v1.3.2 小范围合同补丁：非本体载荷分类

日期：2026-10-13 UTC  
范围：v1.3.1复审I01；只补MD合同，不改产品代码、不运行测试或真实模型/外发。  
判断：缺口成立。v1.3.1已经规定字段Sensitivity与最终投影，但缺少正常用户文本、附件、工具返回和模型自由文本的分类入口及覆盖证明。本补丁不增加敏感度枚举，不改变FullAllow B、unreviewed分类前禁外发及凭据正文禁用决定。

## 一、建议直接插入主册§6的正文

### 非本体载荷也必须有可信分类

Sensitivity仍为unreviewed、none、personal、commercial、credential五值；source_kind、provenance、用户是否明确提供、taint、verification_state是独立维度。user_input、user_selected_attachment、tool_result、model_generated等来源标记不是新Sensitivity值，也不是none、已审或外发许可的别名。用户真实提交/选中只能证明内容来源、当前任务意图及相应输入用途，不能替代凭据检查、现有读取权或其他明确用途限制。

分类对象覆盖最终业务载荷中的全部可披露内容单元：用户文字、附件文本/图片/解析页及chunk、工具/MCP返回、模型自由文本、引用标题/文件名/URL等元数据，以及其历史、摘要、检索、记忆、导出、日志、通知与证据投影。不能只查ontology字段，也不能只检查主正文而漏掉工具history、附件名、错误信息或诊断证据中的秘密。

可信宿主/Rust按已注册、版本化的确定性规则生成分类证据。每项证据至少绑定：

- 内容单元身份、实际字节/规范化内容摘要、来源引用和来源版本
- 来源种类及宿主捕获的来源事件；用户输入另绑定真实user_input_ref或选择事件、任务和scope
- 解析/规范化版本、适用的rule_id及rule_version、规则覆盖到哪些页/chunk/字段/字符区间，未覆盖部分
- 判定的既有Sensitivity类别、继承的来源/用途限制、当前purpose、scope及策略版本
- 本机credential检查的规则版本、complete/incomplete状态及清理结果；证据只留最小原因/引用，不记录秘密样本

这是判定证据，不是模型可填写的approved/classified布尔值。最终序列化前必须核内容/来源版本、规则覆盖和用途仍有效；任何正文、chunk、派生内容或规则版本变化均不得盲用旧判定。规范化和编码前后应有可验证对应，不能在检查后再附加未分类字段。完全由受控模板产生的技术元数据可使用已审模板规则；用户文件名、搜索标题、错误字符串等来源内容不因被放在metadata就自动为none。

### 来源入口与判定方式

| 内容来源 | 可用的可信分类依据 | 无有效依据时 |
| --- | --- | --- |
| 已声明业务对象字段 | 继承固定版本ontology/Q7等可信声明，同时保留实际来源/用途和运行时凭据检查；未知字段不套相邻字段分类 | 未覆盖字段unreviewed |
| 用户在当前任务真实提交的普通自由文本 | 由下述宿主自由文本规则对实际内容完成判定，默认按personal处理；已知commercial等来源分类与更窄限制继续继承 | 解析/检查不完整、内容不在规则覆盖域、疑似秘密无法判定时unreviewed |
| 用户为任务明确选中的附件或其中页/chunk | 选择事件证明该任务输入用途；每个已完整解析单元单独走已注册附件内容规则，可复用受支持文本的personal默认规则；已有商业字段/来源限制不降级 | 未解析页、加密段、损坏区、未知嵌入物/不受支持类型保持unreviewed；不能由“附件已选中”全量放行 |
| MCP/工具返回 | 宿主注册并审定的provider/tool/schema版本及字段/内容规则，结合实际payload分类；服务自报sensitivity只作待核提示 | 无可信规则覆盖的自由文本保持unreviewed，不能换成user_provided来源洗白 |
| 模型自由文本及派生摘要 | 继承输入的来源/用途约束，由明确注册的宿主输出/派生规则独立检查实际新文本；规则覆盖和内容版本须可核 | 模型自报“公开/已审/无密钥”无效；没有可信规则覆盖的部分unreviewed |
| 历史重放、日志、通知、导出与证据元数据 | 复用仍有效的原内容判定及派生关系，按当前目的重新投影；新增包装内容亦有模板或内容分类规则 | 不因“曾发送/只记日志/只是标题”补none或扩大用途 |

派生可合并多个已知类别的限制，但不需要新增一个“混合”Sensitivity枚举；保留各内容单元的已有分类，payload聚合按所有相关类别与限制共同核验。模型摘要、复制、OCR、切chunk、历史恢复或工具包装不能降低来源分类、遗忘/撤权或禁用限制。输出中的新增内容仍需宿主规则覆盖；“来源都已分类”不证明任意新生成文字已经通过credential检查。

### 正常用户自由文本的确定通过路径

定义宿主规则USER-TEXT-v1作为待实现合同：输入来自可信用户提交事件、绑定当前任务与scope；文本解码/规范化完整且在规则支持域内；对实际内容完成本机credential检查；没有已知/命中或疑似凭据信号，没有未处理的继承禁用/失权限制。满足这些条件时，宿主确定性将普通自由文本按personal处理，并记录上述内容摘要、输入引用、purpose、scope和规则版本。它不是none，也不声称文本没有商业含义；对可追踪的商业字段/资料，commercial分类及更窄来源用途继续继承，不能通过粘贴/转述已知来源降类。

这条明确的分类规则使普通用户输入可以完成可信分类，不要求用户逐句选择标签，不用外部模型分类，也不增加审批。FullAllow B下，分类完成且处于当前任务/有效用途内的personal/commercial数据可进入模型或业务载荷，包括新目的地，零额外风险询问；Auto等其他模式仍按各自授权与风险规则。用户输入本身不意味着把它保存为长期记忆、跨任务复用、索引、记日志或向与任务无关的服务外发，这些目的分别检查。

“credential扫描已完整执行且没有信号”是上述有限、版本化规则的一项输入，不是“内容绝对安全”或“已证明不存在任何秘密”。规则应声明检测范围与已知漏检风险；不以必须完美识别所有未知秘密作为普通文本永远无法分类的前提，也不能把未执行、失败、截断、解析不全或疑似秘密误记为“无命中”。

命中可信凭据值/模式的内容单元按credential禁止进入模型/业务正文。疑似秘密但无法确定、扫描/解析失败或超出覆盖范围时，该单元保持unreviewed并给出具体原因；不得让模型自改标签，也不得把普通确认或FullAllow当作解除方法。可在宿主本地按确定规则去除不必要的秘密片段，再对新的内容版本重新检查分类；用户修正输入同样生成新版本，而非给旧版本补一个“同意外发”标记。绑定服务的专用认证通道仍沿既定credentialRef合同，不经过普通正文放行。

### 部分可用与最终投影

分类采用可定位内容单元，不以一处失败自动推定整个会话所有输入不可用。完整覆盖且获准的单元可参与目的投影，失败/未覆盖单元不发送。裁剪后须由宿主核验当前计划及必需字段/来源是否仍满足任务合同：

- 仍可完整执行或已由用户/现有任务合同明确允许部分结果：按当前模式继续，说明实际使用范围和未处理部分，不额外询问FullAllow风险
- 必需内容缺失、语义会改变或不能证明裁剪后仍是原意图：不发送这个不完整业务动作，返回具体缺口或形成新的有效计划；不得让模型先读被禁止内容来判断是否需要它
- 即使全部正文被挡，仍可本机显示不含秘密的具体原因及用户可修改入口；不能把内容全文放进错误、日志或评审证据以解释失败

所有路径共享分类与来源约束，但并非共用同一披露许可：能发当前模型不等于能进日志、导出或长期记忆。最终payload、prompt/tool history、附件转换物、缓存摘要、日志/通知及证据材料各按相应purpose重投影；拒绝结果本身也只含获准最小元数据。分类/过滤是待实现合同，不能把本段写成基线已有完备检测或零泄漏保证。

## 二、三个最小实例（示例，不是已运行测试）

### 例1：普通用户文字可以进入模型

用户从可信输入框发送“请帮我把这份报告整理成三点摘要”。宿主获得真实提交事件和user_input_ref，绑定当前任务/scope；该段UTF-8规范化完整，USER-TEXT-v1覆盖全部文本，本机credential检查complete且无已知/疑似信号，没有继承禁用限制。宿主给该内容版本personal分类证据。FullAllow下，当前任务model用途有效，即可入模型payload，零新增标签选择/确认。报告附件本身仍另按例3逐单元分类，不能因为指令已允许就声称附件已读。

### 例2：看似用户提供仍不能把密钥发给模型

用户输入中混有命中宿主credential规则的API令牌。真实用户来源不把该令牌变none/personal；令牌单元被禁止发送。若令牌与任务无关且宿主能按既定规则裁剪，生成无令牌的新版本重新分类后继续；若任务语义依赖传出该秘密或只是疑似秘密且规则无法确定，保持阻断/未审的具体原因。FullAllow不弹风险确认来绕过；证据仅记录内容引用与规则原因，不保存令牌或泄露性片段。

### 例3：附件部分未解析，不全量放行也不拖死无关输入

用户选10页PDF给当前任务。宿主只成功解析第1–7页；8–10页因加密/解析失败未受规则完整覆盖。1–7页文本逐chunk走已注册规则、继承既有来源分类并完成credential检查；8–10页保持unreviewed且不发送。若任务明确只需第2页，可使用已完整分类的第2页；若任务要求整份合同的完整摘要，不能静默发送前7页并报告“已总结全篇”，须说明缺失页并等待可读材料/新有效任务范围。日志、附件名、页标题和诊断也受同一内容证据与目的投影，不把失败页原文塞入错误材料。

## 三、页册最小同步文案

建议接在S04分类表后；A01/A03附件、工具结果与S06派生内容引用同一条款，不另造规则：

> 用户输入、附件、MCP/工具返回和模型自由文本都显示其真实来源及宿主分类状态，来源不是敏感度标签。普通用户文字经版本化宿主自由文本规则完整解析和本机凭据检查、没有信号及继承禁用限制时，可按personal完成分类，在FullAllow当前任务用途内直接使用；不能因“用户提供”显示none，也不要求逐句手工标类。未知工具/模型内容没有可信规则覆盖时仍未审。
>
> 附件按页/chunk标可用范围：解析或检查不完整部分不送模型；已核可用部分只在满足任务合同或允许部分结果时使用。分类失败显示具体原因、可修改输入或可用替代范围，不显示“确认即可解除”；裁剪后不得伪称任务已完整完成。分类状态、当前用途及版本变化会使旧投影失效，日志、标题、摘要、工具history和证据材料同样受控。

页面状态只投影同一宿主判定：已分类/部分覆盖/未审、credential禁止、失权或用途禁止应分原因显示。是否需要当次授权仍由当前模式决定，不能用“分类复核”恢复FullAllow风险询问。上述状态不等于已核实业务真实性或已完成工程检测。

## 四、精确接入点与证据级别

- 主册§6：在Sensitivity表/现有“最终封包投影”附近插入本节；单元14、D01b沿用，不新增平行能力/授权对象
- 主册D11与记忆/历史章节：引用同一分类/派生合同，来源、用途、遗忘和当前策略不因自动提取而丢失
- 页册S04为唯一页面规则说明，A01输入、A03附件/上下文、S03工具结果及S06记忆/摘要引用；不要求新增页面或独立产品开关
- 只补待实施的合成验收描述：普通文本通过、混credential拒/裁剪重分、附件部分失败、工具/模型伪标签、派生/历史重放不降类、诊断元数据不漏正文、FullAllow无新增确认。此次不执行
- 这是对已定“可信分类后可用”的入口和覆盖合同补全，不新增敏感度类别、常驻访问权、外部分类服务或人工逐次审批。实际分类规则实现/覆盖域/误报漏报评估仍须D01b/单元14冻结和验证，未通过前不声称相应路径可用

## 五、保留的实施限制

有限确定性规则不能保证识别任意形态的所有未知秘密；规范必须保留这个事实，不能以“无命中”作绝对安全证明。缺少trusted规则的外部内容仍保持unreviewed，需要完善规则/解析或合法地换取可分类输入，不能叫模型先外发后分类。无需新产品选择即可补本节；若后续希望允许未完成分类的内容直接外发、由模型自行升格、引入外部分类服务或追加任意跨任务用途，则属于不同决定，不由本补丁授权。
