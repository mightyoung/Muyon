# 本体写卡设计：新建、编辑、关联、批量（CR-2，ChatGPT 6 Pro）

状态：**设计稿，D1～D11 待用户决定** · 代码依据固定 `4483ae0a8179572ef47792c8b845696fbf66b01c`（CR-1 结论引用 `ebf3797`）· 只读静态设计 · 原稿由用户转交，leader A 整理入库：保留全部结论、规则、验收编号与待决事项，代码引用只保留关键位置，细节以原稿为准。

## 总结论
四种写卡统一为：**宿主按本体生成结构、模型只提出草稿值、插件负责领域校验、宿主负责确认与执行、真实回执决定结果**。可复用：本体声明、四个通用写工具（`inquiry_record_tools.dart`）、版本检查、`reg4c` 业务回执。**需新增契约**：提交前完整校验、结构化冲突、写卡接线、原子批量、按「类型 × 操作」的可写字段声明。

| 卡 | 用户核对什么 | 执行语义 |
|---|---|---|
| 新建 | 类型、范围、字段最终值、哪些是模型建议 | 一次确认创建一条；记录 ID 由执行层生成 |
| 编辑 | 当前保存值、本次新值、来源、版本 | 只提交实际改动字段；版本变化重新核对 |
| 关联 | 实际被修改的源对象、关系字段、旧目标与新目标 | 映射为允许的 `ref/refList` 字段更新；解除关联不是删除 |
| 批量 | 记录集合、逐行差异、排除项、整批失败语义 | 推荐同模块同类型同操作同范围的原子批量（新能力） |

两条边界：三档只管呈现，必要的写入确认与拒绝始终存在；外部内容任务保留核对后的单次确认，隐藏持久放行和「全部允许」。报价录价走具名 `inquiry.record_quote`，授标与撤授标仍未开放助手工具。

## 1. 结构
- **可编辑字段 = 本体字段 ∩ 当前操作允许字段 ∩ 宿主支持的编辑器 ∩ 当前用户与范围允许的字段**，任一不满足不生成可提交输入。
- 宿主固定：字段顺序（本体声明序）、必填、枚举、引用目标、可写性、工具、范围、确认摘要、版本、操作 ID、结果。模型只能提议关注字段和草稿值，不能增删字段、改枚举、降敏感度、指定工具、扩大范围。现有字段没有分组 / 折叠 / 只读 / 完整约束元数据，首版用固定字段区；错误、缺失必填、本次改动字段必须可见。关系的 `queryTool` 不能推导写能力。
- 需补最小契约：插件按「类型 × 操作」声明可写字段、创建是否可用、校验入口、关系写入约束、批量能力（现 `BusinessModuleV2` 无通用表单校验；通用工具参数模式是跨类型字段并集）。
- **新建卡**：宿主草稿身份；默认值只来自插件规则或用户选择；创建必需字段不可写且无受信默认值时整卡不可提交；成功后用回执的真实 ID、版本替换「尚未创建」。当前新建 supplier/contact/product/project 需要选择中存在询价全局对象，带 `project_id` 的须属选定项目——不能做成无范围的任意创建。
- **编辑卡**：并列「当前保存值 / 本次拟保存值 / 来源标记 / 校验提示」；`values` 只含改动字段；「未提供=保留」与「显式清空」区分；用户改过的字段不被模型覆盖；无改动时提示无需保存；改成非法输入立即作废旧确认。
- **关联卡**：是允许写入的关系字段的专用编辑视图。`from → field → to` 修改的是 from 对象的 field，从反向入口进入也要说明真实被改对象。候选由宿主检索核对；`refList` 提交完整最终列表（每个成员都要在选定范围内）；范围外目标先经宿主范围选择再生成新确认；解除关联不调删除。「新建后让另一现存记录关联它」首版分两次确认。
- **批量卡**：同模块、同类型、同操作、同范围。行用稳定标识；排除只表示本批不执行；选中集合、值或版本变化即作废整批确认；同一对象重复则拒绝；不自动跳过失败行；超预算提示拆批，每批独立确认。原子批量需新注册复合业务调用：授权绑定整批摘要，插件在同一领域事务检查全部前置条件并提交，任一失败全部回滚（现执行链逐条审批逐条写，失败即停，不具备整批回滚）。不具备时只预览或明确切逐项模式，逐项显示「成功 / 失败 / 未执行 / 结果待核实」。

## 2. 字段类型（`FieldKind` 共 11 种）
| Kind | 控件 | 校验 | 显示 |
|---|---|---|---|
| text | 文本框（可多行） | 字符串、长度、必填；插件规范化（trim/NFC） | 保存值与规范化新值 |
| textList | 增删项；有受信枚举时多选 | 每项类型、长度、条数；去重排序按插件 | 增删项与最终列表 |
| decimal | 保留字符串的精确十进制输入 | 插件精确解析（`ExactDecimal`），禁止浮点往返 | 精确文本，单位单列 |
| integer | 整数输入 | 安全整数、插件范围，不四舍五入 | 整数与单位，零值明示 |
| boolean | 是 / 否（可空时加「未填写」） | 真布尔，不接受 `"true"`/`1` | 三态分别显示 |
| date | 日期选择 + 文本 | 严格 `YYYY-MM-DD` | 不做时区换算 |
| instant | 日期 + 时间 + 明确时区 | 时区与精度按插件 | 用户时区，必要时附 UTC |
| enumeration | 单选 / 下拉 | 只存本体 values 的 key | 标签，必要时附 key |
| ref | 宿主单对象选择器 | 类型、存活、范围、版本、领域约束 | 标题、类型、替换差异 |
| refList | 宿主多对象选择器 | 逐项核验，条数顺序按插件 | 新增 / 移除 / 保留与最终列表 |
| object | 首版只读摘要 + 业务入口 | 无受信嵌套 schema 前禁止通用编辑 | 有限展开，不显示原始 JSON |

缺失、清空、空字符串、零、false、空列表分别处理；规范化改变了值要展示后再确认；`required` 不等于非空列表。现有 typed edit 不覆盖任意文本列表、精确十进制、嵌套对象，需宿主编辑适配。未知 Kind、无可信枚举、引用无目标、object 无 schema、无写工具、本体与工具版本不一致 → 只读退路「此字段暂不支持在卡片中编辑」，只给**实际存在**的业务入口（询价部分类型是 `ObjectPageSupport.none`）。

敏感度：`none` 可写；`personal`、`commercial` 默认遮盖，推荐允许宿主本地显式查看编辑，打开不自动进入模型上下文；`credential` 不进卡片、不接受模型预填、不进确认摘要和复制文本；`unreviewed` 只读、禁止模型预填与通用提交。写卡分开维护「宿主私有草稿值」和「显示 / 模型投影」，禁止把「已遮盖」当新值提交。注意：询价敏感度函数对未特殊分类的字段返回 `none`，新增字段不会自动落到 `unreviewed`。

## 3. 状态机
草稿 → 校验中 → 待确认 → 执行中 → 成功 / 失败 / 冲突 / 执行中·结果待核实；草稿或待确认可放弃 / 拒绝 → 已撤销。各状态按钮：执行中锁定重复提交；失败不自动重试，旧批准不复用；冲突禁用强制覆盖；结果待核实既不显示成功也不显示失败、不解除重复执行锁。任何提交内容变化（包括尚不能解析的输入缓冲）立即作废确认；纯视图状态（展开、滚动、排序）不算，批量选中集合变化算。
冲突用三方差异（基线 B / 草稿 L / 当前 C）：C=B 可保留草稿；草稿未改该字段则取 C；L=C 视为无差异；双方都改且不同须用户逐字段选择。冲突后的提交都形成新草稿修订、新确认摘要、新操作身份；不提供「强制保存」。现工具版本不符只返回普通 `failed`，结构化冲突（稳定错误码、字段路径、当前版本）是新增契约，不靠解析中文摘要。
「撤销」分两种：写入前放弃 → 已撤销；写入后撤回 → 新的补偿操作（新 `operation_id`、当前版本、重新确认），删除有活跃引用仍拒绝，`restore_record` 只恢复删除记录。

## 4. 双重校验
现状：工具 preflight 只做白名单、基础类型、UUID、粗限额；完整 `validatePayload` 在写事务内。所以「已有 preflight」≠ 提交前完整校验。
提交前：确定资格 → 检查形状 → 用可信基线 + 插件默认 + 草稿改动组装完整候选 → 调 `validatePayload` 得到规范化值 → 只读领域检查（关联存活、项目归属、单位币种）→ 生成真实差异 → 冻结确认内容。非法字段就地标出，不调写工具、不签审批。发往更新工具的 `values` 仍只含允许且实际改动的字段。
执行时同一事务再查：工具 / 作用域 / 授权、选定对象身份与版本与摘要、目标状态、`expected_version`、同一校验器、引用约束、未取消；之后才写业务记录和业务回执（保持现在同事务）。
建议新增校验结果：规范化候选、稳定错误码 + 字段路径、表单级错误、已校验草稿修订（丢弃晚到旧结果）、依赖版本证明。现 validator 是 fail-fast，首版可逐个发现错误但必须稳定定位。
来源标签由宿主记录：当前保存值 / 模型建议（尚未写入）/ 用户修改 / 已采纳模型建议 / 已规范化；采纳外部材料中的建议不清除其外部来源。

## 5. 与流式契约的对接
- 推荐：**写卡是宿主插入回答的固定内容块**，与模型 JSONL 节点树分离；单卡复用 `MuyonForm`、受控输入，批量复用表格与 `BatchConfirmCard`。不新增 stream `op`、不另建授权或网关。不让模型直接输出 Form：合法组件树不证明结构来自本体，且现动态字段与确认适配要求已保存事实绑定，无法表达新建。
- 时序：模型草稿先作非执行提案 → 宿主筛字段建草稿 → 流未完成时只读预览 → 有效 `end` 且整体校验通过才激活依赖本流的交互 → 用户编辑后模型不得覆盖 → 流失败保留说明与宿主退路，不从失败流挑合法动作。CR-1 指出的退路缺口（SN-3）是接线前提。
- `UiActionContext` 现只有 `draftRevision`、`draft`、`confirmedRecordRefs`、`operations`。分两层：UI 可引用上下文；宿主私有执行记录（task/card 身份、本体与工具版本、目标、范围与污染证明、基线版本、规范化变更、工具、业务 `operation_id`、确认摘要、审批与回执关系）。每次草稿变化递增 `draftRevision` 并重新发布一致的上下文与动作绑定。
- 动作映射：新建 → `inquiry.create_record`；编辑与关联 → `inquiry.update_record`（加 `id`、`expected_version`，关联提交完整最终引用值）；删除 → `delete_record`（含完整 `referencing_records`）；恢复 → `restore_record`；批量 → 新复合执行契约。没有第五个「关联工具」，原子批量不能靠复用一个旧审批多次调用现工具。工具 ID 与参数映射由宿主 `UiBusinessAction` 提供。
- 三种身份不混用：`operationKeyRef`（UI 引用宿主登记的操作）、`operation_id`（业务幂等，小写 UUID v4，宿主在冻结时生成并持久化，同内容重试沿用、内容变化换新）、`invocationId`（一次工具调用与回执）。
- 回执与恢复：成功必须匹配当前具体操作；恢复先查工具回执，不确定时经宿主受控的只读业务回执查核（需新设计：现执行顺序先查当前选定对象再查业务回执，旧选择证明可能先被拒）；无法确定保持「结果待核实」，禁止换 ID 重发。

## 6. 三档与外部内容
- 自动：回答中直接出写卡（仍需确认）；少用：仅本次宿主入口冻结的明确请求才出卡，否则文字摘要 + 固定编辑入口；只用文字：文字列出对象、改动、缺项，用户进固定宿主编辑页完成，确认 / 拒绝流程仍在。固定编辑页复用同一套本体字段、草稿与校验（插件旧页面可能没有新字段）。
- 呈现偏好与 ADR-0002 权限轴（只读 / 标准 / 自定义）分开；ADR-0002 允许有效授权由宿主签发单次审批，与「写入逐次确认」措辞有差异，见 D4。
- 外部内容任务：新建、编辑、关联保留「仅这一次 + 拒绝」，不出持久放行、不自动消费已有授权、不自动扩大范围；批量只给逐项决定，不出「全部允许」或任何改名等价入口，且不再承诺原子提交。污染事实在渲染、派发、签发、执行前分别核对；clean→tainted/unknown 使旧按钮失效；子任务、重试、恢复继承污染；缺失或损坏的污染记录不按 clean；模型输出、用户采纳、切换固定页面都不能清除污染。

## 7. 范围外
- 报价通用允许字段只有 `quoted_on、lead_time_days、warranty_months、valid_until、notes`；新录报价与改价转 `inquiry.record_quote`；授标 / 撤授标走人工页面（覆盖表 deferred）；不把文档示意的 `inquiry.award` 当作可调用工具。报价整条删除 / 恢复见 D9。
- `merged_into、attachment_ids、source_attachment_ids、capture_mode` 不经通用卡；合并、级联、附件、跨模块事务不从字段编辑推导；无工具覆盖的类型不出可提交卡；「关联报价」不等于授标，预算行引用报价的产品与价格口径校验由插件继续执行。

## 8. 验收（拒绝路径，A01～A52，未执行）
- 结构与字段：A01 模型增删字段或改枚举结构 → 拒绝提案；A02 本体有但白名单无 → 拒提交；A03 模型给的工具 ID、授权、版本、操作 ID 不作依据；A04 不支持的版本或 Kind 只读；A05 创建必需字段不可写且无受信默认 → 整卡不可提交；A06 新建卡伪造已保存事实拒绝；A07 空更新拒绝且不增版本；A08 超预算拒绝不截断；A09 非法 / 超精度十进制或浮点变换拒绝；A10 非法日期、时区、非整数、错布尔拒绝；A11 未知枚举拒绝，空 / 零 / false 区分；A12 不自造列表约束。
- 敏感度：A13 未授权展示 personal/commercial 原值或经模型投影、无障碍文本泄露 → 拒绝；A14 credential 出现在输入、草稿、确认、复制中 → 拒绝；A15 unreviewed 被当 none → 拒绝；A16 占位字符串当业务值 → 拒绝。
- 关联：A17 目标类型错、不可用或越界拒绝；A18 refList 任一成员越界拒整次；A19 反向入口改错端拒绝；A20 解除关联当删除拒绝；A21 用新建回执自动扩大范围拒绝。
- 校验与冲突：A22 提交前校验失败不调写工具；A23 晚到旧校验结果丢弃；A24 改成非法后点旧确认拒绝；A25 模型覆盖用户字段拒绝；A26 规范化值与已确认差异不一致拒绝；A27 版本不符不写库、保留草稿显示差异；A28 冲突后复用旧版本 / 审批拒绝，无强制保存；A29 校验后执行前范围或依赖变化拒绝。
- 流式与派发：A30 无有效 end、坏行、中断、超限 → 新业务动作不可执行；A31 删坏节点后放行剩余动作拒绝；A32 未登记或输入集合不完整拒绝；A33 身份不匹配的旧回调拒绝；A34 视图状态当业务参数拒绝。
- 权限、三档、外部内容：A35 只读模式或写类别关闭不出可执行写提案；A36 模型自报明确请求不能开少用；A37 只用文字下无法确认 / 拒绝不得通过；A38 渲染后变 tainted/unknown 旧放行回调拒绝；A39 外部内容命中长期授权不自动执行；A40 外部批量「全部允许」或改名入口拒绝；A41 恢复或子任务缺污染事实不得变 clean。
- 批量与回执：A42 批内重复对象、混合操作、未确认成员拒绝整批；A43 确认后任一行变化拒旧批准；A44 原子批量任一失败整批不写、无部分成功回执；A45 无原子能力却宣称全成功或全回滚不得通过；A46 同业务 ID 不同参数拒绝，恢复不重复写；A47 超时、断线、回执未知不得显示「未执行」并换 ID 重试；A48 结果对不上具体操作不显示成功；A49 已生效后的取消不直接显示「已撤销」；A50 活跃引用拒删，恢复依赖不满足拒恢复；A51 报价通用创建、改价、授标写入拒绝并给真实入口；A52 不存在的原页面、未登记写工具、未具备的逐项入口不以可用按钮呈现。
