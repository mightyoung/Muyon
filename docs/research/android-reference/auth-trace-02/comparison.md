# 跨产品对比：授权到底在哪一步约束执行

| 维度 | Claude App（本机工具） | Claude Code（远程） | ChatGPT Orbit / 连接器 | ChatGPT DIL 生成式卡片 | Muse |
|---|---|---|---|---|---|
| 谁最终决定 | 客户端：每个工具的 NEVER/ASK/ALWAYS 档位 + g6z.c 输入检查（包内直接证据） | CLI 或服务端（官方说明） | 服务端（未知）；客户端只复用参数摘要一致的旧决定（包内直接证据） | 客户端宿主动作白名单（包内直接证据） | 服务端（未知）；本机审批在客户端挂起等待（包内直接证据） |
| 在哪个执行点检查 | 发请求前（剔除 NEVER 工具）、收到 tool_use 时（k8z.r）、执行前认领（eka.i） | CLI 每次调用工具前（官方说明） | 复用决定前比对摘要（hdb0）；执行点未知 | 触发动作前 | 未知 |
| 审批绑定 | tool_use_id，存在内存待批表；消息结束即过期 | 通知栏审批只带 requestId/toolUseId，**不带输入或版本** | requestId 等六项身份 + **参数 SHA-256 摘要** | 不适用 | 只带 approval_id |
| 防重复 | 本地 INSERT OR IGNORE，**先认领后执行**，同一设备最多执行一次；无参数摘要 | 未知 | 决定层面有摘要，执行层面未知 | 不适用 | 未知 |
| 结果未知怎么处理 | 回给模型"已运行，结果不可用"，**不核对** | 未知 | 有显式文案"无法确认是否继续"；核对调用点未知 | 不适用 | 结果可能是部分生效（PartiallyApplied） |
| 外部内容影响授权 | 服务端会因 prompt_injection_risk 停下；MCP App 界面域名绑定连接器 URL 的哈希 | auto 模式下分类器审查（官方说明） | 网站内容不能授权操作（官方说明） | 不可信 URL 拒绝；特权动作不能回退 | 未知 |
| 仍然未知 | 跨设备重复执行；Stop 后的副作用 | 服务端绑定方式 | 执行幂等性；没有审查器时的行为 | 控制流细节 | 服务端规则；载荷绑定 |

反例和要警惕的地方：
1. Claude 的 INSERT OR IGNORE **确实放在执行之前**。它防住的是"重复执行"，代价是"结果不可知"，并且不按参数区分。
2. Claude Code 的通知栏审批不带参数摘要。
3. 三款产品在客户端都看不到真实的服务端执行状态。
