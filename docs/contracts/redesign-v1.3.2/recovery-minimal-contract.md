## 2 EventCursor：许可投影顺序域

完整 cursor 必须携带 `store_id`、`scope_id`、`stream_id`、`seq`。可比域为前三项全部相等；`seq` 是此许可投影流持久水位。设计已要求十进制字符串表达 seq；范围、规范形式、错误和传输映射由 M03 冻结，本文不选择实现整数类型。禁止依墙钟、HTTP/IPC到达时间、process_epoch、对象 revision 或块数比较进度。

- `store_id` 由可信宿主持有，表示本机存储安装实例；新设备恢复不可继承备份安装身份。两独立库即使 supplier ID 和 seq 相同也不可混投影。
- `scope_id` 限当前已授权范围，不因名称字段低风险而省略。跨 scope 不比较 seq、不泄露受限事件的类型、计数或原审计序号。
- `stream_id` 标识持久许可投影日志；正常进程重启不变，seq 不归零。不同许可投影不共用 stream。旧备份无法保全日志/水位时换 stream 并全量合法快照接入；不能混接旧流，也不能因此重铸原 intent/action/幂等账本身份。
- UI cursor 和 snapshot 水位不是原事实/审计日志序号。去重与相邻检查只在同一已授权投影流成立。合法过滤/合并跳跃须有核心可验证的推进水位/next_cursor并符合快照覆盖；无此依据才作缺口，不机械套原审计 seq+1 或推断隐藏事件数。

事件需先通过存储、scope、日志身份、schema 和当前权限校验才应用。未知安全字段不得忽略后继续执行；精确 schema/enum/未知字段策略由 M03 单源定义。

## 3 ProjectionSnapshot：原子覆盖与激活

必需语义为 cursor 域、`covered_through_seq`、`projection_revision`、`schema_version`、`authority_revision`、`state` 和 `history_completeness`。projection_revision是不透明相等标识，不等于覆盖水位，不能按大小比较；complete仅表示当前许可投影覆盖完整，不代表全审计历史或执行器仍活跃。

核心原子取得 state 与覆盖水位，客户端原子提交对应持久投影及 `durably_applied_cursor`。可用同事务，或经实际故障验证的等价恢复日志；不能先写 cursor 再异步写其数据。内容/头指针布局只能用不可变内容版本与已提交 manifest，或一致事务快照；两事务原地更新正文再换头指针不能证明一致。残缺、环、schema不兼容、摘要不符候选不激活；摘要算法/域不在此另定。

安装前验证域、完整性、schema、当前权限及覆盖水位。当前域里落后于已应用状态的慢快照不覆盖新投影；同水位异状态/摘要或无法证明一致者隔离并核对，不按响应到达先后任选。新 stream 接入只能按可信重新接入流程，不能拿数值更大 seq 证明更优。权限收窄先清除受影响投影，再取得当前许可快照，防止短暂重新显示已撤权正文。

激活后仅应用覆盖水位之后的合格同域事件，移除已覆盖的重复缓冲。独立人工草稿、未送输入、选区/滚动状态不被服务快照覆盖。缓存显示需注明截至水位，活动态重新核对核心/执行器事实；快照不产生业务成功证明。恢复失败标 partial/unavailable，不能补造历史，不能撤销已知成功回执。

## 4 ClientApplyState：接收、应用与持久恢复

`received_cursor` 表示已收到的位置，不保证连续或已应用；`applied_cursor` 表示实际应用边界；`durably_applied_cursor` 表示数据与水位均已提交的恢复边界；`buffer_limit` 是有限资源预算。三者禁止互相代替。重启/重新订阅以持久应用边界恢复，不从最高见过的 seq 跳过数据；ACK是交付/应用进度，绝不是业务成功。不同 cursor 域不得比较这些数值。

正常流：检查身份与权限 → 对同域事件去重/检查合法推进 → 应用对应投影 → 持久提交投影与水位 → 按最终协议确认。提交前崩溃必须能重放，提交后响应前崩溃必须去重；瞬时 received/applied 状态不充当重启水位。相同事件身份异 payload 是冲突，隔离/核对，不用覆盖掩盖分叉。

迟到/乱序流：缺口暂停不可靠增量应用，有界缓冲并从持久应用边界补拉；补不齐、cursor过期或预算耗尽则停止增量，获取原子快照。重连仅恢复查询/订阅，零旧业务自动重提；失败状态需给可安全披露的原因和 resync 路径。

慢订阅：限制事件数及字节预算，设计建议128条或1 MiB仅为待测候选，不能写成产品已定默认。最终阈值、确认点、可恢复错误由 M03/M12测量与协议冻结。任务终态、授权结果、业务效果和回执先持久化，背压不可丢弃；瞬时进度可以合并，须明示其非权威事实。达到预算暂停或断开订阅并告知需补拉/快照；不得无限缓存、静默跳事件或通过重新执行补历史。

## 5 process_epoch 与真实效果分流

process_epoch只核验当前进程/连接相等，隔离旧展示回调；不能按数值排序、重置 seq、替代持久 authority_revision 或证明权限。对象 revision、模式/策略版本另有作用域，均不互比。

旧epoch片段/完成通知/retract不能覆盖当前页面、当前草稿或新代际片段。但带旧epoch的真实 EffectReceipt线索必须走独立核对：按稳定 intent、action/operation、Attempt、规范参数摘要、来源与当前权限查原核心账本，必要时通过当前连接只读取得原回执。不能仅丢弃旧回调就抹掉已提交效果；renderer自报成功或旧回调本身也不足以生成权威回执。

回执核实成功时保存原效果证据，当前可见投影仅显示仍获准的内容；已撤读取权不能借迟到回执回显正文。回执与当前supplier版本分别呈现，原成功不证明当前版本未被后续修改。显示撤回只针对确定scope/片段/版本并留原因，不删除账本或副作用。receipt未知时不预造receipt ID，operation ID不冒充回执。

Stop、导航关闭、解绑、进程退出是独立过程事实：`cancel_requested` 不等于 cancelled；提交前确证取消可零写，提交后取消不能回滚已提交名称；停止未来工作可与成功/unknown效果并存。正文摘要失败、历史缺口、页面关闭均不能改写已确认效果。本草案不另建业务rollback命令。

## 6 PendingInput：送达身份与正文分开

必需语义：`client_message_ref`、`submission_intent_ref`、`delivery_state`、`draft_revision`。状态至少区分未发送、提交中、已确认受理、送达未知；具体enum/wire由 M03 定义。client_message_ref标识一次输入，submission_intent_ref稳定绑定一次发送意图；draft_revision记录编辑版本，不是事件水位。

提交/网络超时以原身份查询受理结果，不新造第二条已确认用户消息；查询无证据保持送达未知，不当作失败自动发。获可信受理证据后才能标送达。若证明未送达且合同允许续办，只复用原发送意图并重验当前事实；修改输入须按真实编辑/新指令合同形成新版本/意图，不仅换key就冒充新指令。正文压缩、快照恢复和模型块重放均不生成新的提交意图。

未送输入/人工草稿独立于可压缩流块，获准保存的正文可恢复；正文是否持久化只服从有效 `chat_retention_policy_ref` 与草稿策略，不因恢复需要无条件保存全文。未获准持久的正文可在进程内保全，但退出后不承诺恢复，须如实说明不可恢复。最小非正文发送身份和必要回执按独立获准审计合同处理，不将它们解释为任意聊天正文保存权。新增留存控制、临时会话、保留期限、崩溃缓冲授权/清理仍待定；不在首片新造默认或开关，保留旧Flutter现行保存事实。供应商表单不是用户聊天消息，不强造聊天turn，但相同的独立草稿/稳定提交身份边界适用。

## 7 名称更新幂等、unknown 与可信新意图

沿用 M02 三项已定领域语义，不在这里重定义规范化：新端传完整raw；UTF-16护栏先于XML检查→trim→NFC→长度规则，具体Unicode等价证据待M04/M05且须在M03冻结前记录。可信用户的新intent即使规范名相同仍执行受控update产生revision+1和独立receipt；同intent双击/重投递/新Attempt或重启重复零第二写、复用原回执。同key异scope/参数摘要冲突，不能自动换key逃过。

名称业务、revision、幂等事实和回执需在同一核心事务提交（M07/M09/M10实现证据待交付）；响应丢失走独立只读回执路径，不能为查回执重新提交已过期的CAS计划或放宽selection guard。可靠回执身份/摘要匹配才认定效果；notFound/unreadable、超时、仅认领无结果都不能单独证明未执行。唯一执行入口和持久派发边界能证明尚未派发则保留未派发事实；可能已派发则unknown先核对，无结果保持unknown，零自动重发。首片本机事务不能据此声称第三方exactly-once。

用户真实明确“再做一次”可建立关联的新业务意图：可信宿主/Rust创建不透明 `acknowledged_unknown_ref`，绑定可审计真实 `user_instruction_ref`、原unknown action/记录版本、当前展示版本、scope、动作类型、规范化目标/参数摘要、新intent/plan摘要。此关联不是授权token或原结果已知证明，精确字段仅由M03/D03单源冻结。模型/ref自填、外部文本、重连、普通确认、超时或切模式不是新指令；仅换key/目标别名/微改payload不能洗掉原效果关系。

新派发前重查原事实、目标/范围、当前权限/用途、真实能力与业务/CAS；变化时更新核对、计划和展示，不盲用旧关联。页面持续内联“原结果未知，本次可能重复”；新intent与新Attempt有独立回执，新成功不将old unknown改为成功或失败。FullAllow合法范围内不加纯风险确认，Auto/每次询问按各自当前模式；真实无权、系统能力限制、非法业务或CAS不通过仍阻断。未知模式细则按D01a标blocked_contract，不用风险暂停代替已定FullAllow零额外问。

旧备份prepared不是零派发证据。换store/stream不改原账本身份；保全当前可用账本/回执并将历史导入标historical/unreconciled，未核对不得续发；完整保全布局与正式恢复演练后置D03/D06/P3。本机导出新副本例外保留既有冻结内容、新exportId/A/B、新目标及真实能力限制；不扩成远端原调用重放或本首片实现。
