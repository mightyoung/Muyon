## 一、产品定位与总体目标

MuSpace（木易工作空间）是一个以个人 AI Agent 为核心的跨端工作空间，连接个人资料、完整业务应用、公共能力和自己的设备。

用户既能打开科研、询价、原型等业务模块自行操作，也能通过自然语言让助手查询、分析和执行获准任务。助手能够使用当前项目、业务对象和选中内容；回答、操作结果与产物可以追溯到原始资料、执行记录和对应业务页面。

MuSpace 是统一安装和使用入口。业务模块在 MuSpace 内保留完整业务流程，公共能力由平台集中建设。目标是减少应用割裂和重复建设，让知识、经验、工作过程与成果持续积累，并在自己的设备之间接续。

## 二、业务功能要求

### 1. 个人 AI 助手

- 支持主对话，以及围绕项目、论文、业务对象的专题对话；桌面可与业务内容并排，手机使用专门页面。
- 使用当前页面和选中对象，在明确范围内查资料、分析问题和调用已注册业务工具；切换项目时同步更新上下文。
- 展示目标、进度、运行设备、等待原因、错误、执行结果与产物。关闭聊天后保留执行记录；暂停、取消、恢复按工具实际能力开放。
- 保存有来源的个人偏好、项目背景、重要决定与经验，支持查看、修改、停用、删除和过期处理。
- 支持后台整理与 Dream 类机制，更新摘要、去重、发现矛盾和提出经验候选；整理不自动扩大权限。

### 2. 科研工作台

- 导入、展示 research-workflow／research-skill 的研究成果，支持手机阅读；管理论文原文件与全文，提供阅读、批注、摘录、精读、检索、限定资料问答和引用回跳。
- 关联研究问题、方向、文献、证据、实验、结论、研究卡和写作提纲，保留现有关系图、提纲、比较与报告能力。
- 记录执行过程、分支变化、接纳或否定结论的理由及不确定性。允许跳转、分叉、重启和否定原方向，不强制按固定科研阶段审批推进。
- 将研究任务、实验任务和输入资料导出到另一设备执行；导入返回的状态、日志、数据和结论，继续人工评估、比较与撰写。保留已有任务包、结果包及研究成果包语义。
- 提供完整研究包交换，保留原文件、研究卡、引用、关系和版本。跨网络支持使用文件包及用户选择的传递渠道，不要求设备在同一局域网。

### 3. 询价与成本业务

复用 software-cost-calculator 的供应商、询价、报价、成本预算、修订及相关真实流程，保留完整业务页面。向助手开放受控查询、解释、比较和确定性计算接口，业务校验与金额规则由询价模块维护。

### 4. 原型业务

支持组织、搭建、展示和管理业务原型，例如 mes-security-model；承接页面、版本及反馈管理需求。已有 Vue 页面可以通过受限 WebView 接入，限制资源访问、导航和宿主桥接，并适配桌面与手机。单页原型的接入不能作为完整业务系统已经迁入的证明。

### 5. 设备通信

支持自己的设备互传文件、链接和研究数据包，以及双方在线的一对一文字聊天和附件传输。展示设备可达性、发送进度、接收确认及结果。接收文件、导入业务、消息已读和人工接纳分别记录。

## 三、产品设计要求

1. **以对话为中心，固定页面为入口。**（2026-10-09 修订）用户主要在对话里完成工作：助手按插件注册的本体生成查询结果、交互小工具和业务表单卡片，并通过注册的工具执行。插件的固定页面保留为固定入口和固定展示，可以从回答或「资料」打开，也可以针对当前对象开启对话，但不再迭代新功能。
2. **以真实业务对象组织信息。** 工作区代表一个实际项目，可以关联多个业务模块。论文、批注、研究卡、询价记录、任务和文件具有稳定身份，对话、通知和执行结果引用这些对象。
3. **科研重记录与分析。** 保留做过什么、依据是什么、为何改变方向和哪些结论不确定。执行完成、人工接纳、证据支持程度分别表达，具体操作仍遵守权限要求。
4. **复用代码与有效能力。** 现有模块迁入同一主体，保留业务规则、页面和交换格式；不要求旧应用继续独立安装或发布。当前没有旧用户数据库，不建设旧安装数据迁移工程；迁入代码和包格式兼容仍需验证，新版本上线后的数据库升级必须受管理。
5. **本地优先与可解释。** 模型不可用时仍能阅读、编辑、检索和管理本地资料；失败和中断明确显示。用户能够查看资料来源、操作影响和实际数据去向。

## 四、总体技术架构与应用组装

采用“Flutter 主体应用＋静态业务模块＋公共能力＋统一接口与工具注册”的模块化架构，支持 Android、macOS、Windows。业务插件是随主应用构建的代码模块，通过代码注册和资源注入接入，不要求动态下载代码市场或模块分别部署成独立服务。

应用按以下结构组织：

- `apps/muspace`：唯一应用入口和组装位置，负责启动、导航、工作区、平台服务、资源管理与设置。
- `packages/muspace_module_api`：稳定的模块契约，定义注册、资源注入、项目会话、对象引用和工具接口。
- `packages/research_module`：迁入科研页面、领域模型、规则、存储操作及交换格式。询价和原型按同一方式组织业务模块。
- 公共文件、解析、检索、模型、OCR 和通信服务由平台创建并注入模块；这些服务按职责组织源码，不强制每项单独拆包。

基础平台承接工作台、消息中心、个人中心、数据与知识中心、接口与工具中心、系统设置六类职责。这些职责可以组合在首页、资料、助手和设置中，不要求六个独立应用或六个主导航入口。

启动和进入模块时，主体负责：打开主库→校验模块 ID、版本及依赖→注册导航、对象跳转和工具→按需准备模块数据库与文件资源→创建模块运行实例→在项目绑定完成后创建业务会话并挂载页面。

首次导入不以“已有业务项目”为前提：模块先展示创建／导入入口，业务项目提交成功后再建立工作区绑定。缺少必要依赖、版本不兼容或升级失败时显示该模块不可用；保留平台设置和其他健康模块的访问能力。

## 五、插件与接口要求

每个业务模块注册以下内容：

- 模块 ID、接口兼容版本、必要与可选依赖。
- 页面入口、路由及业务对象跳转方式。
- 业务对象类型、可关联关系、查询和操作接口。
- 数据库结构声明、版本、定义摘要与有序迁移步骤。
- 公共能力需求、工具效应、权限要求、业务事件、通知和进度信息。

（2026-10-09 补充）模块按契约 v2 声明本体：对象类型、字段（类型、必填、枚举、关联、敏感度）、关系与动作，并用能力覆盖清单说明每个业务操作是由工具开放，还是写明不开放的原因（ADR-0004）。本体是对话中业务卡片的唯一结构来源；插件新增能力时，更新本体与工具即可，对话界面自动跟上。

页面与 Agent 使用同一套领域服务。业务校验、计算、作用域核对和领域数据写入由确定性程序负责；平台提供调用和授权机制，不接管领域业务 SQL。

接口明确定义输入、输出、错误、对象范围和版本，按能力声明进度、取消、暂停、恢复及重试条件。业务页面的每个按钮不必都暴露为工具。Agent 只获得显式注册且获准使用的能力，不自动访问全部数据库或文件。

MCP 等协议用于外部工具适配，内部维持独立、稳定的模块与业务契约，避免绑定某一家模型或 Agent 框架。第三方接口同样需要权限、目的地和结果状态记录。

## 六、统一存储与数据管理

### 1. 主数据与业务数据分库

采用统一管理的多个 SQLite 文件：

- `muspace.sqlite` 保存平台主数据与平台运行记录：工作区、模块及结构目录、项目绑定、设置、权限、对话与执行记录、通知、对象目录、投影进度，以及设备与公共记忆相关记录。
- 每个业务模块拥有一个业务库，例如 `modules/research/research.sqlite`；一个模块库包含多个项目，不为每个工作区复制一份数据库。科研事实、论文记录、笔记、任务、结果、提纲和研究卡由科研模块维护。
- 原文件与附件放在宿主管理、按模块划分的本地文件仓；主库与业务库保存必要记录和引用。
- 全文或向量索引可使用单独的派生存储，例如 `search.sqlite`。它可以重建，不成为第二套业务事实来源。

主数据表示平台共同身份和组织关系，不意味着所有业务中常用的数据都搬入主库。工作区与模块原生项目通过显式绑定连接，跨模块对象使用带模块身份的对象引用。

### 2. MuSpace 统一建立和升级数据库

模块声明自己的结构与版本化迁移；MuSpace 的 StorageManager 统一决定路径，建立、打开、升级和关闭数据库，并提供唯一受管理连接。模块使用注入的资源，不另行打开、迁移或关闭同一库。

主库的结构目录保存各模块目标版本、完整结构声明、定义摘要、观察到的实际版本及迁移状态。模块版本变化时，由宿主运行迁移、验证结果，再更新目录；启动时对账，修复目录滞后。

主库目录用于登记、检查和管理，不作为运行时随意改表的指令源。业务库的真实结构与迁移历史必须核验；同版本不同结构视为漂移，高版本库或升级失败明确阻止该模块启用，不自动清空重建。已有 SQLite／Drift 领域实现可通过适配接入，无需先统一改写存储框架。

### 3. 隔离与一致性

每个物理库只有一个资源管理者和一条写事务队列。异步文件准备、解析和摘要计算在事务外完成，事务内重新核对身份、版本及回执，提交业务数据和对应变更记录。

跨库不依赖外键，也不假定多个 SQLite 文件能够共同原子提交。首次导入采用“主库导入意图＋业务库事务回执＋绑定对账”；业务数据与回执在同一业务库事务提交，主库随后补齐目录和绑定，中断后据回执恢复，避免重复创建或显示虚假成功。

对象目录和检索索引是业务数据的派生投影。业务变化及删除产生变更记录，平台幂等更新投影；真正打开、导出或供模型取材时，再回到领域服务核对对象存在、范围与版本。

分库提供逻辑管理和维护边界；同一进程内的静态代码模块不因此成为安全沙箱。访问约束仍依靠模块契约、资源注入、权限核对和代码验证，受限 WebView 另有访问边界。

### 4. 版本、来源与引用

业务对象保持稳定身份。新增可交换研究卡使用全局修订 ID 和父修订关系，现有任务版本语义通过明确适配保留，不为整合强制改写全部历史模型。

跨设备交换使用稳定的来源项目键和对象 UUID，独立于本地 ID；导入映射和再次导出不改变原对象身份。重复导入、继承修改和并发分叉分别处理，不能以覆盖方式吞掉冲突。

论文引用绑定原文件内容摘要、物理页码、原文引句及必要上下文，位置坐标按实际能力提供。修改标题或作者不改变正文身份；换版保留旧引用，缺原文或无法唯一定位时明确提示。页级回跳与精确文字高亮分别验收。

### 5. 文件与生命周期

区分原文件、提取文本、索引、摘要和缓存，保存生成方式与版本。删除、停用或撤回使用范围时，使相关投影和派生数据失效，并在后续取材前核对，防止后台整理重新恢复被撤回内容。

备份和恢复由宿主协调数据库与文件仓的一致状态，不复制正在写入的裸数据库文件冒充完整备份。传输校验通过不等于业务导入完成，文件缺失不能显示完整成功。

## 七、Agent 执行与工具调用要求

平台保存 Agent 执行记录，与科研任务、实验运行和导入事务回执分别建模、通过引用关联。记录包含目标、上下文快照、对象版本、工具、模型端点、运行设备、阶段、等待原因、权限决定、结果和产物。

调用流程为：识别任务→筛选能力→提出调用→核对参数、对象范围与权限→按分级授权取得确认或命中用户授予的放行（ADR-0002）→执行→核验结果→保存记录并返回对象或产物引用。用户界面和模型资料不能绕过这条业务路径，资料内容和模型回答本身不能授予权限。

聊天与执行记录解耦。进程退出或设备失联后，记录能够解释中断；真正继续执行需要工具支持检查点、状态查询或幂等重试。问答支持取消后续处理、保留记录和重新发起；无损续算与暂停仅在执行工具实际支持时提供。

结果不确定的外部写操作先查询核实再决定重试。取消时说明已发生的动作与未继续的部分；本地取消不能冒称远端动作已经撤销。

工具选择保留可替换层，评估 Jev、Laya 等有限候选方法，保留规则与大模型回退。选择工具、生成参数、授权和执行分别负责，模型置信度不能替代权限判断；尚未选定生产决策模型。

## 八、记忆、经验与 Dream 要求

分别管理原始资料、领域事实、主题记忆、摘要和经验条目。业务事实仍由所属模块维护，公共记忆引用来源，不复制出另一套未经对账的事实库。

记忆包含来源、作用域、时间、修订及事实／推断标识。用户能够纠正、停用、删除和设置过期；矛盾能够回查依据，删除和使用范围撤回传递到后续整理及取材。

后台整理支持增量归纳、去重、摘要更新、冲突识别和经验候选生成，记录变更与资源消耗，允许审阅和撤回。经验经过验证后再参与任务，不凭一次成功推广为通用规则。

记忆和经验不替代授权记录，Dream 不扩大工具权限。

## 九、模型、OCR 与检索要求

- 模型接入覆盖本机、本人其他设备和用户指定的远程服务。模型配置记录实际端点、位置、能力与凭据引用；凭据使用系统安全存储。明确问题、片段、文件等出站范围，失败不自动更换云服务或发送目的地。
- 兼容接口采用能力明确的适配器，逐项验证对话、流式、工具和向量接口；协议兼容不代表功能完全相同。本机地址仅表示第一跳，是否继续使用云代理仍需说明。
- 可靠 PDF 文字层优先提取；扫描页或缺失区域使用 PaddleOCR 识别。保留页码、解析方式、版本和可用定位信息，模型与运行方式通过目标设备及论文场景测试确定。
- 支持关键词、离线全文、向量及组合检索，按项目和选定资料限定范围，专门验证中文短词与中英文混合查询；索引失败、过期或受限扫描明确显示。检索策略依据同语料收益及资源成本确定。
- 限定资料问答冻结范围并核对来源。引用可点击不代表答案得到支持；验收同时检查定位、关键断言支持和应答／拒答质量。无充分证据明确说明，不靠一律拒答通过验收。

## 十、多端通信与数据交换

设备发现、可信配对、通信授权、文件接收与业务导入分别处理。设备名称、同一 Wi-Fi 或可发现性不代表可信，在线通信需要设备身份验证和加密传输。

在线传输使用流式处理、长度和摘要校验，展示进度、接收确认、失败及重试去重。消息送达、附件持久接收、业务导入、已读和结果接纳保持独立状态。

跨设备任务包明确任务身份、输入版本、执行设备、权限范围和预期结果。返回结果按任务与修订归属到真实项目；传入包不自动授予执行权限。接收方取得本机授权后执行，不能仅因导入或联网就自动运行。在线任务调度必须明确执行归属、状态查询和重复执行控制，避免两端重复执行同一操作。

跨网络接续支持文件包和用户选择的传递渠道，不以公共云或同一局域网为前提。在线一对一聊天与文件／链接交换要求双方在线、已认证且通信路径可达；无法直连时明确说明状态，不承诺无需中继就能穿透任意网络。文件传递与业务导入相互独立，不能用传输机制隐式覆盖业务数据。

手机与桌面的后台行为遵守操作系统限制。退出、休眠或网络中断时明确标记状态，不承诺所有设备都能持续后台运行。

## 十一、页面与体验要求

桌面采用清晰导航、中央业务内容和可收起的上下文助手。手机底栏 4 项：助手 · 任务 · 资料 · 设置（2026-10-09 决定）；使用明确的返回关系。

（2026-10-09 修订）以对话为中心：常用的查询、比较、新建与编辑在对话中以交互界面完成（AI 原生界面方案）；内容多、需要长时间编辑的工作在「工作区」打开；插件的固定页面保留为兜底入口。原文「避免将所有操作塞入聊天」改为：不把操作塞进**文字**聊天，而是由回答生成合适的界面。对象跳转保持项目与来源上下文，关系图用于理解依据和关联，点击能够回到实际对象。

形成统一设计系统：浅色层次清晰、深色克制、阅读排版稳定，动效适度并支持减少动态效果。验证窄屏、大字体、键盘操作、空状态、失败状态和真实设备阅读体验。

## 十二、质量与验收要求

以真实业务结果验收：资料能找回、引用能定位、业务规则和计算有依据、操作有结果、权限生效、文件与跨端数据完整，结果能够回到对应页面。

验证离线、重复导入、两项目隔离、首次导入中断、数据库升级、索引过期、原文换版、取消与错误状态。跨库提交、文件传输和远端执行不能把“已开始”或“局部完成”显示成完整成功。

完整研究包独立于任务／结果包验收，验证不同本地 ID 的跨设备往返、来源身份不变、引用闭合、重复导入和并发分叉；同名或相同本地 ID 不得错误合并不同来源对象。

区分文档审查、自动测试、平台构建、真实模型验证和真机业务验收。构建成功不能代替真实业务流程和设备体验验收，固定语料问答通过也不等于普遍科学正确。

科研验收覆盖完整业务链：在实际项目中导入研究成果和论文，阅读、检索并保存批注与研究卡，进行限定资料问答，创建任务并导出，在执行设备完成后导回结果，人工接纳、关联提纲并导出报告；退出重开后资料、决定和关联仍然存在。保留完整业务页面及分支流程，不能只验证一条演示路径。

Android、macOS 和 Windows 分别验证构建、真实业务流程、平台文件操作和设备体验。具体依赖、模型与性能指标以实际验证确定，功能状态与验证证据明确记录。
