## 1. 依赖关系

```
第一阶段收尾 ─► 第二阶段：内核 + 授权 + 外壳 ─► 第三阶段：契约 + 数据中心 + 知识 ─► 第四阶段：常驻与生态
```

- **Agent 内核 v2** 是第二阶段的关键路径：助手界面（UI-3、UI-4）要等内核和 AUTH-1，否则界面做两遍。
- **模块契约 v2** 与数据中心的本体声明是同一件事（对象类型、关系、查询接口、动作、流程、敏感属性；Folio 已有 `supplier_core/lib/src/ontology.dart`），合在一份契约 ADR（ADR-0004）里设计，UI-8、UI-9、DC-1 共用。
- **设计系统 UI-1** 在所有界面任务之前。

## 3. 第二阶段：内核、授权与外壳（5–6 周）

目标：在新外壳和分级授权下跑通询价 North Star，确认次数显著下降。

| 泳道 | 任务（暂定编号） | 执行 | 顺序 |
|---|---|---|---|
| 内核 | **K-1** ADR：模型适配层（能力声明、流式、原生工具调用；替换自定义 JSON 协议）→ **K-2** 实现 → **K-3** 预算式 Agent 循环（取代 4 轮 / 45 秒）→ **K-4** 执行记录事件化（`task_events`、`task_objects`）| senior | 串行，关键路径 |
| 授权 | **AUTH-1** 授权表、`ToolRegistry` 授权解析、模型请求按位置分级、内容审查接口（默认不审查）；界面部分（「助手权限」页）拆给 engineer | senior + engineer | K-2 之后 |
| 体验 | **UI-0** 现状截图 → **UI-1** 设计系统（v4 token + `warn`）→ **UI-2** 新外壳 → **UI-5** 工作台、**UI-7** 设置 → **UI-3** 收件箱与确认卡、**UI-4** 助手栏（等 AUTH-1）| engineer | UI-0～2 与内核并行 |
| 评测 | **E-1** 在 140 题之上加多步任务（含写入审批），指标：任务成功率、审批次数、首字时延、成本；内核每次改动都跑 | junior / engineer | 与 K-1 同时开始 |
| 取证 | **R-1** Android（vivo V2324A）重跑 North Star | engineer | 任意时间 |

退出标准：
1. 只读任务审批次数中位数 0，写任务 1（E-1 测得）。
2. 首字时延：本机 < 1.5 s，远程 < 3 s。
3. 询价 North Star 在新外壳下有真机 + 真实模型证据。
4. 授权测试齐全（过期、撤销、范围变化、防重放、审查器各结果），CI 绿。

## 4. 第三阶段：契约、数据中心与知识（6–8 周）

| 泳道 | 任务 |
|---|---|
| 模块 | **ADR-0004** 模块契约 v2（导航分区、工具注册、对象类型 / 本体、检索来源、结果渲染器、敏感属性标记）→ **UI-8** 科研、原型接入 → **UI-9** 询价换壳（单独分支，`inquiry_*` 与 North Star 测试全绿为门槛） |
| 数据 | **DC-1** 数据中心平台化（6 项检查、同步到助手知识库与回滚、示例问法评测）→ **DC-2** 血缘 → **DC-3** 实例浏览器与敏感属性遮盖（三端后台遮盖）→ **AUTH-2** 外传内容审查实现 |
| 助手 | **记忆 v1**（抽取候选、收件箱、相关度注入、Markdown 导出）· **AS-1** SOUL · **AS-2** 规则配置 · **统一知识服务**（段落切块、FTS5 + 向量混合检索，合并两套检索） |
| 平台 | **UI-6** 数据交换（合并两套局域网传输）· **iOS**（采集、阅读、遥控端）· 去掉 `supplier_core` 自带 LLM 客户端 |

退出标准：新增示例模块宿主零改动；科研问答引用定位正确率 ≥ 95%；至少一个插件通过 6 项检查并同步到知识库；iOS 构建并真机运行。
