# 第一阶段（P0 稳定与取证）执行计划

日期：2026-10-05 · 负责：leader · 合入目标：`develop` · 依据：[深度研究报告 §6.6–6.7](../../reviews/2026-10-05-muyon-deep-review-and-optimization.md)、[ADR-0001](../../adr/0001-leadership-and-scope-freeze.md)

本阶段只做能自动验证、能取证的工作，不改产品行为。范围冻结与退出标准见 ADR-0001。任务派发与状态以 [docs/tasks/README.md](../../tasks/README.md) 为准。

## 工作项

| 编号 | 工作 | 执行 | 产物 |
|---|---|---|---|
| P0-1 | PR/push 自动门禁 | engineer | `scripts/ci.sh`、`.github/workflows/ci.yml` |
| P0-2 | LLM 原生工具调用基线 | senior engineer | 评测代码、夹具测试、按环境变量运行的真实评测 |
| P0-3 | 询价 North Star 纵向链路 | senior engineer | 链路测试（无头 + 设备）、证据 JSON、运行手册 |
| P0-J1 | 取证环境自检脚本 | junior engineer | `scripts/doctor.sh` 及测试 |
| P0-4 | 真机与真实模型取证 | engineer | 证据 JSON、基线报告、证据汇总 |

## 各执行者的顺序

- senior engineer：P0-3 → P0-2
- engineer：B 2.4（在途）→ P0-1 → P0-4
- junior engineer：E11（在途）、P0-J1

P0-1～P0-3 最初在云端开工，按 ADR-0001 停止后，未完成的成果已作为 WIP 提交保存在各自的任务分支上，任务说明里写明了交接状态。

## 询价 North Star 链路（P0-3 范围）

1. 宿主启动，激活询价模块。
2. 用模块自己的领域函数写入夹具数据：项目、预算行、两家供应商报价。
3. 助手只读查询：比较报价、项目预算。
4. 助手提出写入，例如创建询价单。
5. 宿主审批。
6. 写入生效，并能在业务对象上查到。
7. 关闭后重开，记录、任务和出站账本仍在。

模型端点由 `MUYON_EVAL_MODEL_*` 环境变量提供。未提供时使用回环夹具模型，并在结果里标明「夹具，不是真实模型证据」。

## 合并规则

- 任务分支经 leader 审查（`review/<编号>`）后合入 `develop`。
- 合入前，执行者必须在本机跑过相关包的 analyze 与测试，并在提交说明中贴出摘要。
- 不得修改已有测试来换取通过。
