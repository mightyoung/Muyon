分支 `task/k-3-budget-loop` · 依据：[ADR-0005](../adr/0005-model-adapter-and-agent-loop.md)（已采纳）§6、§6.3、§6.6、§8.2、§8.4 · 约束：[ADR-0002](../adr/0002-graded-assistant-authorization.md) §3 · 前置：K-2a 已合入（[审查](K-2a-review.md)）· 执行：Sonnet 5.5 子代理（leader 派发）· 审查 leader · 阶段：第二阶段

## 交付（ADR-0005 §8.2）
1. `assistant/agent_budget.dart`：`Budget`（步数、活动时长、token；等待确认不计活动时长）；默认 `maxTokens` 200 000、`maxSteps` 4（AUTH-1 之前）；`maxRounds` 作为 `Budget.maxSteps` 的别名，getter 保留（`north_star_chain.dart:422` 使用）；耗尽时任务 `failed` 并附小结（`personal_agent_rejections_test.dart:369-388` 的“轮次”文案仍成立）；单请求绝对上限经 `chatStream(maxDuration:)` 传入（剩余活动预算与 5 min 取小）。
2. `personal_agent.dart`：以单步状态机（§6.2 S0～S5）驱动；并行执行只读调用；写入 / 外传进**批量确认卡**（§6.3）：每个调用各自字段、默认全选、`confirm(selectedInvocationIds)`、取消某项默认连带其后各项并可重新勾选、按模型顺序逐个 `prepare` → 比对 `identityDigest` → `approve` → `invoke`（每调用一次性审批与回执）、前一项失败后续不执行、批内范围变化 → 后一项 `stale_scope` 失败并停止、单调用时 `requestDigest == identityDigest`、每卡最多 5 个调用、卡过期 / 取消对整张卡生效；新载荷键只增 `toolCalls`、`toolSelection`，§8.2“载荷兼容”所列键名称与含义不变，`AlwaysConfirmGate` 下每步仍回到 `waitingConfirmation`。
3. 原生模式允许一次回复多个工具调用（K-2a 视为违规的限制在此放开，按上条处理）；合成 `tool` 回填保证每个已保存 `callId` 有且只有一条 `tool` 消息。
4. `ContextCompactor`（§6.6）：S0 触发（声明的 `contextTokens` × 0.8 减输出预留，95% 硬上限）；阶段 A 本地清理旧工具结果（保留最近 3 对，释放 ≥ 15% 才做）；阶段 B 一次摘要请求（`stage = 'compaction'`，经闸门、账本、`OutboundChannel`，同一 profile 或更小暴露面 `local < ownDevice < remote`，不发新端点，工具结果与历史以“引用数据”包裹，摘要上限 2 000 token，对象与引用部分由宿主生成）；阶段 C 原样保留系统提示、记忆块、最近 2 个用户回合（至少 6 条）与当前步；永不压掉待决审批与预览、未执行调用、引用锚点（`references` 不动、`rN` 不重排、压缩后重放引用表）；原始消息永久保留，发送视图为 `f(完整消息, 压缩状态)`；`requestDigest` 与预览覆盖实际发送的压缩视图；摘要失败退回只做阶段 A，仍超硬上限则 `context_too_large` 失败；手动压缩入口（接口即可，按钮留给 UI 任务）。未声明 `contextTokens` 的 profile 不自动压缩（North Star 与现有测试不受影响）。
5. `assistant/agent_event_sink.dart`：`AgentEventSink`（载荷实现），含 `compaction` / `compaction_failed` 事件；K-4 再落表。
6. E-1 跟进（[K-2a 审查](K-2a-review.md) 遗留）：`agent_eval.dart` 的 `RecordingGateway` 覆写 `chatStream`，记录首事件时间与 `Usage`，使流式 / 原生 profile 的评测数据不丢失；加一个测试。
