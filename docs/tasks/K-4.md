# K-4 执行记录事件化（后端）

分支 `task/k-4-task-events` · 依据：[ADR-0005](../adr/0005-model-adapter-and-agent-loop.md) §6.5、§8.3 与 §6.5“K-3 实现注记”；深度研究报告 §6.4.4 · 前置：K-3、K-3b 已合入 · 执行：Sonnet 5.5 子代理（leader 派发）· 审查 leader · 阶段：第二阶段

## 交付
1. 主库迁移（只追加）：`tasks`、`task_events`（`task_id, seq, at, type, payload_json`，主键 `(task_id, seq)`）、`task_objects`（`task_id, module_id, object_type, object_id, role`）。迁移号与 K-2a 的 v7 衔接，读取 `workspace_repository.dart` 现有迁移表确定。
2. `AgentEventSink` 的事件表实现：事件与任务状态更新**同一事务**（`foundation_repository.dart` 的 `createTask` / `updateTask` / `appendTaskEvent`）；`seq` 单调；事件不含正文与密钥（沿用 K-3 的事件字段）。K-3 的“事件存在载荷 `events` 里”改为写表；旧任务载荷中的 `events` 只读兼容。
3. `task_objects`：工具回执与回答引用中的对象写入，支持“对象 → 相关任务”反查（只读 API，界面留给 UI-5）。
4. 恢复“从最后检查点继续”：`resume` 依据事件与已有回执，**不重复执行已有成功回执的写入 / 外传工具**（同一 `invocationId` 的回执已存在则直接取用）；无法判定时停在 `waitingConfirmation` 并说明原因，不静默重放。
5. `assistant/execution_store.dart` 与助手读取路径改为读事件表（兼容旧任务）。

## 约束
- ADR-0005 §8.4 守护测试与 `north_star_chain.dart` 不改；载荷键名称与含义不变（§8.2）。
- 不做界面（时间线留给 UI-3 / UI-5）；不做授权（AUTH-1）。
- 不放宽 ADR-0002 §3；恢复路径不得绕过一次性审批。

## 测试
事件与状态同事务回滚（模拟写失败）；`seq` 单调与并发追加；旧任务载荷 `events` 读取兼容；`task_objects` 写入与反查；从检查点恢复不重复执行已有回执的写入；无法判定时停住；迁移幂等与 v7 → 新版升级；E-1 夹具通过。

## 验证
`flutter analyze` 无问题；新测试与宿主全量通过（贴数量）；变异至少覆盖“事件与状态分开提交”“恢复时重复执行已有回执的写入”“seq 非单调”。
