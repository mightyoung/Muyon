## Field contract

- UI submission: bounded request_id, conversation_id, text only. Separate AIDL/UniFFI submitOrdinaryChat method. UI does not supply workspace, approval, classification, endpoint, price or key. Preference namespace v2 does not reopen old chat identities.
- Rust intent payload: intent=ordinary-chat-v1, conversation_id, text. Supplier payload remains text/key/revision. Current trusted chat authority supplies workspace_id, authority_owner, mode, policy_revision, grant_revision, rule_revision, model_allowed/outbound_allowed and active state; absence denies. Rust creates actual task/attempt and input_ref from the admitted run/request, binds those with conversation/workspace to the frozen send evidence. Default mode Auto; explicit valid FullAllow accepted without extra questions. This slice only executes host-granted model/outbound purposes; mode never manufactures a grant.
- USER-TEXT-v1: complete bounded UTF-8 input with no control/unsupported normalization, versioned deterministic local credential-pattern scan. Known/suspected credential signals deny with minimal reason, never echo text in errors. Plain text becomes personal, not none. Rule version and exact bytes remain bound; no history, attachments, supplier references, memory or tools are implicitly included. Finite scanner coverage/residual misses documented.
- Frozen wire body: exact configured model, one user message of the checked text, n=1, stream=false, max_tokens from trusted call bound; no arbitrary fields. Frozen evidence also binds current provider profile/revisions, workspace/task/input, authority facts and handle identity/generation. Existing ServiceProviderBridge prepares/reserves/final-admits those same bytes through the same durable owner. Commit is admission metadata, never claimed as provider success.
- Credential capability: new controlled opaque identity+generation callback, separate from existing existence sentinel. Ordinary chat cannot use the sentinel. No secret-reading API. Rotation/revocation between prepare/commit/send rejects. Existing admission probe remains metadata only.
- Transport: owner-only one-shot exchange of a committed admission. Same owner atomically rechecks current binding, scope/authority, payload and credential generation, records attempted before fake handoff. No refund/retry after consumption/attempt. Only bounded plain answer/usage supported; tool/multiple-choice/oversize/missing usage rejected. Fake usage/ceiling explicitly synthetic, not an invented real price/currency limit. Production transport absent and missing model/currency/ceiling/price proof deny.
- Durable ledger: dedicated new ordinary-chat schema/file; no existing app/task database. Persist pending send/evidence before handoff, response and admission identity after. Interrupted sends become outcome_unknown, never replay/reopen/resend. Disclosures recheck current workspace/policy/input identity. Chat success has answer_delta + provider_receipt + terminal; no fictitious supplier projection or ToolRegistry receipt. Provider receipt is admission/response correlation, not a supplier-read receipt or real payment proof.
