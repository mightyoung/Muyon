## Files and interfaces

UI chooses existing host references; it never accepts a key or arbitrary credential text. Save is local-only and performs no network/native Agent invocation. Main has no installed SearchHost/connection catalog and reports disabled/unconfigured/notready. Synthetic variant advertises only its fixed fake connection and says awaiting Service validation, never real availability.

Existing UI files: LocalPages.kt and MuyonLabShell.kt settings entry; ChatReadContract.kt and AgentChatReadSession.kt generic tool_projection/tool_receipt closed events; ChatPage.kt source/empty/error/currency display. Every ordinary Send retains the same frontendSubmit→ChatReadPort→Binder submitOrdinaryChat→GeneratedAgentController→Rust Service controller chain. No search button, probe path, direct UI native execution or second queue.

Core additions: provider-neutral RegisteredChatRoute trait in new rust-agent-host service_tools.rs. ServiceHostPorts gets optional route injection with default None, avoiding a reverse dependency on web-search. Trait prepares an immutable configuration route snapshot, executes within the existing admitted run/worker/control/receipt/root, and revalidates current configuration/purpose/receipt before disclosure. The only fields are generic Json input/route and bounded result/receipt, never raw secrets, HTTP adapter or a model fee interface. Existing ServiceProviderHost, CallBudget and chat owner callback are unchanged. A new registered-chat source version is explicitly separated from ordinary-chat history, so tool results cannot be silently laundered into ordinary raw historical user/assistant pairs. Resume/restore never executes; interrupted/incomplete evidence becomes unknown.

Bridge additions: separate registered_tools.rs adapter and callback for nonsecret settings snapshots; additive private Service-bootstrap constructor installs the optional route. Existing with_host and credential callback remain unchanged. Genuine UniFFI generation updates the generated Kotlin binding. Main uses an unavailable executor; only isolated searchFixture Application installs the socket-free executor. GeneratedAgentController.open and AgentRuntimeService bootstrap wire the settings port without changing controller retention, queues, lifetime, private root or admission semantics.

Web-search additions: RegisteredChatRoute implementation built on existing SearchRuntime, Catalog/Enrollment and actual core Agent. Expose the existing controlled in-process NativeSession constructor for this trusted composition (same RunControl); never spawn a plugin process on Android. The synthetic model selects a registered generic tool and the synthetic SearchHost exercises the real DeepSeek wire encoder/decoder. No real owner/TLS implementation is introduced; SearchHost stays a pending integration boundary. The same route metadata can later install a real owner only under the separately coordinated owner contract.

## Required behavior

Settings save cannot make an unavailable host ready, grant authority/budget, resolve secret bytes or send a probe. Enabling search freezes its route/config generation at request admission; changing settings cannot reroute/retry an old identity. When disabled, ordinary chat follows the inherited path; when enabled but unconfigured or without host, ordinary Send returns an explicit failed terminal via the same Service path, with no model/search call and no fake response. Config corruption is not silently treated as disabled.

For the synthetic configured variant, ordinary Send triggers the registered tool through the same durable Service worker and actual core Agent. Results carry real fixture URLs/provider/request/rank, empty results are explicit success, and controlled errors are visible. All results are tainted/instruction_authority=false; UI text/links are not instructions, auto-fetched icons or new grants. Cost is clearly a synthetic ledger estimate, never a real bill. Query, projection and derived answer use the prior exact owner-review/mode/credential path; source/cost/answer disclosure clears on transport/authority loss. Final receipt validation binds request/run/epoch/task/attempt/config/source result; stale configuration, missing/corrupt evidence or partial envelopes hide disclosure and do not resend.

Final exact SHA/terminal CI and independent source/whole-test/claims review; physical device, real SearchHost/TLS/account/paid calls remain NOT_RUN.

Independent design review corrections: prepare runs before queue admission and freezes the bounded closed route snapshot; an already known request returns its frozen intent/query and never re-prepares from new settings. Main always installs a settings-aware unavailable router: only an explicit disabled snapshot returns None, while corrupt/enabled-unconfigured/enabled-nohost freeze a failed route. RegisteredChatRoute has separate prepare/execute/restore/disclose duties. Restore parses the original record and native receipt without executing or choosing new settings; disclose rechecks current configuration/mode/handle/source/purpose and exact stored answer/projection/receipt bindings. UI disclosure loss clears sources/empty/currency/cost/answer while retaining historical admitted epoch/identities for lookup. Executor factories are Send+Sync and construct thread-local Rc adapters only inside the existing worker. No extra executor thread/queue/root is introduced.

Implementation review correction: frozen route also binds the exact registered arguments, scope and connection refs; generic verification cross-checks native dispatch identity, while the provider route passively validates the complete closed synthetic outbound record (query, config, task/attempt/call, handle generation/identity/reference, status, currency and cap). Missing/tampered evidence hides disclosure without resend. Config save uses a fresh 53-bit random generation rather than resetting a counter after corrupt settings; generations are equality tokens, not monotonic ordering or authorization. The new Service root census explicitly admits only registered-result.db and search-outbound.db plus their existing bounded atomic temporary pattern; other unknown files remain rejected.
