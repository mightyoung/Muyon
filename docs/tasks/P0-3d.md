## 背景
P0-4 用 deepseek-chat 跑询价 North Star 链路（无头），两次都在预算题失败，任务结果 `failed`，错误为 `FormatException`：
- 第 1 次：模型提议 `inquiry.project_budget`，工具执行成功；下一轮的最终回答是**纯文本**（数字正确：2080），不是助手协议要求的 JSON。
- 第 2 次：第一轮回复就是 DeepSeek 原生工具调用标记 `<｜｜DSML｜｜ calls>…`，没有工具被提议。

证据：`review/P0-4` 上的 `docs/evidence/2026-10-p0/north-star-macos-headless-deepseek-chat*.json` 和 `docs/implementation/p0-evidence-2026-10.md`「D1」。不修复就得不到 `passed: true` 的真实模型链路证据（第一阶段退出标准第 1 项）。

## 要求
1. **先找根因并写下来**（放在提交说明或本文件末尾的「执行记录」）：助手发给模型的请求是什么形态（是否带 `response_format`、系统提示里怎样描述协议），为什么 deepseek-chat 会回纯文本或原生工具调用标记。
2. **最小修复**，可选做法（自行选择并说明理由，可以组合）：
   - 对 OpenAI 兼容端点请求 JSON 输出（`response_format: {"type": "json_object"}`，`supplier_core/lib/src/llm.dart:80` 已有先例）。端点因不支持该参数返回 4xx 时，要有明确的处理，不能让原本能用的端点变得不能用；
   - 解析失败时做**至多一次**纠正重试：把「上一条回复不符合协议，请只回复协议 JSON」作为新一轮发给模型。
3. **安全约束（必须满足）：**
   - 不符合协议的回复**永远不能**变成工具提议或写入，也不能绕过确认；
   - 每次重试都经过网关，账本里能看到；重试次数有上限并有测试；
   - 错误文本不引用模型原文（与 P0-S1 R2 一致）；
   - 不把纯文本猜测解析为 JSON，不剥离 DSML 后再执行其中的调用。
4. **O1**：链路脚本 `apps/muyon/integration_test/support/` 中，预算题的 `answerPreview` 取到的是工具说明文字而不是模型回答，一并修正。
