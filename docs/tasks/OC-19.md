# OC-19：confirm_binding 在刷新导入新增候选后的行为特征测试

## 依据
CR-15（`docs/reviews/2026-10-11-pr49-reg3cf-reg3d-review.md`，在 `task/cr-15-17-chatgpt`）「记录的非阻塞边界」：批准确认 (D,P) 时 D 有 P、Q 两个待消歧候选；随后正常刷新导入新增候选 R，但 D 字节与 P 的六字段摘要不变（`ambiguous` 只记是否 >1），旧审批仍可确认 P 并删除 Q、R。这符合 GB-2「选择目标后删除竞争候选」语义，建议用一条测试锁定，以后产品若要求「候选集合变化需重确认」再改。

## 要做
新建 `apps/muyon/test/oc19_binding_candidate_refresh_test.dart`，搭法照抄 `apps/muyon/test/reg3d_research_writes_test.dart` 里 `research.confirm_binding` 的测试与其导入夹具。
1. `confirm_binding still confirms target after refresh import adds a competing candidate`：导入后 D 有 P、Q 两个候选（都 ambiguous）；取得 P 的期望摘要并完成审批；在执行前经**真实刷新导入**给 D 新增候选 R（D 字节不变）；执行 → 成功；断言 D 只剩 P 且 `ambiguous=0`，Q、R 都被删除，回执 succeeded。
2. 正对照 `confirm_binding refuses when the target row itself changed`：同样流程，但刷新导入使 P 的六字段之一变化（例如 `paperRev`）→ 被拒、零写入。
前提断言：第 1 步刷新后 R 确实存在、P 的摘要确实未变；做不到真实刷新导入新增候选时停下回报，不要直接写 SQL 伪造。
