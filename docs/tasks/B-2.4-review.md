## 禁令核查
没有打开 `allowUniversalAccessFromFileURLs` 或 `allowFileAccessFromFileURLs`，没有起本机服务，CSP 没有放开远程来源，没有 `feedbackChannel` 以外的桥接频道。✅

Android 上开启请求拦截后，内容拦截规则和自定义 scheme 回调都不会被调用，已从插件源码确认，所以在 Android 上去掉内容拦截规则不会放开任何加载。非 `muyon-proto` 的请求一律返回 403，顶层导航仍由守卫检查。

## 路径安全探针（加载器、策略、守卫）
以下情况都被拒绝或留在根目录内：`..`、各种大小写与混合的 `%2e`、双重编码、`..\`、`%5c`、`%2f`、绝对路径、空路径、其他版本目录、相近名称 `v1x`、目录本身、查询和片段技巧、`%00`。

**问题：**
- 无效的 UTF-8 编码会让代码抛异常（S1）；
- 符号链接会被跟随到根目录以外（S2）。

## 本轮必须修复

**S1（应改）解码出错时要按拒绝处理**（`scheme_loader.dart:55`）
`uri.pathSegments` 的读取放在 try 之外，`%c0%ae`、`%ff` 这类输入会抛出 `FormatException`。Android 插件在 `shouldOverrideUrlLoading` 的 Dart 回调出错时会**放行**导航。
**修复：**
- 解码处捕获 `FormatException` 和 `ArgumentError`，返回 null；
- 在 `prototype_web_page.dart` 中调用守卫的地方加 try/catch，出错时返回 CANCEL；
- 补测试。

**S2（应改）符号链接会逃出根目录**（`scheme_loader.dart:57-69`）
根目录检查只比较路径文本。探针确认，经由符号链接可以读到 v2 和 `/etc` 下的文件。导入时虽然拒绝符号链接，但能写入应用数据目录的人仍可利用这一点。
**修复：**
- 映射路径之后，对 `File(path).resolveSymbolicLinks()` 与解析后的根目录做 `isWithin` 判断，不在根目录内就拒绝；
- 补充文件链接、目录链接、相对链接三种测试。

**S3（应改）测试断言过弱**
- `prototype_screens_test.dart:272` 只检查 `objectPage` 返回值 `isNotNull`。改为按类型断言 `PrototypeDetail` 或 `PrototypeWebPage`。
- `scheme_loader_test.dart` 创建了 `v10.txt` 却没有使用。补上 v1 与 v10 边界的测试。
- 绝对路径的测试是因为文件不存在才通过的。改为在根目录外真实放一个文件，断言读不到。

**S5（应改）运行手册中 Windows 一栏的结论有误**（`prototype-resource-policy.md`）
文中写「原生 C++ 里没有找到对应实现」，但实现其实存在（`flutter_inappwebview_windows-0.6.0/windows/in_app_webview/in_app_webview.cpp:844-902`）。真正的缺口是两点：
- Windows 不支持 `resourceCustomSchemes`；
- WebView2 只为通过 `WebViewEnvironmentSettings.customSchemeRegistrations` 注册过的 scheme 触发 `WebResourceRequested`，而代码没有创建这个环境。

所以 Windows 很可能打不开原型。照此改正，并把 Windows 一栏的 `IGNORE_PREVIOUS_RULES` 标为未验证。另外在「仍未验证」中明确加上一条：「macOS：页面能否通过 `muyon-proto` 正常渲染」。

**S7（应改）补真机证据**
没有在 Android 真机上点击越界顶层链接的记录（A 的验收第 7 项）。请在 Android 16 真机上打开原型，点击一个指向根目录外的链接，确认被拦截。把平台、操作和结果写进运行手册，截图不提交。
