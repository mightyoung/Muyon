The second real run, `/private/tmp/muyon-product-picker-pdf-second.log`, progressed past injection but timed out finding `picker-paper.pdf`; its retained accessibility tree remained at Downloads with `MuyonRefactorFixtures`. Thus successful input injection did not prove folder navigation. Inspection found the short `MotionEvent.obtain` overload left its pointer tool type unknown while only setting the event source. [AOSP DocumentsUI Events.java](https://android.googlesource.com/platform/frameworks/base/+/d7faf53/packages/DocumentsUI/src/com/android/documentsui/Events.java) classifies a touch by `getToolType(0)` accepting finger/stylus; event source alone is insufficient for that classifier. The test now explicitly builds a finger `PointerProperties` and populated `PointerCoords` using the same live node bounds. This is an evidence-backed input-construction fix awaiting device confirmation, not a claim the second run passed. No timeout or acceptance assertion was relaxed.
