## Contract and scope

Verified 2026-10-19 against https://api-docs.deepseek.com/guides/search/ and its linked API reference. This is an independent paid raw-JSON search service, not a model server-side tool. Search uses POST https://api.deepseek.com/v1/tools/search with Bearer authentication in the trusted transport only. No model/tool/stream fields. Fetch is a separate API and is deferred. Default disabled/unconfigured. No user localization or original conversation is sent; the minimal supported request is query/count/need_content=false. Query preserves operators and must have 1–128 Unicode scalar values and non-whitespace; count is 1–50. Optional official ori_question/localization/need_content=true are deliberately unsupported by this first projection, not silently guessed. No free-tier assumption: direct Search nonempty successful responses cost USD750 microdollars per request (CNY5000 microyuan is a separate price/currency, never FX-converted). Empty results are successful and free. Failures/timeouts are documented unbilled, but uncertain outcomes retain a conservative reservation until authoritative reconciliation. Guides currently disagree across languages/versions about QPS; per-install in-flight/one-shot limits are conservative and do not claim an account-wide distributed limiter.

## Files and reuse

Only new `experiments/redesign/web-search-lab/` crate, dedicated workflow and this task directory. No existing chat, owner, provider, bridge, policy or registry runtime edits. Depend on existing native-host and core crates. Register a provider-neutral `web_search.search` operation and connection/result data via the existing Catalog and Enrollment; callers install it into an existing NativeSession and drive the actual existing Agent with RuntimePorts. A host-owned connection ObjectRef binds scope/config revision. Dynamic web citations carry provider/request/URL/rank provenance; they are not local object authorization references. Result fields fit the existing schema subset: exact decimal score is a string, nullable wire fields become optional strings. Full raw provider JSON is not persisted; normalized, reviewed tool result is the receipt payload. No silent truncation on size/shape failures.

## Trusted owner seam (coordination proposal)

Existing ServiceProviderBridge is intentionally unchanged: it requires Chat/model/token budgets. A search-specific binding holds enabled/config revision, provider id, endpoint identity, credential reference and generation, currency, per-request price, max calls and response bytes. A trusted injected SearchHost owns current binding, generation-bound opaque handle resolution, content review, and durable reserve/commit/exchange/settle. Its final one-shot exchange must atomically recheck exact config/policy/handle/payload/purpose/budget and persist the attempt before handing bytes to its TLS adapter; the provider never receives raw credential values. Default methods deny. The host must share the real owner ledger, not independently subtract a parallel in-memory budget. Until parent coordinates/implements that owner port, installed Android UI Send and real network remain unavailable. Fixtures implement that port with a durable new-root ledger and no sockets; this proves the composition contract, not production owner installation.

The owner API binds task/attempt/model-call/scope, source connection ref, exact payload and request identity. Readiness contains no secret or payload; availability reasons are controlled codes. Owner content review covers final query bytes before exchange and every provider-origin title/snippet/summary/URL/site metadata before persistence/model use, and derived answers before disclosure. Hard credential/scope/revocation/unreviewed prohibitions apply in every mode. Invoke shared core policy::authorize for Auto high-risk confirmation and FullAllow no extra risk prompt; taint/new destination cannot themselves become hard denials. Host returns current trusted facts, never model-supplied grants.

## One-shot and taint

A wrapper delegates all registration/dispatch/persistence to existing RuntimePorts. It maps an exchange-admitted failure or post-exchange evidence failure to outcome_unknown and clears the answer; no retry or fallback occurs. The host ledger is authoritative across process/session recreation and rejects consumed/running/unknown request identities. Response errors are controlled status codes; raw error bodies and exception strings never enter results/logs. Nonempty results include real provenance, tainted=true and instruction_authority=false. They enter Role::Tool only and cannot alter mode, purpose, destination or config. Citations and results remain subject to current PurposeReview at model/answer use.

## Independent design review corrections

The read-only reviewer identified identity propagation, failure-path coverage and pre-persistence review gaps. The wrapper sets a private single-flight invocation slot from actual Agent task/attempt/scope/turn and call_ref before delegated dispatch; handler refuses an empty/duplicate slot. Model arguments cannot supply that context. Phase is marked uncertain before host one-shot exchange and result-recorded only after settlement/review/registry dispatch succeeds. Wrapper persist writes a normalized State clone when uncertain; the public run helper also normalizes the in-memory State on both Ok/Err and reports persistence failure explicitly, rather than claiming it was saved. Durable host attempts remain authoritative across sessions; this in-memory phase is not replay protection. Handler reviews the entire normalized result before returning RawRead, and raw equals that same reviewed projection. Even empty responses have tainted=true/instruction_authority=false. Result URLs/icons are tainted data and never fetched. Endpoint is fixed by the DeepSeek wire adapter, HTTPS only, and host must refuse redirects without forwarding authentication.
