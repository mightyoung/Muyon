# CR14-01：宿主事实变化共享通知

执行：待派（下一个空出的本地开发者）。依据：`docs/design/cr14-f1-f2-implementation-2026-10-11.md` 第 2 节「通知」。基线：最新 develop（不依赖 PR42）。

## 要做
1. 先写会失败的测试（`apps/muyon/test/`）：
   - 两个 `HostAuthorizationFacts` 实例共用同一 `ManagedDatabase`：实例 A `markSourceExternal` → 订阅实例 B（或 `FoundationRepository`）收到通知；
   - 锁存先于提交：在写库完成前已能观察到通知/失效状态；
   - 写库失败（SQLite trigger 拒写）通知仍发出、锁存不回退；
   - 不同 `ManagedDatabase` 互不收到；
   - 同一来源重复标记只通知一次（或合并为一次）；
   - `FoundationRepository` dispose 后解绑，不再转发。
2. 实现：按数据库实例共享的通知通道（沿用现有拒绝锁、来源锁的共享方式）；三个 mark 方法内存锁存时同步发布；`FoundationRepository` 订阅一次并转发给现有监听者。不用 `storage_manager` 的 `onCommit`。
3. 不改授权、确认、账本与 OC-11 事实读取规则；不碰 `muyon_ui`。
4. 变异：去掉某个 mark 方法的发布；把发布挪到写库成功之后。两者测试必须失败。
