# P0-4 真机与真实模型取证

分支 `task/p0-4-evidence`（依赖合入后由 leader 从 `develop` 创建）· 执行 本地 engineer · 审查 leader

## 前置条件
- P0-2、P0-3、P0-J1 已合入 `develop`（P0-1 门禁不影响取证，不再作为前置）。分支未创建前不要开工。
- 至少一个真实模型端点：本机（Ollama / LM Studio 等）或远程（OpenAI 兼容）。密钥只放在本机环境变量里。
- 可用设备按实际情况：macOS（需完整 Xcode）、Android 真机、Windows。缺的平台照实写「未验证」。

## 目标
为第一阶段退出标准产出可复核的证据：真机业务链路（R）与真实模型（M）。只跑、只记录，不改代码。

## 步骤

### 0. 环境自检
`bash scripts/doctor.sh`。有 `FAIL` 先修环境，修好前不跑后续步骤。把输出贴进报告（只会显示密钥「已设置/未设置」，仍要人工确认没有密钥）。

### 1. macOS 全量门禁
**先在没有导出 `MUYON_EVAL_REAL` 的 shell 里执行**（`unset MUYON_EVAL_REAL`）：导出该变量时，`verify.sh` 中的链路测试和交叉工具测试会走真实模型路径，前者会产生请求与费用，后者会失败。真实运行只在第 2、3 步按命令单独设置。
在本分支执行 `bash scripts/verify.sh`（含 golden），贴出每行摘要。如果 P0-1 已合入，再执行一次 `bash scripts/ci.sh`，一并贴出摘要。失败时记录失败用例与错误，不修复，继续后续步骤。

### 2. LLM 工具选择基线（M）
真实运行必须设置 `MUYON_EVAL_REAL=1`，只导出模型变量时测试会跳过。需要代理才能访问远程端点时，保留 `HTTPS_PROXY`，同时设置 `NO_PROXY=localhost,127.0.0.1,::1`。推理较慢的模型请设置 `MUYON_EVAL_MODEL_TIMEOUT_SECONDS`，默认 45 秒，超时按错误计分。
按 `apps/muyon/lib/assistant/selection_eval/llm_selection_eval.dart` 顶部注释中的命令，对每个可用模型各跑**一次**，设置 `MUYON_WRITE_EVAL_REPORT=1`，生成 `docs/implementation/tool-selection-llm-baseline-<slug>.md`。
- 每个模型只取一次运行的结果，不挑最好的。因限流或网络失败过半时可以重跑一次，两次的结果都写进报告。
- 报告里写明模型、端点类型（本机/远程）、运行日期。

### 3. 询价 North Star 链路（R + M）
按 `docs/implementation/north-star-inquiry-runbook.md` 依次执行，每次都设置 `MUYON_EVIDENCE_OUT` 输出证据 JSON：
1. 桌面无头 + 真实模型（`flutter test test/north_star_inquiry_test.dart`）；
2. macOS 设备（`flutter test integration_test/north_star_inquiry_test.dart -d macos`，模型参数用 `--dart-define`）；
3. Android 真机（同上，`-d <设备 id>`）；
4. Windows（如有）。

每次真实模型运行，在报告里列出两道只读题各自的 `tasks[].tools`：比价题必须包含 `inquiry.compare_quotes`，预算题必须包含 `inquiry.project_budget`。不满足的运行如实记录，但不计为 2.3 的 M 证据（P0-3c 合入前由 leader 人工核对）。

证据 JSON 放进 `docs/evidence/2026-10-p0/`，文件名为 `north-star-<平台>-<模型 slug>.json`。提交前执行 `grep -rn "$MUYON_EVAL_MODEL_KEY" docs/evidence/2026-10-p0/`，必须没有输出。

### 4. 手动界面走查（可选，需要能操作界面）
在真实应用里用真实模型走一遍同一场景。你不能操作界面时，写「未执行」，交给用户。
1. 设置 › 添加模型。
2. 在询价模块建项目和两家报价。
3. 回到助手，提问「比较 <项目> 的两家报价」。
4. 让助手创建询价单，审批后到询价页面核对。
5. 退出重开，检查对话与任务记录。

每一步记录：需要确认几次；确认弹窗是否看得懂；首次出字与完整回答的耗时；引用能否点回业务页；任何报错原文。截图存本机，不提交，在报告中列出文件名。

### 5. 汇总
新建 `docs/implementation/p0-evidence-2026-10.md`，用一张表列出每次运行：项目、平台/设备、模型（slug 与本机/远程）、命令、结果、证据文件、证据类别（R / M / T）。**不要修改验收账本**，由 leader 审查后统一更新。

## 约束
- 只新增证据、报告和汇总文件，不改任何代码与已有文档。
- 发现缺陷只记录（复现步骤、平台、错误原文），不修复。
- 密钥、私有地址、个人数据不得进入仓库。
- 夹具运行和真实模型运行必须分开写，不能混记。
