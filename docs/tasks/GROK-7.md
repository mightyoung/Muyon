# GROK-7 科研场景交互走查清单（AIUI-7 前置）

分支 `task/grok-7-research-walkthrough` · 执行：grokbot（只做静态核对与写文档；不运行 Flutter，不改代码）· 审查：leader A 抽查 · 给谁用：AIUI-7（科研场景）、AIUI-5（规划提示）、AIUI-3（公式）

## 背景
AI 原生界面以对话为中心（[方案](../design/ai-native-ui-redesign-2026-10-09.md) §4）：用户提出目的，助手的回答就是可以操作的界面。科研的对象、字段、写入方式见 [GROK-6](../reviews/2026-10-09-research-ontology-draft.md)。流式界面的约束见 [AIUI 契约](../design/aiui-stream-contract.md)：数值只来自事实或宿主公式，动作只用登记过的动作。科研敏感度已确认：研究内容和文献作者都是 `none`。

## 只做这些
产出 `docs/reviews/2026-10-09-research-walkthrough.md`：
1. **常见目的清单**：从科研现有页面（`packages/research_module/lib/src/app/` 下的概览、文库与阅读器、任务、结果、写作、关系图）和 Store 能力出发，列出 15～25 个用户在对话里会提的目的。例如「这篇论文支持我的哪个主张」「把这次运行的结果和上次比一下」「把这几条证据挂到第 3 节」。每个目的写：
   - 用户原话示例（1～2 句）；
   - 建议的回答形态（方案 §4.2：文字 / 文字加补充卡 / 交互小工具 / 工作区），以及理由；
   - 用到哪些组件（方案 §5.2 的组件名）；
   - 需要宿主快照提供哪些**事实**（对象、字段，附 `文件:行`）；
   - 需要哪些**宿主公式**（例如运行指标差值、证据计数），交给 AIUI-3 登记；没有就写「无」；
   - 涉及哪些动作，标出路由（本地 / 业务 / 语义）；业务动作写出对应的建议工具（GROK-6 §5.2 的命名），以及效应是写入还是外传；
   - 现在能不能做：工具已有，或者缺什么（对应 REG-3 的哪一项）。
2. **必须留在原页面的操作**：列出来，并说明理由，例如阅读器划词、关系图布局、冲突解决。
3. **优先级**：按「使用频率 × 现在的可行性」排序，给出 AIUI-7 首批建议做的 5～8 个目的。
4. **公式清单**：把第 1 项里出现的公式汇总成表：名称、输入（只能是事实或用户输入值）、输出、单位、一句话定义。这张表交给 AIUI-3。
5. 「未能静态确认」单列。
