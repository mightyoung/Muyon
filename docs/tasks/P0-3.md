## 目标
验收账本中几乎没有真机（R）与真实模型（M）的证据。要做一条端到端的链路自动测试：
- 本机无头运行时，使用回环夹具模型；
- 设置环境变量后，就能在真机、真实模型上运行，并产出证据。

## 链路
1. `MuyonHost.open(新数据目录)`，激活询价模块。
2. 用模块自己的领域函数建立项目、预算行、两家供应商报价。参照 `inquiry_write_tools_test.dart`、`business_tools_test.dart` 的做法，不另造数据通路。
3. 个人助手通过已注册的工具回答只读问题：比较报价、项目预算。
4. 助手提出一项写入，例如通过 `inquiry_write_tools.dart` 创建询价单。
5. 用预览摘要调用 `PersonalAgent.confirm` 完成审批。
6. 写入在询价库中可以查到，结果引用了该对象。
7. `host.close()` 后重开同一目录，对话、任务记录、工具回执、`outbound_requests` 仍在且一致。

目前每一轮模型调用都需要确认（stage 为 `model`）。测试要像界面那样，读取 `requestDigest` 后再确认。

## 交付
1. **共享的链路驱动**，供以下两处使用：
   - `apps/muyon/test/north_star_inquiry_test.dart`：无头、回环夹具模型，按助手协议返回 JSON，随普通 `flutter test` 运行。
   - `apps/muyon/integration_test/north_star_inquiry_test.dart`：同一条链路，使用 `IntegrationTestWidgetsFlutterBinding`，可以在设备上运行。
2. **真实模型**：设置 `MUYON_EVAL_MODEL_ENDPOINT` 与 `MUYON_EVAL_MODEL_ID` 时使用真实模型，`MUYON_EVAL_MODEL_KEY` 可选。
   - 设备上读不到环境变量，所以要同时支持 `--dart-define`。
   - 真实模型下只断言不变量，不断言措辞。不变量包括：工具只来自注册表；写入只在审批之后发生；记录在重开后仍在；出站账本有记录。
3. **证据输出**：设置 `MUYON_EVIDENCE_OUT` 时，写出 JSON 证据，内容包括：
   - 模型端点与 id，或标为 "fixture"；
   - 设备与平台；
   - 各步骤耗时；
   - 任务状态；
   - 账本计数。

   夹具运行的结果要明确标注「不是真实模型证据」。证据中不得出现密钥。
4. **运行手册**：新文件 `docs/implementation/north-star-inquiry-runbook.md`，写明：
   - 三种运行方式的完整命令：无头夹具、桌面真实模型、Android/macOS 设备真实模型；
   - 证据如何回填验收账本，支持哪几行（2.3、7、9a）；
   - 如实说明夹具运行能证明什么、不能证明什么。
