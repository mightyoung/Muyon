Finding 1 [P2] Reentrant close during ready approval still permits spawn
Location: tools/document_fidelity/adapters/runner/authority.py:96-98; launcher.py:117-119.
The RLock permits verify_ready to call close_worker_stage. approve_ready checks worker_closed only before this callback and unconditionally commits ready afterward. The launcher then checks the admission lease, whose check deliberately does not check worker_closed, and calls spawn. A pre-spawn cancellation callback that closes worker stage but returns False gives the same result.
Reproduction: /tmp/worker-phase-fa2-independent-probe.py modes ready_close_worker and cancel_closes_worker_returns_false. Both show spawn=true, status=candidate_validated, candidate/credential/eligible=true under explicit synthetic session.
Impact: an irreversible worker-phase close does not prevent later process launch. Worker permits remain blocked, so this is not evidence of a third-party engine authorization bypass. Synthetic success depends on the fake session's fabricated verification and must not be represented as production execution.
Suggested fix: recheck phase/closed/ready after verify_ready; before spawn require a live claimed ready worker phase rather than an admission-only lease check. Preserve admission for post-reap validation.

Finding 2 [P2] Terminal verifier reentry can mint two one-use credentials
Location: tools/document_fidelity/adapters/runner/authority.py:145-154.
credential_issued is checked before verify_terminal and written only after callback. The verifier can reenter issue_credential once under RLock. Both calls observe no issued credential; each mints a distinct validator for the same attempt/receipt. Both can be consumed before finish. This preexisting adjacent contract gap is retained by the modified function, not introduced by this diff.
Reproduction: /tmp/worker-phase-fa2-reentrant-credential.py; output nested_minted=true, outer_minted=true, distinct=true, both_consumptions=[true,true]. Uses only explicit FakeHostSession/OS API synthetic objects.
Impact: service API single-issuance/replay invariant is not reentry-safe. Ordinary launcher.finish revokes the nested cap if still unconsumed, limiting normal path exposure; arbitrary malicious trusted service code is outside stated threat boundary. No external JSON bypass or durable core commit is shown; core CAS/idempotency remains an additional required check.
Suggested fix: reserve issuance/in-flight state before invoking terminal verifier, or recheck credential_issued after callback and deny second mint; ensure exception/negative-evidence behavior remains fail closed.
