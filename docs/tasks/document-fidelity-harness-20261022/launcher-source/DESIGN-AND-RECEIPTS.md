# Trusted-host launcher source and txn receipt v3 — proposed, not wired

Scope: adapter/runner source and independent docs only. No Rust/Android edits or actual engine/OS sandbox execution. Existing bwrap UID-map read-only refusal remains a known failed operation, never retried or substituted. No software install/EULA/payment/config/credential/permission change.

## Trust and admission

Model/document/ordinary JSON is untrusted data. It supplies only existing schema1/2 request envelope and typed edit. Production qualification must arrive on a separately configured **trusted host bootstrap object channel**, not a request field/boolean/environment flag/old receipt. Host verifies scope/revision/source hash, exact engine id/version/artifact hash, worker/runtime image hashes, source provenance review id, license review id, isolation attestation id, resource-policy digest, nonce and monotonic expiry. An evidence record is bound to this request digest and attempt, never a reusable blanket supportsOffice grant.

Python object capabilities are a service-code boundary, not protection from arbitrary malicious Python already running in the trusted host. Only reviewed host bootstrap can attach a production verifier and OS backend; no JSON factory/CLI switch exists. Current environment has neither channel nor qualified backend, so real entry defaults HOLD even forged pass JSON. Fake OS executor/simulation evidence is a distinct assurance class. A simulation lease/receipt can never mint a host validator credential, even if its serialized fields claim success.

Worker execution changes from unconditional placeholder raise to a permit-checked source path: require a live one-use host-bound WorkerPermit matching source/candidate paths, request/engine identity and staged-sandbox context before importing library. Ordinary dicts and simulation permits reject. Default CLI has no host bootstrap and emits HOLD; no ambient-path or plain-subprocess fallback. Future trusted worker bootstrap/IPC must provide its own verified channel; static command arguments are not authority.

## Controlled lifecycle

received → admitted → prepared → spawned → running → exited → reaped → snapshot_checked → validated. Refusal/HOLD can precede all OS work. Never validate while a worker or descendant can still write. Cancellation before spawn creates no child. Cancellation/timeout/log/output/resource breach after spawn invokes terminate-tree, bounded grace, kill-tree if necessary, then reap-tree; PID/group identity must remain bound to the attempt (actual backend should use pidfd/cgroup or equivalent, not guessed PID). Failure to prove complete reaping is outcome_unknown and quarantines workspace; no automatic resubmit, candidate release or cleanup of a live job.

The OS executor contract must stage a private workspace with fixed source/job RO mounts and independent candidate-only writable output, empty sanitized env, no host credentials/profile, disabled network/macros/refresh/embedded execution, pinned artifacts and enforced deadline/CPU/AS/pids/output/log bounds *before* engine start. Host independently verifies sandbox-ready attestation; executor self-report booleans alone never open production execution. No ready proof means no spawn.

Controller polls bounded events using monotonic time and running output size; byte counters reject over-limit chunks before retaining them. Scope-bound cancellation is checked before preparation/spawn and during loop. Root exit0 is insufficient: reap/kill remaining descendants, freeze a fresh bounded regular single-link/non-symlink candidate snapshot, check exact output set and source/job hashes, then run current independent format oracle. Staging/spawn exceptions require nonce-bound reconciliation; uncertain ownership/reaping quarantines, not retry. Cleanup happens only after proof no child remains. OS syscalls/namespace enforcement are responsibilities of the future qualified backend, never simulated proof.

## Core/txn result boundary

Request wire schema1/2 unchanged. Runner receipt_version3 adds attempt_id, request_digest, binding digest, assurance(host_verified|simulation), lifecycle events, engine/policy/artifact references, source/candidate hashes/manifests, cancellation/timeout/termination/kill/reap/cleanup outcome and independent validation. Reports retain render/recalc/visual/annotation NOT_RUN and global safety/fidelity unknown unless separately supported by real evidence.

Public JSON is audit data only. A production validated result may carry a separate in-memory HostValidationCredential minted by the issuing authority after host verifies terminal/reap/snapshot/oracle evidence. It is not serialized or constructible from receipt JSON, must match all identity/source/candidate/request/attempt/receipt bindings, and is one-use. Host/core must explicitly consume/verify it before considering durable candidate creation. Simulation always txn_eligible=false and credential=None; old simulated_validated receipts are never accepted. Worker validated != durable saved != CAS committed != synced. Rust alone owns authorization/revision/idempotency/durable storage/CAS/rollback and must recheck them at commit. Receipt3 is a proposal, no current Rust consumer or production credential bridge is wired.

## What can be completed here / what cannot be claimed

Complete source unit: trust-bound envelopes and capability checks, admission and lifecycle controller, fixed launch policy, fail-closed reconciliation/cancel/terminate/kill/reap/quarantine flow, bounded event/snapshot/oracle pipeline, receipt/credential separation and permit-checked worker bodies; exercise solely via explicitly fake OS executor. This does not implement or certify the external host verifier/kernel sandbox backend or IPC bootstrap. No actual engines, worker CLI, namespace/process sandbox tests occur.

Future compliant environment must demonstrate authenticated host/broker bootstrap, exact artifact/source/license/native/font approvals, actual no-network/RO scoped mounts/no host credentials, resource enforcement and descendant reaping under races/crash/cancel/timeout, fresh file snapshot and credential IPC authenticity, real library copy round-trip and strict oracle compatibility/render/recalc. Current environment stays HOLD. No source completion label substitutes for these missing measurements or overall four-format capability.
