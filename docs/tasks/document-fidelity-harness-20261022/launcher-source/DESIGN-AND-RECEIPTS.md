# Trusted-host launcher source and txn receipt v3 — proposed, not wired

Scope: adapter/runner source and independent docs only. No Rust/Android edits or actual engine/OS sandbox execution. Existing bwrap UID-map read-only refusal remains a known failed operation, never retried or substituted. No software install/EULA/payment/config/credential/permission change.

## Trust and admission

Model/document/ordinary JSON is untrusted data. It supplies only existing schema1/2 request envelope and typed edit. Production qualification must arrive on a separately configured **trusted host bootstrap object channel**, not a request field/boolean/environment flag/old receipt. Host verifies scope/revision/source hash, exact engine id/version/artifact hash, worker/runtime image hashes, source provenance review id, license review id, isolation attestation id, resource-policy digest, nonce and monotonic expiry. An evidence record is bound to this request digest and attempt, never a reusable blanket supportsOffice grant.

Python object capabilities are a service-code boundary, not protection from arbitrary malicious Python already running in the trusted host. Only reviewed host bootstrap can attach a production verifier and OS backend; no JSON factory/CLI switch exists. Current environment has neither channel nor qualified backend, so real entry defaults HOLD even forged pass JSON. Fake OS executor/simulation evidence is a distinct assurance class. A simulation lease/receipt can never mint a host validator credential, even if its serialized fields claim success.

Worker execution changes from unconditional placeholder raise to a permit-checked source path: require a live one-use host-bound WorkerPermit matching source/candidate paths, request/engine identity and staged-sandbox context before importing library. Ordinary dicts and simulation permits reject. Default CLI has no host bootstrap and emits HOLD; no ambient-path or plain-subprocess fallback. Future trusted worker bootstrap/IPC must provide its own verified channel; static command arguments are not authority.

## Controlled lifecycle

received → admitted → prepared → spawned → running → exited → reaped → snapshot_checked → validated. Refusal/HOLD can precede all OS work. Never validate while a worker or descendant can still write. Cancellation before spawn creates no child. Cancellation/timeout/log/output/resource breach after spawn invokes terminate-tree, bounded grace, kill-tree if necessary, then reap-tree; PID/group identity must remain bound to the attempt (actual backend should use pidfd/cgroup or equivalent, not guessed PID). Failure to prove complete reaping is outcome_unknown and quarantines workspace; no automatic resubmit, candidate release or cleanup of a live job. Terminalization closes the lease and revokes all outstanding worker/validator permits except the single accepted validator result. Each ready/worker mint/validator mint transition is single-use. Authority fails closed after1024 attempts instead of evicting replay history; a future host service must manage authority lifetime and persistent idempotency outside this bounded object.

The OS executor contract must stage a private workspace with fixed source/job RO mounts and independent candidate-only writable output, empty sanitized env, no host credentials/profile, disabled network/macros/refresh/embedded execution, pinned artifacts and enforced deadline/CPU/AS/pids/output/log bounds *before* engine start. Host independently verifies sandbox-ready attestation; executor self-report booleans alone never open production execution. No ready proof means no spawn.

Controller polls bounded events using monotonic time and running output size; byte counters reject over-limit chunks before retaining them. Scope-bound cancellation is checked before preparation/spawn, during loop, after snapshot/oracle and before release. Operation deadline is checked before spawn and before/after terminal verification, including cleanup time. A cancelled/expired terminal verifier result is discarded and its synthetic/in-memory capability revoked; core must still atomically recheck cancellation/auth/revision at its commit linearization point. These checks do not claim to eliminate distributed commit races. Root exit0 is insufficient: reap/kill remaining descendants, freeze a fresh bounded regular single-link/non-symlink candidate snapshot, check exact output set and source/job hashes, then run current independent format oracle. Staging/spawn exceptions require nonce-bound reconciliation; uncertain ownership/reaping quarantines, not retry. Cleanup happens only after proof no child remains. OS syscalls/namespace enforcement are responsibilities of the future qualified backend, never simulated proof.

## Core/txn result boundary

Request wire schema1/2 unchanged. Runner receipt_version3 adds attempt_id, request_digest, binding digest, assurance(host_verified|simulation), lifecycle events, engine/policy/artifact references, source/candidate hashes/manifests, cancellation/timeout/termination/kill/reap/cleanup outcome and independent validation. Reports retain render/recalc/visual/annotation NOT_RUN and global safety/fidelity unknown unless separately supported by real evidence.

Public JSON is audit data only. A production validated result may carry a separate in-memory HostValidationCredential minted by the issuing authority after host verifies terminal/reap/snapshot/oracle evidence. It is not serialized or constructible from receipt JSON, must match all identity/source/candidate/request/attempt/receipt bindings, and is one-use with the original admission expiry. Consumption requires current trusted-host monotonic time; omitted/negative/nonfinite/expired time refuses. Host/core must explicitly consume/verify it before considering durable candidate creation. Simulation always txn_eligible=false and credential=None; old simulated_validated receipts are never accepted. Worker validated != durable saved != CAS committed != synced. Rust alone owns authorization/revision/idempotency/durable storage/CAS/rollback and must recheck them at commit. Receipt3 is a proposal, no current Rust consumer or production credential bridge is wired.

## What can be completed here / what cannot be claimed

Complete source unit: trust-bound envelopes and capability checks, admission and lifecycle controller, fixed launch policy, fail-closed reconciliation/cancel/terminate/kill/reap/quarantine flow, bounded event/snapshot/oracle pipeline, receipt/credential separation and permit-checked worker bodies; exercise solely via explicitly fake OS executor. This does not implement or certify the external host verifier/kernel sandbox backend or IPC bootstrap. No actual engines, worker CLI, namespace/process sandbox tests occur.

Future compliant environment must demonstrate authenticated host/broker bootstrap, exact artifact/source/license/native/font approvals, actual no-network/RO scoped mounts/no host credentials, resource enforcement and descendant reaping under races/crash/cancel/timeout, fresh file snapshot and credential IPC authenticity, real library copy round-trip and strict oracle compatibility/render/recalc. Current environment stays HOLD. No source completion label substitutes for these missing measurements or overall four-format capability.


## Exact proposed consumer handshake (source API; not a wired bridge)

1. Trusted application bootstrap constructs a registered authenticated `TrustedHostSession`, pinned `EngineIdentity`, tightening-only `Policy`, qualified `HostOSBackend` and `TrustedRuntimeBinding`. Neither model tools nor request JSON exposes this constructor channel. No concrete provider is installed in this environment.
2. `run_production(source_bytes, request_schema1_or2, binding, cancel=scope_cancel)` returns `Result`. Missing/invalid typed binding is HOLD before staging. `runtime.run_real(..., trusted_runtime=...)` exposes audit JSON only and must not be treated as a commit API.
3. Accept only a candidate_validated result with immutable candidate bytes and non-None opaque credential. Recompute candidate SHA and `model.digest(result.public)`; provide unchanged request and current trusted-host monotonic `now` to the same authority's `consume_credential(credential, request, candidate_sha, receipt_digest, now=now)`. This is one-use and expires with admission. JSON receipts have no credential factory. This remains a service-code boundary, not a cryptographic cross-process protocol implementation.
4. Core must combine its own cancel/auth/scope/base-revision/idempotency check with durable candidate/report persistence and CAS according to its transaction protocol. Validation success alone is not a saved/committed/synced receipt. A new real IPC design must authenticate/translate the opaque channel and preserve all bindings; serializing a Python capability is deliberately forbidden.

Public receipt3 includes request_schema_version, identity, source/request/binding digests, nonce attempt_id, engine hashes, policy_digest, lifecycle, source_manifest, preview, candidate_sha256, validation, reaped, log byte counts and hashes. `txn_eligible` is descriptive audit data, never sufficient authority. No public field upgrades safety/fidelity from unknown or render/recalc/visual/annotation from not_run. A future consumer must explicitly support receipt3; no silent coercion to legacy receipt1.

FakeHostSession/FakeHostOS tests deliberately exercise the trusted application's interface with synthetic objects. Their in-memory test capability is not authenticated host evidence or a real validator credential. They do not install any production bootstrap and cannot qualify the current environment. Ordinary simulation Authority/FakeOS and serialized receipts remain ineligible.
