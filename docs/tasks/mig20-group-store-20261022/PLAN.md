# MIG20 BusinessStore persistence slice

Base runtime 12a001deae8e49de4eba2012975539a4b234a527. New owned group_runtime/store.rs, dedicated SQLite integration tests and this directory. No core/lib.rs, contract enum, BusinessStore owner file, group governance, FFI or host/shell owner edit.

API: typed local GroupCommand / GroupOperation, host-only issue_group_local_grant_trusted, execute_group_local, opaque GroupScope::current, group_run/group_next_pending/group_lookup_original. Group registration explicitly persists owner/admin/member/policy/conversation facts, validates a real existing project and workspace, never invents account records or assumes a pre-existing group. Local grant issuance uses existing persisted business_grants binding/generation/owner/expiry semantics, never produces network execution authority. The caller must be authenticated host code, like existing issue_grant_trusted; wire principals do not authenticate themselves.

Same BusinessStore Db tables: group_runtime_schema (explicit version), group_runtime_groups, group_runtime_runs, group_runtime_nodes (local proposal/original-reference facts), group_runtime_local_intents (local mutation pending/receipt journal), group_runtime_events. Initialization is explicit and transactional; validates exact DDL. Metadata and strict required business schema unchanged. All group effects, group CAS revision, epoch/handoff count, stop, summaries, local receipt and grant consumption share one BEGIN IMMEDIATE transaction. Pending is durable before effects; interrupted pending is query-only and never replayed. This is a local coordination mutation journal, not a second provider request or accounting ledger.

Original requests are linked only after checking real AgentOwner workspace and request conversation against registered group/run; original lookup uses owner.lookup with no transport. Unresolved original state forbids handoff/new admission advice. Business/AgentOwner connections are separate: no cross-database atomic execution is claimed; the final host gateway must still do its own authorization, cost proof, reserve and claim. Unknown query never settles/releases/retries. Runtime scope is exact workspace/project/group, stale owner epoch cannot mutate.
