Apply `CORE-EXPORT.patch` by the sole core/lib.rs owner after bringing governance/runtime sources from pinned commits; patch was generated against document-core f4a8e8d3971208f16d4a3b1ddff5d4e8fb2a63ac, dry-run checked on a disposable copy. ## Implemented APIs

```rust
BusinessStore::initialize_group_runtime(&self) -> Result<(), ContractError>;
BusinessStore::issue_group_local_grant_trusted(&self, &GroupCommand) -> Result<(), ContractError>;
BusinessStore::execute_group_local(&self, &GroupCommand, Option<&AgentOwner>) -> Result<LocalReceipt, ContractError>;
GroupScope::current(&BusinessStore, project: &str, group: &str) -> Result<GroupScope, ContractError>;
BusinessStore::group_registration(&self, &GroupScope) -> Result<Registration, ContractError>;
BusinessStore::group_run(&self, &GroupScope, run: &str) -> Result<StoredRun, ContractError>;
BusinessStore::group_next_pending(&self, &GroupScope, run: &str, &AgentOwner) -> Result<PendingAdvice, ContractError>;
BusinessStore::group_lookup_original(&self, &GroupScope, run: &str, node: &str, &AgentOwner) -> Result<OriginalRequestView, ContractError>;
```

GroupScope is opaque, constructed from a real existing project and registered group, checks workspace/project/group and current BusinessStore owner epoch on each use. `GroupActor::Human` is a payload assertion, not authentication. Only authenticated compiled host code may issue a local grant after current user authorization/confirmation. The exact command (actor, scope, expected revision/epoch, parameters, authority reference) is domain-hashed and stored in the existing business_grants table. Issue/call APIs are not exposed to arbitrary wire JSON/model code. This matches the baseline trusted issuance boundary; this module does not create or verify a multi-user account system.

The six explicitly initialized tables are group_runtime_schema/groups/runs/nodes/local_intents/events. They share the actual BusinessStore connection and transaction. BusinessStore's strict business schema/meta and existing original intents/receipts/requests/budgets remain unchanged. group_runtime_local_intents is the local coordination mutation journal, not a provider request ledger or accounting owner. `LocalStatus::Committed` means the local facts committed, never that an Agent ran.

Register must explicitly persist owner/admin/member/scopes/mode/conversation facts under a real existing project. Start persists an explicitly selected leader (none for host_only, configured for fixed, required per_task), finite limits and task-local member grants. Same root ID cannot be restarted under a fresh run ID to reset its stored lifetime. Plan persists a bounded, versioned proposal; PendingHostAdmission is an advisory object with no executable ticket/permission. It is never a queued provider request. Stop records stopped_unbound for unbound proposals because a cross-owner request may already exist; it does not assert that no request was sent.

BindOriginal and Observe require a real AgentOwner reference and verify its workspace and persisted original conversation against the explicit group registration. BindOriginal registers only an existing original reference, including after stop/deadline/handoff for reconciliation, and cannot create/confirm/claim/resend it. Handoff always requires the real owner, even when no node is bound, so unregistered unresolved conversation requests cannot be missed. OriginalRequestView preserves original_request_id, all actual chain receipts, and the actual last receipt in current. Unknown/prepared/tool followups cannot be bypassed by interpreting tool_consumed as a final success. An original receipt's charged=0 with unknown status is not evidence of known zero usage.

## Necessary host/core-owner hooks, not implemented by editing owned files

The baseline AgentOwner public API exposes workspace, conversation and immutable request-chain observations; it does **not** expose a canonical request payload binding with project/group/run/node/member/policy identity. RunLedger's get/children are private. Therefore this slice verifies persisted group registration + exact local mutation grant + real workspace/conversation/request-chain identity, but cannot prove that a particular original request executed the planned canonical payload for that node. Node state is an observation of the associated original receipt, not certification of task correctness. Actual run/child attribution and final admission must remain HOLD until the following owners wire their facts.

1. **Core/AgentOwner owner:** provide a read-only request-binding projection from the actual persisted request owner. Minimum fields available in current requests are request_id, workspace, conversation, configuration_id, owner_epoch, payload_digest, purpose and price/config revision. Do not synthesize project/group/member fields which do not exist there. A suggested signature is `request_binding(&self, request_id: &str) -> Result<OriginalRequestBinding>`; this is a concrete missing hook, not a trait added by this task.
2. **Host owner:** before original admission, persist the accepted group request context (workspace/project/group/run/root/node/member plus configuration/policy/plan/grant revisions and coordinator epoch) bound to that actual canonical request digest in the existing trusted host request/context owner. Any new registrar must validate current scope/grants and the actual original request identity, not accept a model's claimed context. This mapping is currently absent and must be real registration, not a fabricated account/group or a memory-only snapshot. The group registration and reconciliation reference facts supplied here are already real BusinessStore rows; they do not retroactively prove original payload authorization.
3. **RunLedger owner:** expose complete scoped root/all historical child/attempt state and the actual root budget source. It must exclude the root from child capacity counts, retain unknown/reservations and failed/cancelled lifetime attempts, not use truncated presentation events. A proposed read-only shape is the existing `group_governance::HostSnapshot` plus root ownership context, produced by the actual ledger, not caller JSON. Root_task_id in this slice is explicitly a registered planned root reference; it is not proof that RunLedger created that root.
4. **Host gateway owner:** atomically recheck live host lease, registered scope/context, canonical payload and recipient, current approval/grant/cost proof, limits/epoch, budget and original receipts in its sole original intent/reserve/claim path. BusinessStore and AgentOwner are separate connections. This slice provides atomic local group CAS/persistence only and makes no cross-database execution transaction guarantee. It never expands permissions or unlocks engine isolation/production HOLD.

No owner hook is faked by a placeholder implementation. All delivered methods have real SQLite behavior and executable synthetic-event tests. These hooks are explicit next integration work; no operation to modify protected owner files was attempted or denied.
