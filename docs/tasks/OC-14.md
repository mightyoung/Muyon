## 依据
`docs/reviews/2026-10-11-record-tools-gap-audit.md`（CR-11）第 2 节隐藏耦合 (1) 与第 5 节 B：候选组装顺序是「先全字段默认 → 覆盖旧记录 → 覆盖 `values`」，未提供的字段保留旧值，显式 `null` 才清空，更新带 `allowClear: true`（`apps/muyon/lib/platform/inquiry_record_tools.dart` 约 495 行）。后续 WC-B 抽共享函数时不能改变这些语义，先用测试钉住。

## 要做
新建 `apps/muyon/test/oc14_update_value_semantics_test.dart`，搭法照抄 `apps/muyon/test/inquiry_general_write_tools_test.dart` 现有 update 测试（真实宿主、真实选择、经确认调用 `inquiry.update_record`）。选一个有文本、数字、布尔或列表字段的类型（例如 contact 或 product，先读本体声明确认字段类型），先建一条所有这些字段都有非空值的记录，然后各用一次 update：
1. 未提供某字段（`values` 不含该键）→ 该字段保持旧值；
2. 显式 `null` → 记录现在的结果（清空，或被拒绝）；
3. 空串 `""` → 记录现在的结果；
4. 数字 `0` → 保存为 0，不当成未提供；
5. `false` → 保存为 false，不当成未提供；
6. 空列表 `[]`（如果该类型有列表字段；没有就跳过并在回报里说明）→ 记录现在的结果。
7. `values` 为空 `{}` → 记录现在的结果（审计说当前会拒绝）。

每个测试都要断言：写入后从 Store 重新读出的字段值；以及版本号是否加一。2、3、6、7 写成「现在就是这样」的断言，并在测试名里写清行为，例如 `explicit null clears contact phone`。
