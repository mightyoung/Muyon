## 背景
`scripts/doctor.sh` 已合入 `develop`。复核时发现两处低风险问题和几处测试缺口，属于范围冻结允许的安全修复。

## 只做这些
只修改 `scripts/doctor.sh` 与 `scripts/test_doctor.sh`，不改其他文件。在本分支提交并推送，不合并 `develop`。

### 1. 端点必须以 `http://` 或 `https://` 开头
现在没有 scheme 的端点能伪装成本机地址：`${EP_AUTH#*://}` 会剥到字符串里第一个 `://`，所以 `host:port/x://localhost/v1` 会被判成本机，密钥随后以明文发给 `host`。
- 在解析 authority 之前，用 `case` 判断：开头不是 `http://` 或 `https://` 时，`FAIL model-env`，说明写「端点必须以 http:// 或 https:// 开头」。
- curl 加上 `--proto '=http,https'`，URL 改用 `--url "$MODELS_URL"` 传入，防止以 `-` 开头的端点被 curl 当成选项。

### 2. 密钥里有换行或回车时直接拒绝
`printf 'header = ...'` 交给 `curl -K -` 时，密钥中的换行会注入额外的 curl 配置行。
- `MUYON_EVAL_MODEL_KEY` 含 LF 或 CR 时，`FAIL model-key`，说明写「密钥含换行或回车字符」，不回显密钥，也不调用 curl。

### 3. 补测试（`test_doctor.sh`）
每个新场景失败时，打印实际输出，方便排查。
1. 没有 scheme 的端点（`127.0.0.2:18082/x://localhost/v1`）和 `ftp://localhost/v1`：`model-env` 为 FAIL，退出码 1，假 curl 没有被调用。
2. 密钥含换行：`model-key` 为 FAIL，输出中没有密钥，假 curl 没有被调用。
3. 本机端点（`http://localhost:11434/v1/chat/completions`），有密钥和无密钥各一次：断言参数里有 `--noproxy` 和 `*`，URL 是 `http://localhost:11434/v1/models`；无密钥时参数里没有 `-K`。
4. 精确主机匹配：`http://localhost.evil.com/v1` 为 FAIL（按远程处理、需要 HTTPS）；`http://[::1]:8080/v1` 为本机 OK。
5. 密钥转义：密钥为 `sk-a"b\c` 时，假 curl 收到的标准输入里是 `header = "Authorization: Bearer sk-a\"b\\c"`，或者经 curl 解析后等价的内容。
6. 端点末尾带 `/`：`https://api.example.com/v1/` 请求的是 `https://api.example.com/v1/models`。
