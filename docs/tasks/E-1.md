# E-1 多步任务评测（现状基线）

分支 `task/e-1-agent-task-eval` · 执行：Sonnet 5.5 子代理（leader 派发）· 审查 leader · 阶段：第二阶段（[ADR-0003](../adr/0003-phase2-scope.md)）· 性质：**只加评测代码与测试，不改产品行为**

## 背景
现有评测只测“单题选哪个工具”（`apps/muyon/lib/assistant/selection_eval/`，140 题）。第二阶段退出标准要求测出“只读任务审批次数中位数 0、写任务 1”和首字时延（[路线图](../superpowers/plans/2026-10-07-roadmap-phase2-4.md) §3），需要一套**多步任务**评测，并先在**现有**助手上测出基线，供内核 v2（K-2～K-4）和分级授权（AUTH-1）对比。

## 交付
1. **任务集** `apps/muyon/lib/assistant/agent_eval/agent_task_set.json`：不少于 20 个任务，基于询价 North Star 的种子数据（复用 `apps/muyon/integration_test/support/north_star_seed.dart` 的数据；如需在 `lib/` 或 `test/` 中复用，抽出共享函数时不得改变 North Star 驱动的行为）。覆盖：
   - 单步只读（如比价、预算）；
   - 多步只读（如“查预算再比两家报价”，需要 ≥2 个工具）；
   - 写入（`inquiry.create_inquiry`、`inquiry.record_quote` 等现有写入工具），含应拒绝 / 应弃权的题；
   - 每题写明：提示词、范围（选中对象）、期望工具序列（允许顺序无关时写明）、期望的结果事实（如成本合计 2080）、期望写入（或期望不写）。
2. **运行器** `apps/muyon/lib/assistant/agent_eval/agent_eval.dart`：用 `MuyonHost`（新数据目录）驱动现有 `PersonalAgent`，自动按正确摘要确认，记录每题：
   - 是否成功（工具序列、结果事实、写入或不写入全部满足）；
   - **人工确认次数**，分为模型请求确认与工具审批；
   - 轮数、总时长、首个模型响应时延（现有为非流式，记“首个完整响应”并在报告中写明口径）；
   - token 用量（有则记）。
3. **夹具测试** `apps/muyon/test/agent_eval_test.dart`：用回环夹具模型（可参考 `north_star_fixture_model.dart` 和 `test/llm_selection_eval_test.dart` 的做法）跑完整任务集，断言评分逻辑：成功、工具缺失、多余写入、事实不符、请求失败都被正确判定；不访问网络。
4. **真实模型运行**：与 `llm_selection_eval.dart` 相同的约定——只有 `MUYON_EVAL_REAL=1` 且提供端点、模型、密钥环境变量时才发真实请求；只有 `MUYON_WRITE_EVAL_REPORT=1` 时才写报告 `docs/implementation/agent-task-eval-<模型 slug>.md`。夹具运行的结果**不得**写成真实模型证据。
5. **报告模板**：表格列出每类任务的成功率、确认次数（中位数 / 平均）、时延 p50 / p95、用量；文件顶部写明评测口径与“现状基线（第二阶段之前）”。

## 约束
- 不改 `lib/` 下现有产品代码的行为；如需测试钩子，只能加只读的访问器，并在回报中逐条列出。
- 不改已有测试的断言。
- 密钥只经环境变量读取，不打印、不写入报告或日志；报告里端点只写到路径。
- 本任务**不运行**真实模型（没有密钥）；报告文件不提交，留给有密钥的执行者。

## 验证
- `cd apps/muyon && flutter analyze` 无问题（info 也算失败）。
- `flutter test test/agent_eval_test.dart` 通过；宿主全量 `flutter test` 通过，贴数量。运行测试时取消代理变量并设 `NO_PROXY=localhost,127.0.0.1,::1`。
- 变异：把评分里的“多余写入”判定、“事实不符”判定各删一次，确认测试失败。

## 回报
分支与提交哈希；任务集的分类统计；夹具运行的结果摘要（注明是夹具）；测试数量；变异结果；新增的测试钩子（如有）。
