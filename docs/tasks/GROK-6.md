# GROK-6 科研本体盘点（REG-3 与本体业务卡片的前置）

分支 `task/grok-6-research-ontology` · 执行：grokbot（只做静态核对：读代码、grep、写文档；不运行 Flutter，不改代码）· 审查：leader A 抽查 · 给谁用：REG-3（科研迁 v2）、AIUI-7（科研场景）、AIUI-9（本体业务卡片）

## 背景
询价已经在 v2 契约里注册了完整本体（`apps/muyon/lib/app/adapters/inquiry_module.dart:308`），对话里的业务卡片可以先在询价落地。科研还没迁到 v2（REG-3），没有本体声明。本任务先把科研的数据结构静态盘清楚，给出本体初稿，供 REG-3 直接转成 `ModuleOntology`。可以参照 [GROK-5 询价盘点](../reviews/2026-10-09-inquiry-ontology-cards.md) 的格式。

## 只做这些
产出 `docs/reviews/2026-10-09-research-ontology-draft.md`，每个结论都附 `文件:行`：
1. **对象类型清单**：从 `packages/research_module/lib/src/core/`（`models.dart`、`store.dart`、`outline_store.dart`、`cards/card_store.dart` 等）和数据库表结构（schema / 迁移）里，找出所有业务对象：项目、文档、条目、任务、运行、笔记、绑定、提纲、章节、卡片等，以实际代码为准。逐个给出：
   - 中文名、一句话说明、对应的表、主键与版本字段；
   - 字段：名称、类型（按 ADR-0004 的 `FieldKind` 归类；归不进去的标「需要新类型」）、是否必填、枚举值、关联目标；
   - **建议敏感度**（`none` / `personal` / `commercial` / `credential`）及理由。科研里可能有作者、联系方式、未发表内容等，拿不准的单列，交用户确认。
2. **关系**：对象之间的引用（例如 条目 → 文档、运行 → 任务、卡片 → 文档），说明由哪个字段承载，是一对一还是一对多。
3. **写入方式**：每类对象的新建、修改、删除由哪个 Store 成员完成；有没有校验函数（没有就写明）；有没有级联效果，例如接纳运行会改什么。对照 [GROK-2 科研覆盖清单初稿](../reviews/coverage-drafts/research.md)，补上缺漏。
4. **卡片建议**：每类对象适合哪种卡片（新建 / 编辑 / 关联 / 批量），哪些应留在原页面（例如阅读器、关系图），理由要具体。导出、导入类按 ADR-0004 Q10 已确认的结论处理：报告和主张草稿的本机导出开放，其余暂不开放。
5. **REG-3 需要补的东西**：要让科研对象能用通用卡片新建、编辑，还缺哪些写工具、校验函数和版本字段；给出建议的工具清单（与 GROK-5 §5 的命名风格一致）。
6. 「未能静态确认」单列。

## 不做
不改代码、测试或已有文档；不运行 Flutter；不确定就写「未能静态确认」，不要猜。

## 回报
分支与提交哈希；文档路径；对象类型数与字段数；需要用户确认的敏感字段；建议的工具清单。
