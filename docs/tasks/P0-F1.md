## 问题
`packages/supplier_core/test/lan_security_test.dart` 中的 `stop cancels pending uploads and completes cleanup before returning`，在云端 Linux 沙箱里 14 次运行失败 11 次，错误为 `SocketException: Broken pipe ... SecureSocket.connect`（`lan_security_test.dart:90`，由 293 行的 `partial(node)` 触发）。同一测试在 GitHub Actions 上通过。不稳定的测试会让 CI 门禁时不时误报红，所以必须修。

初步怀疑：引入 TLS 1.3 和证书固定之后，服务端在握手后关闭连接，与客户端写入之间存在竞态。这只是推测，**需要先确认根因**。

## 要求
1. **先复现并定位根因。** 要回答清楚：是测试的时序假设有问题，还是 `supplier_core/lib/src/lan.dart`（或宿主 `TransferService` 所用的路径）在 `stop` 时确实存在竞态。如果是产品代码的问题，用户实际使用时会表现成什么样？
2. **按根因修复：**
   - 如果是测试问题：修改测试，让它等待确定的事件，**不要**靠加 `sleep`、加大超时或重试来掩盖；
   - 如果是产品问题：做最小修复，并补一个能稳定复现原问题的测试；
   - **不得**跳过、禁用或删除这个测试，也不得放宽它的断言。
3. **证明已经稳定**：在本机循环运行该测试至少 50 次，全部通过。用 `stress` 或并行跑其他测试制造负载，再跑 20 次，全部通过。把命令和结果写进提交说明。
