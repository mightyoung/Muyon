适用文档 v1.3.2　编制日期 2026年10月14日 北京时间

本目录供 M02、D01a、D01b、M03 和单元14实施者冻结合同、编制离线合成样本与核对验收范围。它补充最终复审 V132-I01、V132-S01、V132-S02、V132-S03，不修改两册、迁移表或 Android 原稿，不编写产品代码、不创建或提交仓库文件。

所有新增规则 ID、处理状态名和 fixture 字段均为**稳定拟定标识，待合同冻结，未实现、未运行**。已有 `USER-TEXT-v1` 名称继续沿用，也只是待实现合同。本文不把规则登记写成规则已经注册，不把 DOCS-G0、旧产品 CI 或文档 CI 通过写成新功能验收通过。

## 2 不变的边界

### 2.1 分类和动作许可分开

Sensitivity 仅为 `unreviewed / none / personal / commercial / credential`。来源、taint、业务核实状态、分类尝试状态、授权模式和效果回执分别记录，不增加“用户提供”“模型生成”“无规则”或“混合”Sensitivity。

`classified` 只说明某版本内容在特定规则覆盖域完成可信分类；命中 credential 也可以形成确定分类结果，但该内容不能进入模型或业务正文。分类完成不等于用途许可、不等于 Auto 低风险、不等于业务事实已核实，更不等于已经执行。

| 条件 | 必须遵守的动作边界 |
| --- | --- |
| FullAllow B；none/personal/commercial；当前任务、scope、读取权、用途和业务条件有效 | 可按相应有效合同使用，包括合法新业务目的地；不增加高风险、taint、首次端点或分类确认 |
| Auto，含新装默认 Auto | 仍由 D01a/D01b 已冻结的确定性 RiskDecision 决定自动、确认或拒绝。普通用户文本能否自动发模型不能由本目录代定 |
| Auto 所需风险规则或模式映射尚未冻结 | 分类结果可独立验证；动作侧记“合同未定”，不得宣称自动通过、套用 FullAllow 或随意加一套永久确认默认 |
| unreviewed 或当前版本未被规则完整覆盖 | 相应单元不进模型/业务载荷；用户确认、模型标签和切换 FullAllow 均不能解除 |
| credential 命中 | 不进模型、业务工具/分享正文、日志或诊断；身份绑定认证通道另行处理 |
| 已失权、有效明确用途禁止、服务硬限制、业务不合法、CAS 冲突 | 保留真实原因，按合同拒绝或重规划；不得借“风险确认”绕过，也不得把纯风险建议伪装成硬限制 |

### 2.2 字段与生成值的组合

模型生成值写入已声明字段时，执行以下组合，而不是从“字段”与“模型自由文本”两行任选一行：

1. 可信宿主确定命令、字段路径、schema 和声明版本。模型或 renderer 不能自报字段类别，未知字段不能借相邻字段通过
2. 字段声明提供基础类别；实际来源的限制、撤权/遗忘事实及可定位敏感内容继续继承。不能把商业来源复制进 none 字段来降类
3. 宿主捕获实际模型输出及其版本；输出规则覆盖参数中所有新文本。credential 检查须对应规范化后的实际新值，而非只查用户输入、旧值或示例值
4. 命中 credential 的内容单元禁正文；疑似、未检查、不完整或超出输出规则域的部分保持 unreviewed，并结束或更新其处理状态
5. 全部必要单元分类可用后，仍按当前用途、模式、scope、业务校验、计划/revision 和真实能力执行。检查后的参数若改变，旧证据失效

对干净的已覆盖模型输出，基础类别来自字段声明，而不是因 `source_kind=model_generated` 永久 unreviewed。对继承了个人/商业来源的片段，保留逐单元类别及限制共同核验，不用单个 none 或新“混合”枚举覆盖它们。

### 2.3 保留直 Rust 入口

用户在供应商编辑页已经给出完整新名称时，`domain_command` 直接进入 Rust 的计划、字段、权限、CAS 和回执链。没有新模型输出就不要求模型输出规则，不能为给字段分类而调用模型。已有输出被用户采纳后，仍保留它真实的模型来源和当前内容版本，不得改标成纯用户原创来消除检查。

本目录的模型名称样本使用假模型结果或固定合成输出验证边界，不改变首片“无真实模型、无新端点调用”的范围。它是需要生成内容时的附加路径与安全合同，不替换 D01.1 默认确定性改名路径。

## 4 合成 fixture 记录与执行顺序

### 4.1 每个样本需要的证据

最终字段名以 M03 单一 schema 为准。此处是语义清单，不能生成独立且不兼容的第二套产品 DTO。

- 主编号、子 case ID、合成输入版本和 hash；准确实现 SHA、schema hash、规则版本及测试命令
- 内容单元 ID、真实或合成宿主来源事件引用、source_kind、来源版本、task/scope/purpose；模型输出另绑 ModelTurn/ToolInvocation 或假输出事件
- 对象/字段路径和声明版本；基础类别、继承类别与用途限制；不可由模型填写的宿主判定来源
- 规范化/解析版本、已覆盖页/chunk/字段/区间、未覆盖部分、credential 检查 complete/incomplete 及非秘密原因码
- 分类尝试 ID与处理状态；内容修正、规则更新或来源变化后使用新版本/新尝试，旧结果不可原地冒充新内容结果
- 模式及其规则版本、RiskDecision、能力/计划/revision验证结果；分类结果与派发决策分栏
- 最终 payload 摘要、实际模型/业务调用计数、认证通道身份、日志/通知/历史/证据投影；数据库diff和回执在涉及写入时登记
- `pass / fail / not_run / blocked_contract`，以及独立审查人与准确证据范围。本文所有工程执行状态为 `not_run`

生产证据只保留必要引用和受保护摘要，不保存真实秘密样本、原文片段、含秘密URL、裁剪差分或可反推秘密的公开低熵摘要。摘要的存储与访问本身也受相应用途及保留策略约束。合成canary可以在隔离测试输入中受控存在；最终输出和一般测试日志不得回显canary全文，断言以命中/缺失、受控引用及计数呈现。

### 4.2 确定性顺序

1. 冻结本次内容版本、来源事件、任务/scope、字段声明与来源限制；捕获待执行的真实参数，不能先检查后追加内容
2. 完整解析并规范化，在明确覆盖域中选择已冻结规则；仅排队有可运行规则的分类任务

## 7 V132-S02 的处理状态补充

建议在 Android 补充第4条和两端共用状态投影中登记 `classification_attempt_state=no_coverage`，中文显示“无覆盖规则”。这是拟定处理状态名，最终编码由 M03 同源schema冻结；**不是第六种 Sensitivity，也不是永久数据属性**。

| 处理状态或结果 | 含义 | 后续行为 |
| --- | --- | --- |
| 尚未开始 / classifying | 有待执行或正在执行的明确分类工作 | 仅在存在可运行规则与当前内容版本时推进；不得对不存在的规则无限排队 |
| classified | 当前内容在该规则域已有可信类别 | 再经purpose/模式/业务门禁；credential仍禁正文，不自动allowed |
| no_coverage | 当前内容/解析器/provider/schema不在可用规则支持域；本次尝试终态 | 单元保留unreviewed，不发送；显示具体原因和可用的修改/补材料入口；不承诺等待后自行完成 |
| 解析/扫描失败、疑似秘密无法判定 | 本次尝试已得到具体不可用结果，处理原因与no_coverage分开记录 | 对应部分unreviewed；有真实可恢复条件时按任务合同新尝试，不把失败当无命中 |
| 失权 / 用途禁止 / 规则证据失效 | 对应权限或证据条件已变 | 阻断相应使用；分类成功历史不复活授权或被遗忘内容 |

终态的边界是“该内容版本＋规则版本的这次分类尝试”。新支持规则上线、新解析能力确实可用、或用户提供新内容后，可以建立新尝试；必须重验当前来源、用途、权限及内容，不能通过原地把no_coverage改为classified来假装旧规则曾经覆盖。

状态机不引入新产品开关、后台轮询任务或自动安装解析器；缺覆盖与能力不可用分别提供原因，独立已覆盖单元仍可按完整性规则继续。
