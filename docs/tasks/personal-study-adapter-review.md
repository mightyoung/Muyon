# Personal study adapter review

Read-only source review against `docs/superpowers/specs/2026-10-28-personal-study-app.md`, 2026-10-28. No Gradle build or device test run. Findings refer to the reviewed working-tree versions; MainActivity is concurrently being revised.

## Findings

1. **P1 — Fresh installs cannot use offline voice.** `apps/study_android/app/src/main/java/com/mightyoung/muyon/study/adapters/OfflineSpeech.kt:58` unconditionally opens `assets/model.zip`, but the study app assets contain only `mem-papers.json`, and its Gradle configuration does not provide the archive. Every first recognition attempt therefore reaches the generic failure message. Package the expected Chinese Vosk archive or implement an explicit verified download/install flow; verify the final APK contains it and the archive root matches `ArchivePaths`. A clean-device smoke test is required.

2. **P1 — Android 13+ users have no reminder permission flow.** `MainActivity.kt:44` registers the notification launcher but never launches it. `DueReminders.kt:26` exits before scheduling when notification permission is missing. New installations therefore silently retain task data without an in-app route to enable due reminders. Request POST_NOTIFICATIONS from an explicit reminders action (or first due-task save), then reconcile the current snapshot when permission is granted. The callback currently only shows a message, so merely adding the launch does not schedule the saved tasks.

3. **P2 — Recognition loses earlier fragments and permits callbacks after dismissal.** `OfflineSpeech.kt:38-44` forwards each Vosk result independently, and `MainActivity.kt:69` replaces `voiceText` with each result. After a pause, a later recognized segment replaces the previous segment rather than accumulating the fragmented input required by the spec. Also, `stop()` at line 74 only sets `stopped`; queued callback guards check generation/closed but not stopped. A result queued immediately before cancel can run after `onVoiceDismiss` clears the dialog and reopen it. Accumulate final segments per recording session; invalidate that session on stop/cancel and check it inside posted callbacks. Test two finalized utterances and dismiss-before-callback delivery.

4. **P2 — Drive file access and cloud backup recovery are not connected to a user action.** `MainActivity.kt:59` only lists files; `StudyUi.kt:132-133` renders text and a Close button. No call site invokes `Providers.driveDownload` (`Providers.kt:110`) to preview/import a selected file or restore a cloud backup. The authorized `drive.file` scope is appropriate for app-created files and files explicitly selected for the app, but no picker grants access to existing arbitrary Drive files. Add a selected-file import/restore action plus a Google Picker or supported Android document-provider selection flow; do not promise all-Drive visibility under this scope. If `driveDownload` is used for backups, raise/configure its current default 32 MiB response cap to match the 256 MiB supported backup size, or consistently lower the export cap and disclose it.

## Checked without a blocking finding

- `/tmp/maimemo-api.yaml` confirms POST `/open/api/v1/memo/study/get_study_progress`, no request body, top-level `progress`, integer `finished`, `total`, `study_time`, with study time in milliseconds. The adapter matches that primary schema and preserves the units/freshness warning. Its extra `data.progress` compatibility path does not break the official response. Existing fixtures cover the official top-level payload and malformed fields.
- Calendar reads paginate calendar lists and events, omit cancelled events in an authoritative snapshot, and complete all requests before callers dispatch an update. Publishing only creates deterministic IDs in a marked owner calendar, reports modified/manual events as conflicts, and does not overwrite them. Partial/uncertain write errors are not automatically retried.
- Credentials are AES-GCM encrypted using Android Keystore and stored outside the exported study snapshot. Android automatic backup is disabled. No plaintext credential export path found.
- Plan ZIP parsing bounds decompressed bytes, rejects duplicate/traversal entries, and rejects DTD/external entity XML. Invalid files fail before a task preview is committed. StudyFiles stages restore files in unique directories, rewrites resource paths, and cleans staged/installed files on parsing failure; it does not overwrite existing resources.
- Reminder reconciliation cancels old alarms/notifications, filters done/deleted tasks, persists the new task snapshot, and restores future alarms after boot/time changes. Notification permission integration above remains the blocker. Exact-alarm denial has an inexact fallback and communicates delay.

## Validation gaps

Existing JVM tests cover import examples/path attacks and Maimemo parsing, but not Android speech cancellation/accumulation, model availability in the APK, notification permission grants/reconciliation, reboot/done/delete delivery, Drive restore, or backup failure atomicity. These need focused adapter/device checks; this review does not claim they were run.
