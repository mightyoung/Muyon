# LE-04：宿主本机导出生成与清理状态机

执行：Haiku。派发：leader A，2026-10-11。集成：Leader B。基线：LE-01 `task/le-01-local-export-contract` @ `202e44af`（LE-01 合入 develop 后改为最新 develop）；分支 `task/le-04-export-staging`。依据：CR-17 设计 `docs/design/research-local-export-facade-2026-10-11.md`（在 `task/cr-15-17-chatgpt`）第 1.4、3.1–3.3 节。

## 范围（宿主侧，`apps/muyon/lib/platform/` 下新文件；不接工具、不做审批、不做系统另存为、不碰 Sonnet 的 LE-05 文件）
1. 生成协调器：输入 LE-01 的导出准备（冻结字节 + SHA-256 + 导出种类）与宿主给定的科研导出目录（`<科研目录>/exports`），执行：排他创建本次操作拥有的临时文件 → 写入冻结字节 → 关闭 → 核对长度与 SHA-256（宿主侧用 `crypto` 计算）→ 原子提交为完整文件 → 返回 LE-01 的分阶段生成结果。
2. 命名：宿主生成 `report-<exportId>.md`、`workbench-claims-<exportId>.jsonl`；`exportId` 宿主生成；不拼项目标题或原始 ID；同名一律不覆盖（排他创建）。
3. 失败 / 取消：写入中失败或取消 → 清理本次临时文件，结果为 failed / cancelled；清理本身失败要单独记录在结果里，不能报「已清理」。已提交的完整文件不被后续取消删除。
4. 越根防护：最终文件必须在导出目录内；拒绝目录或目标是符号链接的情况；不能只靠 `startsWith`。文件系统操作通过一个可注入的小适配器，测试可用替身注入故障（磁盘满、权限不足、关闭失败、清理失败）。

## 测试先行
正常生成：文件内容逐字节等于冻结字节，SHA-256 一致；磁盘满 / 权限不足 → failed，无残留临时文件；写入中取消 → cancelled，无残留；清理失败 → 结果如实标注清理失败；同一 exportId 重复生成 → 拒绝覆盖；导出目录是符号链接或目标被替换为符号链接 → 拒绝；字节长度或摘要不符 → failed 且不提交；半成品永远不会以最终文件名出现。

## 变异（必须做）
跳过摘要核对；失败时不清理临时文件；去掉符号链接检查。都必须被测试抓到。
