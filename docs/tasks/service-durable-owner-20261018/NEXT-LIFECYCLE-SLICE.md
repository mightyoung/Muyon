## Exact present call chain and gap

`MuyonLabApplication` does not implement `ServiceHostOwnerInstallation`. `AgentRuntimeService.onCreate` reserves the retained controller slot, then its background bootstrap calls `ServiceHostBindings.resolve(this)`. `resolve` casts `serviceContext.applicationContext`; because the Application has no installation, it returns SyntheticLab. `GeneratedAgentController.open` therefore calls `AgentServiceController(config)` rather than `.withHost(config, ServiceHostBindings.callback(owner), mode, budget)`. The new owner is not instantiated or retained anywhere on that actual path.

The existing Installed branch and genuine generated `.withHost` constructor already exist. There is no need to introduce Dart, infer authority from UI/Binder data, or change UI merely to select an explicitly installed owner.

A second, distinct execution gap exists: Rust `service_host.rs::configured_readiness` calls `bridge.readiness(&budget)` and then unconditionally returns `configured_transport_unavailable`. `supplier_business.rs` explicitly performs no reserve/commit there. Switching the Application to Installed alone will exercise provider metadata/existence callbacks but WILL NOT exercise review/reserve/commit or prove persistent admission across restart. There is currently no exported Service-owned metadata-only prepare/final_admit operation. This is a concrete missing execution contract, not a reason to silently enable transport or claim the readiness path consumed the ledger.
