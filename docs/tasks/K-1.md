# K-1 模型适配层与 Agent 循环设计（ADR-0005）

分支 `task/k-1-model-adapter-adr` · 执行：Sonnet 5.5 子代理（leader 派发）· 审查 leader · 阶段：第二阶段（[ADR-0003](../adr/0003-phase2-scope.md)）· 性质：**只写设计文档，不改代码**

## 背景
生产助手 `apps/muyon/lib/assistant/personal_agent.dart` 用自定义 JSON 协议（`{"type":"tool"|"answer"}`），非流式（`services/models/model_gateway.dart` 请求里 `stream: false`），最多 4 轮，45 秒总超时；P0-3d 加了至多一次协议纠正（DeepSeek 曾返回 `<｜｜DSML｜｜ calls>` 这类非 JSON 内容）。原生 function calling 只在评测器 `assistant/selection_eval/llm_selection_eval.dart` 里用过（`.` 编码为 `__`）。见[深度研究报告](../reviews/2026-10-05-muyon-deep-review-and-optimization.md) §6.2、[路线图](../superpowers/plans/2026-10-07-roadmap-phase2-4.md) §3。

## 交付
`docs/adr/0005-model-adapter-and-agent-loop.md`，状态“提议”，包含：
1. **现状**：逐项写清当前调用链（`PersonalAgent` → 网关 → 出站账本 `platform/outbound_ledger.dart` → `ToolRegistry`），每条带 `文件:行号`。包括：确认流程与 `requestDigest`、轮数与超时、协议纠正、取消与中断语义、出站入账时机、脱敏（`credential_redaction.dart`）。
2. **模型适配层**：`ModelCapabilities`（原生工具、并行工具、流式、JSON schema、上下文长度）与 `ModelProvider`（事件流：文本增量、工具调用增量 / 完成、用量、结束、错误）的 Dart 接口草案；OpenAI 兼容端点的映射；不支持原生工具的端点如何回退到现有 JSON 协议（显式能力声明，不隐式回退到其他模型）。
3. **流式与出站账本**：流式时“记不进账就不发送”如何保持；中途取消、断流、部分输出如何记账与展示。
4. **预算式 Agent 循环**：取代“4 轮 / 45 秒”，用步数、时长、token 预算；每步的状态机；与执行记录事件化（K-4，`task_events`）的衔接点。
5. **与 ADR-0002 分级授权的衔接**：模型请求按 `ModelLocation`（本机 / 本人设备 / 远程）决定是否询问；`requestDigest` 在“仅这一次”与审计中的作用；工具调用仍经 `ToolRegistry.prepare` 与一次性审批。
6. **迁移与拆分**：K-2（适配层 + 流式 + 原生工具）、K-3（预算循环）、K-4（事件化）的边界、顺序、每项要改的文件与需要新增 / 改写的测试；哪些现有测试必须保持不改（如 `personal_agent_test`、`personal_agent_rejections_test`、`assistant_cancel_test`、`outbound_ledger_test`、`north_star_inquiry_test`）。
7. **风险与待决问题**（交用户决定的单独列出）。
