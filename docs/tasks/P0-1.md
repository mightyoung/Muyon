# P0-1 PR/push 自动门禁

分支 `p0-1-ci` · 执行 engineer（Sonnet）· 审查 senior（Opus）

## 目标
现有 `.github/workflows/verify.yml` 只能手动触发且只在 macOS 运行。增加对 develop、main、feat/** 的 push 与 pull request 自动门禁，`verify.yml` 保持不变。

## 交付
1. `scripts/ci.sh`：由 `scripts/verify.sh` 派生、适合 Linux 的门禁。`flutter pub get`，对七个包 `flutter analyze`，再跑同样的测试套件，排除 golden/截图测试（基准图在 macOS 生成）和确实无法在无头 Linux 上运行的测试。排除必须明确且最少：优先用 tag（检查 `dart_test.yaml` 与 `@Tags`），否则列名单并逐条写原因。不能因为测试失败就排除它：非 golden 测试在 Linux 失败时先排查，平台限制才列入排除，真实缺陷要报告。
2. `.github/workflows/ci.yml`：ubuntu-latest，`subosito/flutter-action@v2`（3.47.5 stable，开缓存），运行 `bash scripts/ci.sh`，上传日志，`permissions: contents: read`，并发组取消过期运行。像 `verify.yml` 一样跑四个 Laya Python 脚本测试。
3. `scripts/ci.sh` 顶部注释说明与 `verify.sh` 的差异及原因。

## 验证
在分支上 `bash scripts/ci.sh` 退出码 0；YAML 可解析。

## 环境
Flutter 3.47.5 在 `/opt/sdk/flutter/bin`。`flutter pub get` 需要保留代理环境；跑测试时按 `verify.sh` 去掉代理并设 `NO_PROXY=localhost,127.0.0.1,::1`。命令被权限系统拒绝时停下报告，不绕过。

## 回报
分支与提交；`ci.sh` 最终摘要行；排除清单及原因；发现但未排除的真实失败。
