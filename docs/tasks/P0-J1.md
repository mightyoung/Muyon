# P0-J1 取证环境自检脚本

分支 `task/p0-j1-env-doctor` · 执行 junior（opencode）· 审查 engineer（Sonnet）

## 背景
第一阶段要在真机和真实模型上取证（见 [第一阶段执行计划](../superpowers/plans/2026-10-05-phase0-plan.md)）。跑之前常因为环境不全白跑一趟：Flutter 版本不对、设备没连上、缺 Xcode/Java、模型端点或密钥配错、本机代理干扰 Flutter 测试。需要一个只读的自检脚本，一次列出哪里没准备好。

## 你只做这些
在分支 `task/p0-j1-env-doctor` 上**只新增**两个文件，不修改仓库里任何已有文件：

1. `scripts/doctor.sh`
2. `scripts/test_doctor.sh`

完成后提交到本分支。不要推送到其他分支，不要合并 `develop`。

## `scripts/doctor.sh` 要求

**运行方式：** `bash scripts/doctor.sh`，可加 `--json`。要能在 macOS 自带的 bash 3.2 和 Linux bash 上运行，所以不要用关联数组、`mapfile`、`${var,,}`。可以用 `python3` 解析 JSON。

**每项检查输出一行：** `状态<TAB>检查名<TAB>说明`，状态只能是 `OK`、`WARN`、`FAIL`、`SKIP`。最后一行汇总：`summary: N ok, N warn, N fail, N skip`。

**退出码：** 有任何 `FAIL` 时退出 1，否则退出 0。

**`--json`：** 不输出表格，改为向标准输出打印一个 JSON 对象 `{"checks":[{"status":"OK","name":"...","detail":"..."}],"summary":{"ok":0,"warn":0,"fail":0,"skip":0}}`，退出码规则不变。

**检查项（按顺序）：**

| 检查名 | 怎么做 | 判定 |
|---|---|---|
| `flutter` | `flutter --version`，取版本号 | 找不到命令 → FAIL；版本不是 `.github/workflows/verify.yml` 里的 `flutter-version`（从该文件读，不要写死）→ WARN；相同 → OK |
| `devices` | `flutter devices --machine`，用 python3 解析，列出每个设备的 `name` 与 `targetPlatform` | 命令失败 → WARN；没有任何设备 → WARN；有 → OK，说明里列出设备 |
| `android` | `adb version` 与 `java -version` | 两者都有 → OK；缺一个 → WARN（说明缺哪个） |
| `xcode` | 只在 `uname` 为 Darwin 时运行 `xcodebuild -version` | 非 Darwin → SKIP；失败 → WARN；成功 → OK 并给出版本 |
| `proxy` | 看 `HTTP_PROXY HTTPS_PROXY ALL_PROXY` 及小写同名变量 | 有任何一个 → WARN，说明"运行 flutter test 前请按 scripts/verify.sh 去掉代理"；都没有 → OK |
| `model-env` | 看 `MUYON_EVAL_MODEL_ENDPOINT`、`MUYON_EVAL_MODEL_ID` | 都没设 → SKIP（"未配置真实模型，只能跑夹具"）；只设一个 → FAIL；端点不是回环地址（`localhost`、`127.0.0.1`、`::1`）且不是 `https://` → FAIL（远程端点必须 HTTPS）；否则 OK，说明里标"本机"或"远程" |
| `model-key` | 远程端点时看 `MUYON_EVAL_MODEL_KEY` 是否非空 | 没配置模型 → SKIP；远程且为空 → FAIL；本机 → OK（不需要）；其余 → OK |
| `model-reach` | 仅当上面两项都 OK：把端点末尾的 `/chat/completions` 去掉，得到基址，`curl -sS -o /dev/null -w '%{http_code}' --max-time 10` 请求 `基址/models`，有密钥时带 `Authorization: Bearer $MUYON_EVAL_MODEL_KEY` | 前置不满足 → SKIP；200 → OK；401/403 → FAIL（"凭据被拒绝"）；其他状态或连不上 → WARN 并给出状态码 |

## 安全要求（必须遵守）
- **绝不打印、记录、写入密钥。** 说明文字里只能写"已设置/未设置"。用 `set -x` 调试后要删掉。
- 只发 `GET /models`，**不要**发任何对话或补全请求，不要上传任何内容。
- 不写任何文件，不修改环境，不安装东西。

## `scripts/test_doctor.sh` 要求
- 用一个临时目录放假的 `flutter`、`adb`、`java`、`curl` 小脚本（例如假 `flutter --version` 输出 `Flutter 3.47.5 • channel stable`），把它放到 `PATH` 最前面后运行 `doctor.sh`，再检查输出。
- 至少覆盖以下 6 个场景，每个场景打印 `PASS 场景名` 或 `FAIL 场景名`：
  1. 版本一致时 `flutter` 为 OK；
  2. 版本不同时为 WARN；
  3. 没配置模型时 `model-env` 为 SKIP 且退出码 0；
  4. 远程 `http://` 端点时 `model-env` 为 FAIL 且退出码 1；
  5. 假 `curl` 返回 `401` 时 `model-reach` 为 FAIL；
  6. 设置 `MUYON_EVAL_MODEL_KEY=sk-test-secret` 后，整个输出（包括 `--json`）里找不到 `sk-test-secret`。
- 全部通过时退出 0，否则退出 1。不依赖网络，不依赖真实 Flutter。
