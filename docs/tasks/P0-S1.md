# P0-S1 模型网关与助手的凭据脱敏

分支 `task/p0-s1-credential-redaction` · 执行 senior engineer · 审查 leader · 来源：[P0-2 复核](P0-2-review.md)「留作记录」· 性质：安全修复（范围冻结允许）

## 问题
密钥格式异常时，例如末尾带回车或混入全角字符，dart:io 设置请求头会抛出 `FormatException`，异常文本里含完整的 `Bearer <密钥>`。这段文本目前会流到几个会持久保存或展示的地方：
1. `apps/muyon/lib/services/models/model_gateway.dart` 的 `request()`：请求失败时把 `'$error'` 写进出站账本 `outbound_requests`。`ledger.begin` 在设置请求头之前执行，所以这条记录已经存在。
2. `apps/muyon/lib/assistant/personal_agent.dart` 的 `confirm()`：把 `'$error'` 截断后写进任务的 `error` 字段。这个字段会持久保存在 `execution_records`，显示在助手界面上，并作为通知正文发出。
3. 其他调用网关、并保存或显示错误文本的地方，需要逐一排查：`qa_service.dart`、`dream/dream_service.dart`、`services/knowledge/embedding_service.dart`、`app/inquiry_plugin.dart`，以及询价模块里经由宿主网关的路径。

P0-2 的评测里已有 `redactCredentials`，评测只在自己内部做了脱敏，正式应用没有。

## 要求
1. **共享脱敏函数**：在 `apps/muyon/lib/services/models/` 下新建一个文件，提供脱敏函数，供网关、助手和评测共用。
   - 含 `bearer` 或 `authorization` 的错误文本整条不显示，只保留异常类型和固定说明。规则与评测保持一致。
   - 评测改为调用这个共享函数，删掉评测里的重复实现，行为保持不变。
2. **网关提前校验**：读取凭据之后、`beforeSend` 与 `ledger.begin` 之前，校验凭据只包含可见 ASCII 字符。不符合时抛出 `StateError('credential_invalid')`，消息中不含凭据值。这样不会发出请求，也不会生成账本记录。
3. **写入账本前脱敏**：所有写进账本的错误文本先经过脱敏函数。
4. **助手和其他调用方**：写入任务记录、通知或界面之前，错误文本先经过脱敏函数。第 3 条列出的位置都要排查，每处在提交说明里写明「已处理」或「不涉及」，并说明理由。
5. **保存密钥时校验**：在设置里添加模型、保存密钥的界面上，密钥含不可见字符、换行或全角字符时拒绝保存，提示「密钥含不可见或非 ASCII 字符，请重新粘贴」，不回显密钥。不要静默修剪，以免把错误的密钥存进去。

## 测试
- **网关**：密钥格式异常时，抛出 `credential_invalid`；回环服务器收到 0 次请求；账本中没有新记录。另外构造一个绕过前置校验、在设置请求头时出错的情况，断言账本里的错误文本不含密钥。
- **助手**：用格式异常的密钥走完一次确认流程，断言任务的 `error` 字段、通知正文和会话消息都不含密钥。
- **脱敏函数**：单元测试覆盖 `Bearer xxx`、`authorization: xxx`、大小写变体，以及不含凭据的普通错误（原样保留）。
- **设置界面**：widget 测试，粘贴带回车的密钥时拒绝保存，界面上不显示密钥。
- 不修改已有测试的断言，只新增测试。
