# P0-S2 MCP 令牌凭据脱敏

分支 `task/p0-s2-mcp-token-redaction` · 执行 senior engineer（P0-S1 修复之后）· 审查 leader · 来源：[P0-S1 审查](P0-S1-review.md) F4 · 性质：安全修复（范围冻结允许）

## 问题
如果 MCP 服务器配置的令牌格式不对，比如末尾带回车，`platform/mcp_adapter.dart:208` 在设置请求头时会抛出 `FormatException: Invalid HTTP header field value: "Bearer <令牌>\r"`。这条报错会被原样显示到 `screens/mcp_servers_page.dart:213` 的页面上（`'$failure'`）。这和 P0-S1 修过的模型网关是同一类漏洞，只是这次泄露的是 MCP 令牌。

## 要求
1. **复用共享脱敏函数**：使用 P0-S1 新增的 `services/models/credential_redaction.dart`。如果 P0-S1 还没合入，先合并 `review/P0-S1`，或者等它合入 `develop` 后再从 `develop` 合并。
2. **提前校验令牌**：`mcp_adapter` 在设置请求头之前，先校验令牌是否只包含可见 ASCII 字符。不合规时抛出不带令牌值的错误（例如 `StateError('mcp_token_invalid')`），并且不发出任何请求。
3. **脱敏所有对外的错误文本**：凡是会显示到界面、写入存储或日志的 MCP 错误文本，都先经过脱敏函数。如果令牌值本身出现在文本里，替换成 `<redacted>`。
4. **保存时就拒绝**：MCP 服务器配置页保存令牌时，遇到不可见字符或非 ASCII 字符直接拒绝，提示文案与模型密钥保持一致，并且不回显令牌。
5. **排查其他凭据**：检查 `mcp_adapter` 以及 MCP 服务器配置的存储与展示路径中，还有没有别的凭据（例如环境变量、URL 中的令牌）会被原样显示或保存。逐项写出「已处理」或「不涉及」。

## 测试
- 令牌格式异常时：抛出 `mcp_token_invalid`，回环服务器收到 0 次请求，页面上看不到令牌。
- 绕过提前校验、构造一个原样带令牌的异常时：页面显示的文本里不含令牌。
- 配置页保存格式异常的令牌时：被拒绝，不写入存储。
- 不修改已有测试的断言。
