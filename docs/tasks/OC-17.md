# OC-17：REG-3c 多行写入中途失败整体回滚测试

执行：opencode。派发：leader A，2026-10-11。集成：Leader B。基线：PR #49 head（`task/reg3f-reg3d-integration-repair-20261011` @ `ee831084`）；分支 `task/oc-17-reg3c-rollback`。**只加测试，不改 `lib/` 下任何文件。**

## 依据
CR-13「应补」：多行更新 / 级联删除中途失败时，业务行与变更日志要整体回滚；拒绝和失败不产生新增日志。

## 做法
用 SQLite 触发器在测试里注入失败（参照 `apps/muyon/test/assistant_authorization_facts_test.dart` 里 `CREATE TRIGGER ... RAISE(ABORT, ...)` 的写法），只在测试数据库上建。新建 `apps/muyon/test/oc17_reg3c_rollback_test.dart`，搭法照抄 `oc16_reg3c_changes_exact_test.dart`。
1. `delete_section rolls back when an outline delete fails midway`：S1 引用两条证据（两条 outline 链接）；建触发器：删除 outline 中第二条链接时 ABORT；用正确的 deleteDigest 确认删除 S1 → 回执非成功；S1 仍在、两条链接都在、research `change_log` 与模块变更日志行数与内容都和删除前一样。
2. `update_section heading rolls back when a linked outline update fails`：S1 有两条链接；触发器在更新第二条链接的 heading 时 ABORT；改 S1 的 heading → 非成功；S1 与两条链接的 heading 都保持旧值；日志无增量。
3. 正对照 `delete_section succeeds without the trigger`：同样数据、不建触发器 → 成功，S1 和两条链接都没了，日志有对应记录。

断言前先证明触发器真的生效（例如测试 1 里先单独执行一次会被拦的 SQL，确认抛错，再恢复数据）——不能因前提不成立而假通过。

## 变异（必须做）
在 `packages/research_module/lib/src/core/outline_store.dart` 的级联删除里，临时把删链接和删段落拆到不同事务（或把段落删除挪到链接删除之前并单独提交），测试 1 必须失败；做不到这种变异就改为：临时把 `module_tools.dart` 的 `store.write(() {...})` 拆成两次写，测试 1 或 2 必须失败。回报失败第一行后恢复。

## 停止条件
回滚实际不成立（触发器拦截后仍有部分行被删或日志增加）：不改源码，停下回报失败第一行与残留情况——这是需要修的缺陷。
