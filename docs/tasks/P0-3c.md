# P0-3c 询价链路判定收尾（低优先级）

分支 `task/p0-3c-chain-per-question` · 执行 senior engineer（P0-F1 之后）· 审查 leader · 来源：[P0-3 第 2 轮复核](P0-3-review.md)「留作后续」

## 背景
P0-3 已经合入。在本任务完成之前，leader 审查 P0-4 证据时会人工逐题核对每道题用了哪些工具。本任务把这项核对改为由链路自动判定，并补上两处小问题。只修改 `apps/muyon/integration_test/support/` 下的文件和运行手册，不改生产代码。

## 要求
1. **N1 逐题判定。** `_drive` 已经按题记录了 `receiptsBefore`，用它判定：
   - 比价题的工具结果中必须有 `inquiry.compare_quotes`；
   - 预算题的工具结果中必须有 `inquiry.project_budget`。

   不满足时运行失败，`failure` 写明是哪道题缺了哪个工具。补一个夹具或探针测试：模型交叉使用工具（比价题只用 `knowledge.search`，预算题同时调用两个工具）时，运行必须失败。
2. **N3 开关值。** `MUYON_EVAL_REAL` 只接受 `1`。设置为其他非空值（如 `true`）时，打印一次提示「MUYON_EVAL_REAL 只接受 1」，然后照常跑夹具。
3. **N4 写入步骤标记。** 写入核验失败时，`assistant.write.create_inquiry` 这一步要标为 `ok:false`，与 R2-D 对只读步骤的处理方式一致。
4. **运行手册**：同步更新第 123 行附近关于 2.3 的说明。

## 验证
- `flutter analyze`（apps/muyon）无问题。
- 无头链路测试通过。
- 新增的交叉工具测试会失败，且原因写在 `failure` 中。
