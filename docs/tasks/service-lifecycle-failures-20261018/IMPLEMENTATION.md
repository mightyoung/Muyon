## Ownership changes

- AgentRuntimeService denies all calls synchronously after retirement, then dispatches potentially mutex-blocking native retirement to existing backend/settlement pump. Platform onDestroy never waits behind native owner callback.
- onReady throw requests real controller disposal and settlement instead of leaving a published unavailable native controller forever.
- ServiceHostLease records attempted versus completed close. Failed owner close never becomes successful through a second no-op close; native/owner/slot stay retained conservatively.
- Internal no-op lifecycle hooks are installed only through Application/lease composition; no IPC or runtime selector was added. Successful cleanup remains genuine native close, then owner close, then unique-slot release.

Independent static review also found a previously uncovered path: with actual controller still constructing, unbind/destruction queued bootstrap retirement behind construction. A second queued dispatch could reject, mark setupFailed, and trigger shutdown while the unique slot was reserved but unpublished. Later installed rejection cleaned the controller and shut down the backend, after which the queued bootstrap retirement attempted another waiter submission on the shutdown executor, throwing uncaught RejectedExecutionException inside its task. This issue was identified statically; it was not reached by the first failed-build CI run.

The follow-up adds `AgentServiceBootstrap.requestRetirement()`: platform caller marks retirement immediately under the bootstrap lock; the active construction/initializer worker owns native retirement and settlement. If no worker is active, one guarded direct retire/await task is submitted. There is no task that queues another task in this asynchronous path. Rejected submissions and direct task failures report unavailable while retaining ownership; synchronous legacy `retire()` waiter dispatch rejection is guarded too. The worker loop handles retirement arriving during its initial waiter without missing the native signal. AgentRuntimeService uses this lock-only request when its published controller is absent. Destruction shuts down only when there is no reservation or cleanupCompleted is proven, never from a null retained() value that could still mean a reserved unpublished native controller.
