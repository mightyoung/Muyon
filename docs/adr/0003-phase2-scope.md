# ADR-0003 第二阶段范围

日期：2026-10-07 · 状态：**已采纳**（用户 2026-10-07 确认阶段划分）· 生效：第一阶段退出报告提交之后 · 计划：[第二至第四阶段路线图](../superpowers/plans/2026-10-07-roadmap-phase2-4.md)

## 背景

ADR-0001 冻结了第一阶段范围。第一阶段即将退出（退出标准第 1 项由用户 2026-10-07 决定接受 macOS 证据）。深度研究报告指出范围曾三次调头，因此每个阶段开始前先写明边界。

## 决定

角色、派发、审查、合入沿用 ADR-0001 §1～§3。

### 允许

- 路线图 §3 的任务：K-1～K-4（Agent 内核 v2）、AUTH-1（分级授权与内容审查接口）、UI-0～UI-5、UI-7、E-1（多步评测）、R-1（Android 取证）；
- **2026-10-07 修订（用户同意）**：注册机制 v2 REG-1～REG-5、范围模型 S-1、平台自省工具 T-3（见 [AI 原生与注册机制评估](../reviews/2026-10-07-ai-native-and-registration.md)）。模块契约 v2 的代码改动因此**在第二阶段允许**；
- 第一阶段搁置项中路线图 §7 排在第二阶段的；
- 测试失败、回归与安全缺陷的修复；审查提出的修复；
- 设计稿第五轮返工（设计方执行，不涉及代码）。

### 不允许（排到第三阶段或之后）

- UI-6、UI-8、UI-9（导航分区的**声明**在 REG-1 中定义，界面改造仍在第三阶段）；声明式插件 REG-6；
- 数据中心平台化、血缘、实例浏览器（DC-1～3）、AUTH-2；
- SOUL、规则配置（AS-1、AS-2）、记忆 v1、统一知识服务；
- iOS、常驻节点、MCP 服务端、科研 North Star A；
- OCR 原生三端、Laya 专门化、向量检索与 Dream 扩展、原型搭建能力。

例外需要用户确认。

### 退出标准

见路线图 §3：只读审批中位数 0、写 1；首字时延本机 < 1.5 s、远程 < 3 s；新外壳下询价 North Star 真机 + 真实模型证据；授权测试齐全且 CI 绿。2026-10-07 增加：示例模块只改模块包与一行登记、宿主零改动；询价、科研、原型通过契约合规测试，**能力覆盖为 CI 硬门槛**（每个业务操作有工具或写明不开放理由）。

## 后果

- 第二阶段集中在助手本身（内核、授权、界面）与 Agent 能力面（契约 v2、工具覆盖、范围模型）；导航界面改造（UI-8、UI-9）留到第三阶段，减少与新外壳的冲突。（2026-10-07 修订，原为“不碰模块契约”）
- 第三阶段开始前再写一份范围 ADR。
