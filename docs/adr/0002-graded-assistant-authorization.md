# ADR-0002 助手分级授权

日期：2026-10-07 · 状态：**已采纳**（用户 2026-10-07 决定方向，并确认 §5 两问）· 实施：第一阶段退出之后（ADR-0001 范围冻结）

## 背景

现状（`apps/muyon/lib/assistant/personal_agent.dart`、`apps/muyon/lib/platform/tool_registry.dart`）：

- **每一次模型请求**都进入 `waitingConfirmation`，用户核对 `requestDigest` 后才发出，不分本机或远程模型。
- **只读工具**在已解析的范围内直接执行。
- **写入 / 导出 / 联网工具**由宿主签发一次性审批（`tool_approvals`，绑定 `identity_digest`、`scope_digest`、`input_digest`，有过期时间，用后即 `consumed`，防重放）。
- 出站账本（`outbound_ledger.dart`）“记不进账就不发送”。

问题：一个三步任务要确认三四次，每次读一段 JSON（[深度研究报告](../reviews/2026-10-05-muyon-deep-review-and-optimization.md) 第 1 项）。v4 设计稿画了「助手权限」四类开关，但确认流程与代码不一致（[v4 审阅](../reviews/2026-10-07-design-v4-review.md) F2）。

用户 2026-10-07 决定：参考 ChatGPT、Claude、Muse，**设多级权限、分级控制**。

## 参考（公开资料，2026-10 检索）

| 产品 | 做法 |
|---|---|
| Claude Code | 模式定基线（default：只读免确认、其余询问；acceptEdits；plan：只读；dontAsk：只允许预先放行的）；单次询问可选“允许一次 / 本会话允许这一类 / 拒绝”；allow/deny 规则可按工具或命令细分 |
| ChatGPT 应用（连接器） | 默认“重要操作”档：读取自动，有外部影响、暴露敏感信息或难以撤销的操作前询问；“始终允许”把该应用改为不再询问；工作区管理员可限定 |
| Meta Muse | 授权可以是一次、一个会话、一个任务、一段时间或长期；部分应用可只给读不给写；外发动作经独立的权限代理（Sentinel）放行、拦截或上报用户 |

## 决定

### 1. 两个维度

**操作类别**（与 `ToolEffect` 对应）：

| 类别 | 例子 |
|---|---|
| 读取 | 范围内的只读工具 |
| 模型请求 | 把上下文发给模型；按 `ModelLocation` 分为 本机 / 本人设备 / 远程 |
| 写入 | `ToolEffect.write`，如 `create_inquiry`、`record_quote` |
| 外传 | `ToolEffect.export`、`ToolEffect.network`、MCP 调用、设备发送 |

**授权时长**（参考 Muse）：仅这一次 · 本次任务 · 本次对话 · 限时（如 1 小时）· 始终。

### 2. 三档模式（参考 Claude Code / ChatGPT）

| 模式 | 读取 | 模型请求 | 写入 | 外传 |
|---|---|---|---|---|
| **只读** | 自动 | 本机自动；其余同“标准” | 不提出 | 不提出 |
| **标准**（默认） | 自动 | 本机、本人设备自动；远程首次询问，可选“本次对话允许发往此端点” | 询问；可选“本次任务 / 本次对话 / 始终允许同一工具、同一范围” | 新端点逐次询问；已授权端点可选“本次对话允许” |
| **自定义** | 按规则 | 按规则 | 按规则 | 按规则 |

“自定义”由用户在「助手权限」页按 **类别 × 工具 / 端点 × 范围 × 时长** 建规则，受 §3 硬性底线约束。写入可以设为“始终”（§5 Q1）；外传对已授权端点最长可设为“本次对话”（§5 Q2）。

### 3. 硬性底线（任何模式、规则都不能放宽）

1. 授权只能由用户在宿主界面里给出。**模型回答、资料内容、规则配置、SOUL 都不能授予或扩大权限。**
2. 授权绑定 **工具 + 范围 + 目的地**；范围或目的地变化即失效，需重新询问。
3. 发往**从未授权过的远程端点**一律逐次询问。外传内容是否需要额外询问或拦截，交给**外传内容审查**（§4）；本期不实现审查，默认放行，并在审计中记“未审查”。
4. 每次实际执行仍走一次性审批与防重放回执：放行规则只是让宿主替用户签发审批，回执注明“由授权 #id 放行”。出站账本照常逐条入账。
5. 授权可随时撤销，并立即生效；所有授权的创建、使用、撤销进审计记录（「助手权限 › 变更审计」）。
6. 四类开关只能收紧：关闭某类后，助手不再提出该类操作，并提示“该操作类别已关闭，未提出”。

### 4. 实现要点（第一阶段之后）

- `muyon.sqlite` 新增授权表：`grant_id, category, tool_id, scope_digest, destination, duration_kind, expires_at, max_uses, uses, revoked_at`。`duration_kind` 取值 `once | task | conversation | timed | always`。
- **外传内容审查接口**（本期只留接口，不实现审查）：
  - 宿主定义 `OutboundContentReviewer`：输入为一次外传的 工具 / 端点 / 发送内容 / 范围 / 来源对象引用；输出 `allow` / `confirm(reason)` / `block(reason)`。
  - 外传在授权解析**之后**、签发审批**之前**调用审查器：`confirm` 让已授权的外传也改为逐次询问并展示原因，`block` 直接拒绝并入出站账本（状态“被审查拦截”）。审查器只能收紧，不能放宽授权。
  - 审查器可由业务插件（经模块能力注册）、本机服务或远程服务（MCP 等）提供；远程审查器本身也是一次外传，需单独授权并入账。可注册多个，结果取最严。
  - 默认实现为 `NoopReviewer`：一律 `allow`，回执与审计记“未审查”。审查器异常或超时按 `confirm` 处理（失败时回到询问用户，不静默放行）。
- `ToolRegistry.prepare` 在签发审批前查授权；命中则签发并立即消费，回执记 `grant_id`；未命中走现有确认流程。
- `PersonalAgent` 的模型请求确认改为按 `ModelLocation` 与授权判断；`requestDigest` 与核对流程保留，供“仅这一次”和审计使用。
- 确认卡统一为 v4 `components.md` 的“确认卡”：做什么 / 对谁 / 发送内容 / 摘要散列 / 后果，写入按钮为“仅这一次 / 本次任务 / 本次对话 / 始终允许 / 拒绝”（后几档折叠在“更多”里）；外传发往新端点只有“仅发送这一次 / 拒绝”，发往已授权端点另有“本次对话允许”。
- 安全敏感改动：实施任务必须过 [REVIEW.md](../tasks/REVIEW.md) 安全清单；`assistant_cancel_test`、`personal_agent*_test`、`outbound_ledger_test` 全绿，并新增授权过期、撤销、范围变化、防重放，以及审查器 `confirm` / `block` / 异常 / 超时的测试。

## 5. 用户确认（2026-10-07）

| # | 问题 | 决定 |
|---|---|---|
| Q1 | 写入能否设为“始终允许”？ | **可以**。授权仍绑定工具与范围（范围可选当前项目或当前工作区），可随时撤销 |
| Q2 | 外传能否按“已授权的端点 + 本次对话”放行？ | **可以**。先不做内容审查，留内容审查插件 / 服务的接入接口（§4） |

由此，原不变量“写入与外传逐次确认，不可关闭”改为：**写入与外传默认询问；用户可按工具、范围、端点授予放行（写入最长可到“始终”，外传最长到“本次对话”），随时可撤销；新端点逐次询问；授权只能由用户在宿主界面给出。** 产品总览只写“取得必要确认”，与此一致，不需改动；v4「助手权限」页的“逐次确认不可关闭”说明由第五轮提示词改正。

## 后果

- 本期外传内容不经审查：已授权端点在本次对话内收到的内容，只靠用户授权时的判断与出站账本事后核查。接上审查器之前，这是已知的风险。
- 确认次数显著减少：标准模式下，“查预算再比两家报价”在本机或本人设备模型上不需要确认；用远程模型时每个对话只确认一次端点。
- 一次性审批、防重放回执与出站账本保留，审计更完整（每次放行都能追到授权）。
- 「助手权限」页从“四个开关”扩展为“模式 + 规则列表 + 审计”，v4 稿需重画（第五轮提示词）。
